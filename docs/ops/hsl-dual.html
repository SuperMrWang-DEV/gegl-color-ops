HSL Dual Extract

lb:hsl-dual 分量 整块区域

HSL 分量曲线工作流的提取器：把一张图拆成「R = HSL 饱和度、G = HSL 明度、B = 色相/360」的数据图，一张图同时携带三个分量

把一张图打包成一张数据图：R = HSL 饱和度、G = HSL 明度、B = 色相/360，全部 0…1。alpha 恒为 1。

原图 ──lb:hsl-dual──> (R=S, G=L, B=H/360)
                          │
                    ┌─────┴─────┐
                 S 曲线(红)   L 曲线(绿)
                    └─────┬─────┘
                          ▼
                    lb:hsl-compose  ──> 真实颜色

为什么要把 S 和 L 塞进同一张图

HSL 的饱和度与明度是耦合的：

C = (1 − |2L − 1|)·S        V = L + C/2        S_hsv = C/V

想把 HSL 的 (S, L) 精确换回 HSV 的 (S, V)，编码器必须同时读到这两个值。分成两张灰度图的话，每张只有自己的分量，两条互相独立的 1D 曲线表达不了这个二元映射——只在「只动其中一个、另一个恒定」时才碰巧正确。

塞进一张图后，两条曲线各挂一个通道（红、绿），再由 lb:hsl-compose 一起读，就精确了。这就是 HSL Split (Curves) 用它当第一道滤镜的原因。

输入输出

格式含义
inputR'G'B'A float滤镜栈的编码域缓冲，与 component-extract 同域
outputR'G'B'A float数值是数据不是颜色：0.6 / 0.5 / 0.583 = S 60%、L 50%、色相 210°

转换由 babl 的 HSLA float 完成，与 GIMP 自己的 HSL（component-extract 的 hsl-s / hsl-l）同一口径；本算子只做通道重排。babl 的输出本来就是 0…1 归一化（h/360、s、l），不需要再缩放。

alpha 恒写 1：分量层必须不透明，透明度交给组蒙版（半透明的混合层会按 alpha 做 lerp 而不是纯替换）。

实测

tools/check_hsl_split.py 里 dual → compose 恒等往返：32 位浮点图 0.0002 码， 8 位图 ≤ 1 码（只剩量化）。无色像素（S = 0）的色相在 babl 侧无定义，算子把非有限值折成 0，不会把 NaN 漏进缓冲。

注意

  • 输出是数据图，不要直接看它当照片：它看起来是某种奇怪的彩色，这是正常的。
  • 它和 lb:hsl-compose 是配对使用的。只装一个没有意义。

只要这一个

Windows 模块 hsl-dual.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 hsl-dual.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

HSL Dual Extract

lb:hsl-dual Component area

Packs HSL saturation, lightness and hue into a single data image — one channel per component, so two separate curves can act on S and L without losing the coupling between them.

Menu: Colors → SuperMrWang → Component → HSL Dual Extract (a filter op)

Overview

Packs an image into one data image: R = HSL saturation, G = HSL lightness, B = hue/360, all 0…1. Alpha is always 1.

input ── lb:hsl-dual ──> (R=S, G=L, B=H/360)
            │
            ├── S curve (red)
            ├── L curve (green)
            ▼
     lb:hsl-compose ──> real colour

Why S and L share one image

HSL saturation and lightness are coupled:

C = (1 − |2L − 1|)·S        V = L + C/2        S_hsv = C/V

Turning an HSL (S, L) pair back into HSV's (S, V) exactly requires the encoder to read both values at once. Split into two greyscale images, each carries only its own component, and two independent 1D curves cannot express that two-variable map — they are only correct while one of the two is held constant.

In one image the two curves own one channel each (red, green) and lb:hsl-compose reads them together, which is exact. That is why HSL Split (Curves) uses this operator as its first filter.

Input and output

FormatMeaning
inputR'G'B'A floatthe filter stack's encoding-domain buffer, same domain as component-extract
outputR'G'B'A floatthe numbers are data, not colour: 0.6 / 0.5 / 0.583 = S 60%, L 50%, hue 210°

The conversion is babl's HSLA float, the same one GIMP's own HSL extraction (hsl-s / hsl-l from component-extract) uses; this operator only reorders channels. babl already returns normalised 0…1 values (h/360, s, l), so no extra scaling is applied.

Alpha is written as 1 unconditionally: a component layer has to be opaque, and transparency belongs on a group mask — a semi-transparent blend layer would lerp with alpha instead of replacing.

Verification

tools/check_hsl_split.py runs the dual → compose identity round trip: 0.0002 codes on a 32-bit float image, ≤ 1 code on 8-bit (quantisation only). Achromatic pixels (S = 0) have no defined hue on the babl side; the operator folds non-finite values to 0 so no NaN leaks into the buffer.

Notes

  • The output is a data image — do not read it as a photo. It looks like a strange colour image; that is expected.
  • It is only meaningful together with lb:hsl-compose.

Just this one

Windows module hsl-dual.dll, drop it into %LOCALAPPDATA%\gegl-0.4\plug-ins; Linux module hsl-dual.so, drop it into ~/.local/share/gegl-0.4/plug-ins, then restart GIMP. Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs. The full bundle is on the download page.
