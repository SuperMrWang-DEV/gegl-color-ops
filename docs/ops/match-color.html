Match Color

lb:match-color 色彩 双输入施工中

施工中　三种方法已经能用了，但 MKL 的通道尺度（100/128/128）和直方图的 256 桶还在试，极端对比的图上结果随时可能动，先别拿它跑批处理。

经典图像编辑器 匹配颜色：把另一张图（或另一层）的 Lab* 统计量迁移到本层

经典图像编辑器的「图像 → 调整 → 匹配颜色」的复刻：把另一张图 / 另一个图层的颜色统计量迁移到本层。默认的「统计」方法就是 经典图像编辑器 的行为（Reinhard 等 2001 年的 L\a\b\* 均值-方差仿射迁移）；另外两档是公开文献里成熟、比它更好用的算法，做成了 method 下拉框。

模型

工作在 CIELAB（D50）里，method 三选一。

① 统计（stats，默认）——逐通道均值/标准差仿射映射，与 经典图像编辑器 一致：

$$\text{out} = \bigl(v-\mu_t\bigr)\cdot\frac{\sigma_s}{\sigma_t} + \mu_s$$

② Monge-Kantorovich（mkl）——把 L/a/b 当成一个三维分布，用完整协方差解线性最优传输：

$$\text{out} = T\bigl((v-\mu_t)\oslash S\bigr)\odot S + \mu_s, \qquad T\,\Sigma_t T^{\mathsf T} = \Sigma_s$$

S = diag(100, 128, 128) 是通道尺度：L 的量程和 a/b 差一倍多，不归一化的话 L 的方差会压过色度，传输度量就歪了。T 有闭式解（Pitié & Kokaram, CVMP 2007）：

$$T = \Sigma_t^{-1/2}\left(\Sigma_t^{1/2}\Sigma_s\Sigma_t^{1/2}\right)^{1/2}\Sigma_t^{-1/2}$$

在满足 T Σt Tᵀ = Σs 的所有线性映射里，它是传输代价（Wasserstein-2）最小的那个。差别在于：逐通道方法等于硬性假设 L/a/b 互不相关，而真实图像里三者强相关——所以逐通道缩放会把「同一种颜色」沿某条通道撕开，出现色斑和空洞；MKL 不会。

③ MKL + 直方图（mklhist）——先做 ②，再对每个通道做一次 CDF 匹配（256 桶 LUT），把残差分布拉到来源的直方图上。线性映射够不到的色调尾部由它补齐，代价是原图的层次会被参考图替换得更多、极端情况下偏平。

统计量对整层计算（经典图像编辑器 亦然），来源是 aux pad 接的图层；没接 aux 时来源退化为本层自身，恒等映射。

与 经典图像编辑器的滑杆对应

经典图像编辑器这里语义（模型对齐，非逐码标定）
亮度 Luminance（1–200，默认 100）luminance只缩放 L 的映射量：k = 滑杆/100，映射按 lerp(1, ratio, k) 收敛。100=精确匹配，200=双倍修正，1=几乎不动
颜色强度 Color Intensity（默认 100）color-intensity同上，只作用于 a/b
渐隐 Fade（0–100）fade整体映射量乘 (1 − fade/100)；等价 经典图像编辑器的「编辑 → 渐隐」
中和 Neutralizeneutralize输出的 a/b 均值强制为 0（去色偏），L 照常；来源仍提供对比度

三种方法共用这四个滑杆：映射量都是「向原值 lerp」，所以滑杆的语义不随方法改变。 mklhist 的直方图那一步也乘同一个量（先算完整映射，再按 k 混回原值）。

经典图像编辑器 2025 的匹配颜色没有脚本接口（对话框没有 DOM API，Mk/matchColor 均被拒），拿不到实测基准点，所以这里是模型对齐而非黑盒标定——与色阶的处理方式一致，README 如实声明。

不是直方图匹配

常有「经典图像编辑器的匹配颜色其实是直方图规定化」的说法，实测与逆向复刻都不是：

  • 经典图像编辑器 读的是六个数字：L、a、b 各自的均值与标准差。映射是仿射的， 同一通道内所有像素共用一条直线的斜率与截距——直方图只会被整体拉伸、平移、 削顶，不会被改写成参考图的形状；
  • 直方图匹配（直方图规定化 / CDF 匹配）逐通道求累积分布的反函数 v' = CDF_s⁻¹(CDF_t(v))，输出的直方图与参考图几乎逐箱相同，原图的层次 关系被参考图替换；
  • 一条自己能验的判据：拿线性灰阶（0→255 均匀渐变）去匹配任意参考图。仿射映射 的结果仍是线性渐变，只在两端被削平；CDF 匹配的结果会带上参考图的色调分布形状， 出现压缩与台阶；
  • 三个滑杆的语义也只在统计模型下成立：亮度/颜色强度按 lerp(1, ratio, k) 收敛、 渐隐按比例回混——直方图匹配没有「比例」可调，只能改 CDF 的幂次，或者与结果按 比例混合。

另一种做法是 Lab 三通道各做一次 CDF 匹配，更贴参考图的整体调子，代价是原图的明暗结构被替换、容易发平。本算子的默认方法保持与 经典图像编辑器 一致的统计迁移，那条 CDF 路线做成了可选的 mklhist（建在 MKL 之上，而不是替代它）。

全局统计 × 逐块渲染

GEGL 的 process 每次只拿一小块，而均值/方差必须对整层算。做法：

  • 首次 process 时整层扫一遍 input 与 aux（Lab 域，攒 sum/sum²），缓存在 operation 实例上（互斥锁保护，键 = 源节点 + extent + 层级）；
  • 键里不放缓冲指针：GEGL 每次重新求值都会给 pad 换一块缓存缓冲，指针必然 变，拿它做键等于永远不命中——4 MP 的图拖一下滑杆就整层重扫两遍，约 1 秒；
  • 后续块直接复用缓存，预览拖滑杆不会反复重算（4 MP：首次 0.12 s，之后 每次 0.02 s）；
  • 来源图层内容变了（非破坏预览场景）勾一次「重算统计 / Refresh stats」， 重算完自动复位。
  • 缓存对象本身的创建也要串行：GEGL 用多个线程并行跑不同的块，首帧时它们 都会看到「还没有缓存」，各自 g_new0 一份再挂到实例上，而挂载函数会 free 掉上一份——先创建的那个线程随后在已释放的内存上加锁、读模型， 拿到 n = 0 的垃圾模型就走「原样输出」。表现就是画面上若干块根本没被 转换（看着像「一半没转过来」），严重时直接崩溃。所以创建段用一把全局 锁串起来，锁内二次检查。

细则

  • 透明像素不进统计：目标与来源两侧都以 alpha ≤ 0 剔除，抠图层的洞 不会把统计拖向黑（这个坑在应用图像/计算里已经踩过一轮）。
  • σ 保护：σ < 1e-3 视为常数通道，比值取 1；均匀色来源会把输出均值 平移到自己的均值色（(v − μt) 项本来就是 0）。
  • 削顶：输出 L 削到 [0, 100]、a/b 削到 [−128, 127]，与经典图像编辑器在 8bit L\a\b\* 里工作一致。
  • 与「只有相交部分起作用」无关：匹配颜色不是逐像素混合，来源只捐统计 量，映射作用于目标整层——这正是 经典图像编辑器的行为。
  • 匹配是仿射的（三种方法都是），几何不必对齐：来源图层尺寸/偏移随意。
  • 协方差奇异时自动退回逐通道：目标层是纯色（三通道 σ 全 < 1e-3）或有效像素 不足 2 个时，MKL 的逆平方根会放大到 1e6 量级，没有意义，于是直接走 stats 那条路；特征值另有 1e-6 的下限兜底，不出 NaN。
  • mklhist 的 LUT 什么时候重建：它依赖「映射之后」的分布，所以在统计重算、 切到该方法、切换「中和」三种情况下各重建一次（一趟整层扫描 + 256 桶）； 之后拖滑杆、调亮度/颜色强度都只查表，不重扫。
  • 性能（2400×1800 = 4.3 MP，GIMP 3.2 内实测）：stats 首次 0.10 s / 拖滑杆 0.015 s；mkl 0.11 s / 0.020 s；mklhist 首次 0.23 s（多一趟直方图）/ 0.031 s。 切换方法时若切到 mklhist，第一次约多 0.16 s（建 LUT）。

Match Color

lb:match-color Color two inputsWIP

Work in progress　All three methods work, but the MKL channel scale (100/128/128) and the 256 histogram bins are still being tuned, so results on extreme-contrast images can still move. Don't put it in a batch pipeline yet.

The classic editor's Match Color — Reinhard's Lab mean/variance transfer from another layer or image, plus a linear Monge-Kantorovich and a histogram variant, with Luminance, Color Intensity, Fade and Neutralize.

A reproduction of the classic editor's Image → Adjustments → Match Color: transfer the colour statistics of another image or layer onto this one. The default Statistics method is exactly what the classic editor does (Reinhard et al.'s 2001 L\a\b\* mean–variance affine transfer); the other two are well-established published algorithms that behave better, exposed as a method dropdown.

Model

Working in CIELAB (D50), with method choosing one of three mappings.

① Statistics (stats, default) — per-channel mean/std affine, what the classic editor does:

$$\text{out} = \bigl(v-\mu_t\bigr)\cdot\frac{\sigma_s}{\sigma_t} + \mu_s$$

② Monge-Kantorovich (mkl) — treats L, a and b as one 3-D distribution and solves the linear optimal transport on the full covariance:

$$\text{out} = T\bigl((v-\mu_t)\oslash S\bigr)\odot S + \mu_s, \qquad T\,\Sigma_t T^{\mathsf T} = \Sigma_s$$

S = diag(100, 128, 128) is the per-channel scale: L's range is more than twice a/b's, and without normalising, L's variance would swamp chroma and skew the transport metric. T has a closed form (Pitié & Kokaram, CVMP 2007):

$$T = \Sigma_t^{-1/2}\left(\Sigma_t^{1/2}\Sigma_s\Sigma_t^{1/2}\right)^{1/2}\Sigma_t^{-1/2}$$

Among all linear maps satisfying T Σt Tᵀ = Σs it is the one with the least transport cost (Wasserstein-2). The difference that matters: per-channel matching implicitly assumes L, a and b are uncorrelated, while real images correlate them strongly — so independent scaling tears a single colour apart along one channel and leaves blotches and holes, which MKL avoids.

③ MKL + histogram (mklhist) — ② followed by a per-channel CDF match (256-bin LUT) that pulls the residual onto the donor's histogram. It reaches the tonal tails a linear map cannot, at the price of replacing more of the original's tonal structure (and going flat in extreme cases).

Statistics are computed over the whole layer (the classic editor does the same), with the source coming from the layer wired to the aux pad. With no aux connected the source falls back to this layer itself, i.e. an identity map.

Mapping to the classic editor's sliders

Luminance (1–200, default 100)luminanceScales how much of the L map applies: k = slider/100, and the map converges as lerp(1, ratio, k). 100 = exact match, 200 = double correction, 1 = almost nothing
Color Intensity (default 100)color-intensitySame, for a/b only
Fade (0–100)fadeMultiplies the whole map by (1 − fade/100); equivalent to the classic editor's Edit → Fade

All three methods share the four sliders: every mapping is approached by "lerping towards the original value", so the slider semantics don't change with the method. In mklhist the histogram step is scaled by the same amount (the full map is computed first, then mixed back with k).

the classic editor 2025's Match Color has no scripting interface (no DOM API for the dialog, and both Mk and matchColor are refused), so there is no measured reference to calibrate against. This is model alignment, not black-box calibration — the same situation as Levels, and stated here honestly.

Not a histogram match

Match Color is often described as histogram specification. It is not, and neither is this operator:

  • the classic editor reads six numbers: the mean and standard deviation of L, a and b. The map is affine, so every pixel in a channel shares one line's slope and intercept — a histogram gets stretched, shifted and clipped, never reshaped into the reference's;
  • histogram matching (histogram specification / CDF matching) inverts the cumulative distribution per channel, v' = CDF_s⁻¹(CDF_t(v)), so the output histogram ends up almost bin-for-bin identical to the reference and the original tonal structure is replaced;
  • a test you can run yourself: match a linear grey ramp against any reference. The affine map returns a linear ramp, clipped at the ends only; CDF matching returns the reference's tonal distribution, with all of its compression and steps;
  • the three sliders only make sense under the statistical model: Luminance and Color Intensity converge as lerp(1, ratio, k), and Fade mixes the original back proportionally. Histogram matching has no "ratio" to dial — only a CDF exponent, or a blend with the original.

The alternative — one CDF match per Lab channel — follows the reference's overall grade more closely, at the price of replacing the original's tonal structure and often going flat. The default method here keeps the classic editor's statistical transfer; that CDF route is available as the optional mklhist method, built on top of MKL rather than replacing it.

Global statistics, tiled rendering

GEGL's process only sees a small tile at a time, while means and variances need the whole layer:

  • on the first process, input and aux are scanned once (in Lab, accumulating sum/sum²) and cached on the operation instance (guarded by a mutex, keyed by source node + extent + level);
  • the key deliberately holds no buffer pointers: GEGL hands the pad a fresh cache buffer on every evaluation, so pointer keys would never hit — one slider step on a 4 MP image would rescan both layers and cost about a second;
  • later tiles reuse the cache, so dragging a slider in the preview does not recompute (4 MP: 0.12 s once, then 0.02 s per step);
  • if the source layer changes (a non-destructive preview), tick "Refresh stats" once and it resets itself.

Details

  • Transparent pixels do not enter the statistics: both target and source drop alpha ≤ 0, so a cut-out's holes cannot drag the statistics toward black (a trap already hit once in Apply Image / Calculations).
  • σ guard: σ < 1e-3 is treated as a constant channel and the ratio becomes 1. A flat-colour source just shifts the output mean to its own mean colour (the (v − μt) term is 0 anyway).
  • Clipping: output L to [0, 100], a/b to [−128, 127], matching the classic editor working in 8-bit L\a\b\*.
  • Nothing to do with "only the intersection acts": Match Color is not a per-pixel blend. The source only donates statistics and the map applies to the whole target layer — exactly the classic editor's behaviour.
  • The map is affine under all three methods, so geometry need not line up: the source layer can be any size or offset.
  • A singular covariance falls back to per-channel: when the target is a flat colour (all three σ below 1e-3) or has fewer than two usable pixels, the MKL inverse square root would amplify by 1e6 and mean nothing, so the stats path is used instead; eigenvalues are additionally floored at 1e-6 so nothing produces NaN.
  • When the mklhist LUT is rebuilt: it depends on the post-map distribution, so it is rebuilt when the statistics are recomputed, when you switch to this method, and when Neutralize changes (one whole-layer scan plus 256 bins). Slider drags afterwards only look the table up.
  • Performance (2400×1800 = 4.3 MP, measured inside GIMP 3.2): stats 0.10 s first time / 0.015 s per slider step; mkl 0.11 s / 0.020 s; mklhist 0.23 s (one extra histogram pass) / 0.031 s. Switching to mklhist costs about 0.16 s once, for the LUT.
