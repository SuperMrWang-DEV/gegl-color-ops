Levels

lb:levels 色阶家族 逐像素

经典图像编辑器 色阶：复合 + R/G/B 四组「输入黑场 / 灰点 / 白场 + 输出黑场 /白场」，数值刻度 0–255，与 经典图像编辑器 对话框的数字框一一对应

经典图像编辑器「色阶」对话框的复刻：复合 + R/G/B 四组，每组都是「输入黑场 / 输入灰点 / 输入白场 + 输出黑场 / 输出白场」五个数，刻度 0–255，和 经典图像编辑器的数字框一一对应。

对应面板：Colors → SuperMrWang → Levels → Levels。

模型

单通道：

$$t = \operatorname{clamp}\!\left(\frac{v-\text{inLow}}{\text{inHigh}-\text{inLow}},\,0,\,1\right), \qquad t' = t^{1/\gamma}, \qquad \text{out} = \text{outLow} + t'\,\bigl(\text{outHigh}-\text{outLow}\bigr)$$
  • inLow 及以下压成 outLow，inHigh 及以上压成 outHigh， 中间按 gamma 曲线重新分布；
  • gamma > 1 提亮，gamma < 1 压暗（与经典图像编辑器数字框同向。注意这与 「标准 gamma」的直觉相反，因为 经典图像编辑器的滑块值直接进的是 1/gamma 的倒数位置； 指数写成 t^gamma 会让方向整个反过来）；
  • 输入区间会把整段拉伸：设了 inLow = 64 之后，v = 240 会变成 235， 不是原样保留；
  • inHigh == inLow 时区间塌成一点，该通道原样透传（不除零，也不会压成单值）。

执行顺序：先复合组（三通道同一条曲线），再各通道组。各通道组默认恒等，所以「只动复合」与 经典图像编辑器的 RGB 通道模式逐位一致；「只动红」等价于 经典图像编辑器的 Red 通道模式。四组可以叠加使用，这比经典图像编辑器一次只能选一个通道更强。

域

在 8bit sRGB 伽马域逐通道直接算，不回线性光。色阶的黑白场是「0–255 编码值」的语义，喂线性光会让数字框对不上 经典图像编辑器。算子自己在 prepare 里把两个 pad 钉成感知格式（R~G~B~A float），不需要前置 linear-rgb。

本机为什么没做逐码标定

经典图像编辑器 2025（26.10.0）在这台机器上：executeAction 的 Lvls 事件、以及 Mk 创建调整图层，都直接抛「不能完成命令，因为程序错误」；DOM 的 LayerKind.LEVELS 也给「只能改为文本或正常」。诊断日志见 ../lvls-cal/_diag2.txt。colorRange 反而能跑，所以不是 ExtendScript 整体不可用，是这两个命令在这套安装里被挡了。

因此基准改用公开实测值，而不是本机标定。如果你在另一台机器上能跑经典图像编辑器脚本，可以把 lvls-cal/ 里的 ps_levels.jsx 修好重跑，就能升级成逐码标定。

与 GIMP 自带「色阶」的区别

GIMP 的 Colors → Levels 是 app 层私有实现，GEGL 里的 gegl:levels 只有 in-low / in-high / out-low / out-high 四个属性——没有 gamma，没有每通道，也没有 0–255 的数字刻度（gegl --info gegl:levels 可查）。所以这个算子补的是 GEGL 算子层面的真空白：脚本、批处理、gegl 命令行里都能用 经典图像编辑器的色阶参数。

只要这一个

Windows 模块 levels.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 levels.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

Levels

lb:levels Levels per-pixel

The classic editor's Levels dialog — composite plus R/G/B, five numbers each, 0–255 scale, with the classic editor's gamma direction.

A reproduction of the classic editor's Levels dialog: composite plus R/G/B, four groups of five numbers each — input black, input grey, input white, output black, output white — on a 0–255 scale that matches the classic editor's numeric fields one for one.

Panel: Colors → SuperMrWang → Tone → Levels.

Model

Per channel:

$$t = \operatorname{clamp}\!\left(\frac{v-\text{inLow}}{\text{inHigh}-\text{inLow}},\,0,\,1\right), \qquad t' = t^{1/\gamma}, \qquad \text{out} = \text{outLow} + t'\,\bigl(\text{outHigh}-\text{outLow}\bigr)$$
  • inLow and below is crushed to outLow, inHigh and above to outHigh, and the middle is redistributed along the gamma curve;
  • gamma > 1 brightens, gamma < 1 darkens — the same direction as the classic editor's field. Note this is the opposite of the usual gamma intuition: the classic editor's slider value goes straight into the reciprocal position of 1/gamma, and writing the exponent as t^gamma flips the whole direction;
  • the input range stretches everything: after setting inLow = 64, v = 240 becomes 235 rather than staying put;
  • when inHigh == inLow the range collapses to a point and is handled as a step (anything ≥ that value is white) instead of dividing by zero.

Order: the composite group first (one curve for all three channels), then the per-channel groups. Per-channel groups default to identity, so "touch only the composite" is bit-identical to the classic editor's RGB mode and "touch only red" matches the classic editor's Red channel mode. All four groups can be stacked, which is more than the classic editor allows (one channel at a time).

Domain

Everything is computed per channel in the 8-bit sRGB gamma domain, never decoded to linear. Levels' black and white points mean "0–255 encoded values", and feeding linear light would make the numeric fields disagree with the classic editor. The operator pins both pads to a perceptual format (R~G~B~A float) in prepare, so no upstream linear-rgb is needed.

Why there is no per-code calibration on this machine

On this machine, the classic editor 2025 (26.10.0) throws "could not complete the command because of a program error" for both the Lvls executeAction event and Mk adjustment-layer creation, and the DOM's LayerKind.LEVELS only offers text-or-normal. The diagnostic log is in ../lvls-cal/_diag2.txt. colorRange does run, so ExtendScript as a whole is fine — those two commands are blocked in this installation.

Hence the reference is public measurements rather than local calibration. If you can run the classic editor scripts on another machine, fix ps_levels.jsx in lvls-cal/ and re-run it, and this can be upgraded to a per-code calibration.

Difference from GIMP's own Levels

GIMP's Colors → Levels is a private app-level implementation, and GEGL's gegl:levels has only four properties — in-low / in-high / out-low / out-high — with no gamma, no per-channel groups and no 0–255 scale (check gegl --info gegl:levels). This operator fills a genuine hole at the GEGL level: the classic editor levels parameters now work from scripts, batch jobs and the gegl command line.
