Apply Image

lb:apply-image 混合与通道 双输入

经典图像编辑器 应用图像：把 aux 输入当成源，按混合模式、不透明度与遮罩压到主输入上，可选只作用于某一个通道

lb:apply-image · 菜单 SuperMrWang → Blend → Apply Image · 双输入（input + aux）

对应 经典图像编辑器的 图像 → 应用图像：把一张图（另一个图层 / 另一个文件）当作源，按混合模式、不透明度、遮罩压到当前图层上，还可以只作用于某一个通道。

参数 / Parameters

参数默认说明

scale1.0仅加法/减法：结果 = (A ± B) / 缩放 + 补偿值，范围 1.0..2.0
offset0仅加法/减法：缩放后加上的补偿值，±255（8bit 口径）
opacity100混合强度，0 = 不动，100 = 完全应用

source-channelComposite从 aux 取哪个通道作为源
mask-enabled否用一路通道当遮罩
mask-fromSource layer遮罩取自 aux 还是本层

算法

flowchart TD
  A["本层 input"] --> C1["目标通道 target-channel"]
  B["源 aux（可只取一个通道）"] --> C2["source-channel → 合成或亮度"]
  C2 --> M["B = mode(A, B)"]
  C1 --> M
  M --> N["按 opacity 与 mask 回插<br/>alpha = opacity/100 × mask × 源 alpha"]
  N --> O{"target-channel"}
  O -- "Composite" --> P["整像素替换"]
  O -- "单通道" --> Q["只写回该通道，其余保留"]
$$\text{out} = (1-\alpha)\,A + \alpha\,B_{\text{mode}}(A,B),\qquad \alpha = \frac{\text{opacity}}{100}\cdot m\cdot\alpha_{\text{src}}$$
$$\text{add/sub:}\quad \text{out} = \operatorname{clamp}\!\left(\frac{A \pm B}{\text{scale}} + \frac{\text{offset}}{255},\ 0,\ 1\right)$$

经典图像编辑器的遮罩可以指向第三张图（既不是目标也不是源），GEGL 的 composer 只有两个输入，所以这里限定在「本层」或「源层」二选一——实际用法里这两处覆盖了绝大多数场合。

行为细节 / Behaviour notes

  • aux 没接时源退化为本图，可以用来做「同图内通道互混」； Without an aux connected the source falls back to the input itself.
  • 源层的透明像素（alpha = 0）不参与作用：源层是抠图、文字层或带透明背景 的图层时，透明区的 RGB 是 0，照常混合会把目标乘成黑色。alpha 同时当作覆盖率， 半透明的柔边会渐隐而不是留硬边。 Transparent source pixels take no part: on a cut-out or text layer the holes hold RGB 0, which would blacken the target under multiply. The alpha doubles as coverage, so soft mattes fade instead of leaving a hard edge.
  • 目标是单通道时只改那一个通道，其余原样保留；源是合成时取亮度作标量。 With a single-channel target only that channel changes; a composite source is reduced to luminance.
  • 深色 / 浅色（Darker / Lighter Color）比较整像素亮度后取其中一方全部通道， 不是逐通道取最小/最大——这一点和「变暗 / 变亮」不同。
  • 在 8bit sRGB 伽马域计算，与 经典图像编辑器的混合模式定义同域；结果会裁到 0..1。
  • GIMP 里这类带 aux 的滤镜目前只能合并应用，不能保存成非破坏性 fx。

源图层的尺寸与位置 / Source layer size and position

经典图像编辑器的应用图像要求两个图层像素尺寸完全一致，尺寸不同时源图层直接灰掉； GIMP 里图层可以比画布小、也可以带偏移，所以这里得自己定规则：

  • 算子按 aux 缓冲区自己的 extent（即源图层的大小和位置）做粗筛，没盖到 的像素原样输出；
  • 盖到的范围内，再由源像素的 alpha 决定真正有没有像素：alpha = 0 的地方 原样输出，alpha 介于 0 和 1 之间按覆盖率减弱。只有「既属于源层、又有像素」 的地方才被改动，这才是经典图像编辑器意义上「只有相交部分起作用」。

早先版本用的是 GeglOperationPointComposer，process 只拿到一段裸指针，看不到 aux 的 extent，界外被 GEGL 补成透明黑再参与混合：正片叠底会把外侧涂黑，正常模式会把外侧擦成透明。改成 GeglOperationComposer 后 process 拿到的是真正的 GeglBuffer，gegl_buffer_get_extent(aux) 就能取到图层尺寸， tools/auxrun 也补了 aux-x / aux-y 用来模拟带偏移的源层。

extent 只能说明「这块地方属于源层」，说明不了「这块地方有像素」——抠图的透明洞也在 extent 里面，光看 extent 会把洞一起乘黑。所以两者要配合用。

Apply Image

lb:apply-image Blend two inputs

The classic editor's Image → Apply Image: blend a second image into this one with a mode, opacity and mask, optionally into a single channel.

lb:apply-image · menu Colors → SuperMrWang → Blend → Apply Image · two inputs (input + aux)

Replicates the classic editor's Image → Apply Image: a second image (another layer, another file) acts as the source and is blended onto the current layer with a blend mode, opacity and mask — optionally into one channel only.

the classic editor's mask may point at a third image — neither the target nor the source. A GEGL composer only exposes two inputs, so the mask is limited to "this layer" or "the source layer", which covers the overwhelming majority of real use.

Algorithm

flowchart TD
  A["this layer (input)"] --> C1["target-channel"]
  B["source (aux), optionally one channel"] --> C2["source-channel → composite or luminance"]
  C2 --> M["B = mode(A, B)"]
  C1 --> M
  M --> N["blend back with opacity and mask<br/>alpha = opacity/100 × mask × source alpha"]
  N --> O{"target-channel"}
  O -- "Composite" --> P["replace the whole pixel"]
  O -- "single channel" --> Q["write that channel only, keep the rest"]
$$\text{out} = (1-\alpha)\,A + \alpha\,B_{\text{mode}}(A,B),\qquad \alpha = \frac{\text{opacity}}{100}\cdot m\cdot\alpha_{\text{src}}$$
$$\text{add/sub:}\quad \text{out} = \operatorname{clamp}\!\left(\frac{A \pm B}{\text{scale}} + \frac{\text{offset}}{255},\ 0,\ 1\right)$$

Behaviour notes

  • With no aux connected the source falls back to the input itself, which is useful for mixing channels inside one image.
  • Transparent source pixels (alpha = 0) take no part. On a cut-out, text layer or any layer with a transparent background the holes hold RGB 0, and blending them normally would multiply the target to black. The alpha doubles as coverage, so a soft matte fades out instead of leaving a hard edge.
  • With a single-channel target only that channel changes and the rest is preserved; a composite source is reduced to luminance.
  • Darker / Lighter Color compare whole-pixel luminance and then take all channels of the winner, not per-channel min/max — that is what separates them from Darken / Lighten.
  • Everything runs in the 8-bit sRGB gamma domain, the same domain the classic editor's blend modes are defined in; the result is clipped to 0..1.
  • In GIMP these aux-carrying filters can currently only be applied destructively — they cannot be stored as a non-destructive fx.

Source layer size and position

the classic editor requires both layers to have exactly the same pixel size and greys the source out otherwise. GIMP layers may be smaller than the canvas or carry an offset, so the rule here is two-stage:

  • the operator uses the aux buffer's own extent (the source layer's size and position) as a coarse filter — pixels it does not cover are passed through;
  • inside that area the source alpha decides whether a pixel really carries anything: alpha = 0 is passed through, and alpha between 0 and 1 attenuates by coverage. Only "belongs to the source layer and has a pixel" is modified, which is what the classic editor means by "only the intersection takes effect".

The earlier version used GeglOperationPointComposer, whose process only gets a raw pointer — it cannot see the aux extent, so GEGL padded the outside with transparent black and it took part in the blend: multiply blackened the outside, normal erased it. Switching to GeglOperationComposer gives process a real GeglBuffer, gegl_buffer_get_extent(aux) returns the layer size, and tools/auxrun grew aux-x / aux-y to simulate an offset source layer.

The extent only says "this area belongs to the source layer", not "this area has pixels" — a cut-out's holes sit inside the extent, and extent-only logic would still multiply them to black. Both checks are needed.
