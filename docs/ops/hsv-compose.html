HSV Compose

lb:hsv-compose 分量 整块区域

HSV 分量曲线工作流的合成器：把「R = 饱和度、G = 明度、B = 色相/360」的数据图还原成真实颜色

把数据图还原成真实颜色：R = 饱和度、G = 明度、B = 色相/360（都是 0…1）， 按 HSV 定义算出 RGB。

(R=S, G=V, B=H/360) ──lb:hsv-compose──> 真实颜色

输入约定是硬的

本算子无法分辨输入是一张数据图还是一张普通照片——它一律按「R 是饱和度、 G 是明度、B 是色相」解释。挂错地方会把照片当成数据算出一张乱七八糟的图。

正常用法是紧跟在 lb:hsv-dual 之后（中间夹三条曲线）：

lb:hsv-dual → S 曲线(红) → V 曲线(绿) → H 曲线(蓝) → lb:hsv-compose

为什么不用「HSV 分量混合模式」

GIMP 的 HSV Hue / HSV Saturation / HSV Value 三个模式合起来也能改 HSV，但每层 只看得见一个分量：色相层换了角度，它保留的仍是下层的 S、V——对 HSV 来说这恰好 就是「只改色相」，所以旧版能用。代价是三层、每层要先把分量抽成灰度、曲完再编码 成「携带该分量」的颜色，8 位图上还得靠组内浮点缓冲才不偏色。

一次合成没有这个包袱：三个分量在同一条管线里，算完就是最终颜色。

实测

  • dual → compose 恒等往返：32 位浮点 0.0002 码，8 位 0.49 码。
  • 在完整插件里（tools/check_hsv_split.py 33 项）：改 S 曲线后结果的 V 与色相 偏差 &lt; 0.001 码。

注意

  • 输出 alpha 恒 1，理由同 lb:hsv-dual。
  • 输入超出 0…1 的值会被夹紧；NaN 折成 0。
  • 色相为环形量：0 与 1 是同一个角度，数据图里不要指望「1.0 表示比 0.0 大」。

只要这一个

Windows 模块 hsv-compose.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 hsv-compose.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

HSV Compose

lb:hsv-compose Component area

Turns the HSV data image back into real colour in one pass — three components in, final pixel out, no per-layer encode round trip.

Menu: Colors → SuperMrWang → Component → HSV Compose (a filter op)

Overview

Restores a data image to real colour: R = saturation, G = value, B = hue/360 (all 0…1) go in, the matching RGB comes out of the HSV definition.

(R=S, G=V, B=H/360) ──lb:hsv-compose──> real colour

The input convention is strict

The operator cannot tell a data image from an ordinary photo — it always reads R as saturation, G as value and B as hue. Put it in the wrong place and it will happily turn a photo into nonsense.

The intended chain keeps it right behind lb:hsv-dual, with the curves in between:

lb:hsv-dual → S curve (red) → V curve (green) → H curve (blue) → lb:hsv-compose

Why not use the HSV component blend modes

GIMP's HSV Hue / HSV Saturation / HSV Value modes can also change HSV, but each layer only sees one component: the hue layer changes the angle while keeping the S and V of what is underneath — which, for HSV, happens to be exactly "change hue only", so the old route works. The price is three layers, each needing its component extracted to grey, curved, and re-encoded as a colour "carrying" that component, plus a group float buffer in 8-bit just to stay colour-accurate.

A single compose has none of that: the three components live in one pipeline and the result is the final colour.

Verification

  • dual → compose identity round trip: 0.0002 codes in 32-bit float, 0.49 codes in 8-bit.
  • Inside the full plug-in (tools/check_hsv_split.py, 33 assertions): after editing the S curve, V and hue deviate by < 0.001 codes.

Notes

  • Output alpha is always 1, for the same reason as lb:hsv-dual.
  • Input outside 0…1 is clamped; NaN folds to 0.
  • Hue is circular: 0 and 1 are the same angle, so do not expect "1.0 is more than 0.0" in the data image.

Just this one

Windows module hsv-compose.dll, drop it into %LOCALAPPDATA%\gegl-0.4\plug-ins; Linux module hsv-compose.so, drop it into ~/.local/share/gegl-0.4/plug-ins, then restart GIMP. Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs. The full bundle is on the download page.
