LCH Levels

lb:lch-levels 色阶家族 整块区域

CIE LCh 三个分量各自设输入 / 输出黑白场与伽马

菜单：SuperMrWang → Levels → LCH Levels（Filter 类）

概述

CIE LCh 的 L / C / H 三个分量各自做独立色阶。和 lb:lab-levels 是同一套 Lab 底子，区别在坐标：Lab 是直角坐标（a、b 两轴），LCh 是极坐标 （色度 C 与色相角 H）。在 LCh 上调色度不会连带改色相，改色相也不会连带 改色度——这是 Lab 色阶做不到的（那里动 a 就会同时改 C 和 H）。

色彩空间

直接工作在 babl 的 CIE LCH(ab) alpha float（D50 白点）上，RGB↔LCh 交给 babl，与 GIMP「分解 → LCH」同一套口径。

分量量程说明
L0–100CIE 明度
C0–~132色度，sRGB 色域内最大约 131（纯蓝），所以量程给到 132
H0–360°色相角，0° 偏红（纯红约 40°，纯蓝约 301°）
$$z = (h-\text{ia}) \bmod 360,\qquad S_{\text{in}} = (\text{ib}-\text{ia}) \bmod 360,\qquad S_{\text{out}} = (\text{ob}-\text{oa}) \bmod 360$$
$$h' = \bigl(\text{base} + \text{span}\cdot t^{1/\gamma}\bigr) \bmod 360,\qquad (t,\ \text{base},\ \text{span}) = \begin{cases} \left(\dfrac{z}{S_{\text{in}}},\ \text{oa},\ S_{\text{out}}\right), & z \le S_{\text{in}} \\[10pt] \left(\dfrac{z-S_{\text{in}}}{360-S_{\text{in}}},\ \text{oa}+S_{\text{out}},\ 360-S_{\text{out}}\right), & z > S_{\text{in}} \end{cases}$$

$S_{\text{in}}$ 或 $S_{\text{out}}$ 为 0（黑白场重合）时按整圈 $360°$ 处理。

$$u = \operatorname{clamp}\!\left(\frac{x-x_{\text{lo}}}{x_{\text{hi}}-x_{\text{lo}}},\,0,\,1\right), \qquad \text{out} = o_{\text{lo}} + u^{1/\gamma}\,\bigl(o_{\text{hi}}-o_{\text{lo}}\bigr)$$

$o_{\text{lo}} > o_{\text{hi}}$ 时输出反相；结果夹在 $[\min(o_{\text{lo}},o_{\text{hi}}),\ \max(o_{\text{lo}},o_{\text{hi}})]$ 内。

规则细则

  • H 环形重映射：把圆在黑场处剪开，主弧（黑场 → 白场）映到输出弧， 剩余弧按比例跟进，两段共用 gamma。默认参数逐位还原；黑白场重合 = 纯色相旋转。
  • C 线性：C 归零 → 全图变中性灰（Lab 的 a=b=0），这是最常用的「去色」 手法；C 反向输出（下限 > 上限）会得到互补色的味道，但明度不动。
  • L 线性：普通色阶语义，与 lab-levels 的 L 完全一致。
  • 黑白场交叉自动交换。
  • alpha ≤ 0 透传。
  • C 超过色域的输入会被 clamp 到 132；输出 C 可以拉高，超出 sRGB 的部分由 babl 转回 RGB 时裁掉（等价于 GIMP 色域警告里的那些像素）。

与 lb:lab-levels / lb:hue-saturation 的关系

需求用哪个
单独压/提色度，色相不动本算子（C 通道）
单独转色相，色度不动本算子（H 通道）
分别调 a、b 两轴（比如只加黄不加绿）lb:lab-levels
按色相段分别调饱和度/明度（RAW 编辑器 风格）lb:hsl-seven

python tools/check_color_levels.py lch（3 项）：

用例判据实测
恒等（默认参数）与源图逐像素 ≤1 码最大 0

LCh↔RGB 的转换在 babl 里，Python 无法复算，所以这里不做公式对拍——但 「C 归零必须得到中性灰」「H 转 180° 必须整环变色」这两条已经把转换方向和 色相环的拓扑覆盖住了；恒等能到 0 码，说明往返没有数值漂移。

已知事项

  • H 在 C≈0（近中性色）时无意义，算子按 H=0 处理；此时调 H 不影响画面。
  • H 的 360°/0° 是同一点，输出下限/上限给到 360 与 0 是等价的，界面不做 特殊提示。

只要这一个

Windows 模块 lch-levels.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 lch-levels.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

LCH Levels

lb:lch-levels Levels area

Levels on CIE LCh — chroma and hue angle as separate channels, so changing one never drags the other along.

Menu: Colors → SuperMrWang → Tone → LCH Levels (a filter op)

Overview

Independent levels for CIE LCh's L, C and H. Same Lab base as lb:lab-levels, but in polar coordinates (chroma C and hue angle H instead of the a/b axes). Changing chroma in LCh does not drag the hue, and changing hue does not drag the chroma — which Lab levels cannot do (there, moving a changes C and H together).

Colour space

Works directly on babl's CIE LCH(ab) alpha float (D50 white point); RGB↔LCh is babl's job, the same convention as GIMP's "Decompose → LCH".

ComponentRangeNotes
L0–100CIE lightness
C0–~132chroma; inside sRGB the maximum is about 131 (pure blue), hence 132
H0–360°hue angle; 0° leans red (pure red is about 40°, pure blue about 301°)
$$z = (h-\text{ia}) \bmod 360,\qquad S_{\text{in}} = (\text{ib}-\text{ia}) \bmod 360,\qquad S_{\text{out}} = (\text{ob}-\text{oa}) \bmod 360$$
$$h' = \bigl(\text{base} + \text{span}\cdot t^{1/\gamma}\bigr) \bmod 360,\qquad (t,\ \text{base},\ \text{span}) = \begin{cases} \left(\dfrac{z}{S_{\text{in}}},\ \text{oa},\ S_{\text{out}}\right), & z \le S_{\text{in}} \\[10pt] \left(\dfrac{z-S_{\text{in}}}{360-S_{\text{in}}},\ \text{oa}+S_{\text{out}},\ 360-S_{\text{out}}\right), & z > S_{\text{in}} \end{cases}$$

A zero $S_{\text{in}}$ or $S_{\text{out}}$ (coincident black / white points) is treated as the full $360°$ circle.

$$u = \operatorname{clamp}\!\left(\frac{x-x_{\text{lo}}}{x_{\text{hi}}-x_{\text{lo}}},\,0,\,1\right), \qquad \text{out} = o_{\text{lo}} + u^{1/\gamma}\,\bigl(o_{\text{hi}}-o_{\text{lo}}\bigr)$$

An inverted output ($o_{\text{lo}} > o_{\text{hi}}$) gives a negative-style inverse; the result is clamped to $[\min(o_{\text{lo}},o_{\text{hi}}),\ \max(o_{\text{lo}},o_{\text{hi}})]$.

Rules

  • Circular hue remap: cut the circle at the black point, map the main arc (black point → white point) onto the output arc and the rest proportionally, both sharing the gamma. Bit-exact at defaults; black and white point at one angle means a pure hue rotation.
  • C is linear: C to zero turns the image neutral grey (Lab a=b=0) — the most common way to desaturate. An inverted C output (low > high) gives a complementary-looking result while lightness stays put.
  • L is linear: ordinary levels semantics, identical to lab-levels' L.
  • Crossed black and white points swap automatically.
  • alpha ≤ 0 passes through.
  • Input above the gamut is clipped to C = 132; the output C can be pushed higher and whatever falls outside sRGB is clipped by babl's conversion back to RGB (the pixels GIMP's gamut warning would flag).

Which operator for what

NeedUse
Lower or raise chroma alone, hue untouchedthis operator (C channel)
Rotate hue alone, chroma untouchedthis operator (H channel)
Move the a and b axes separately (add yellow without green)lb:lab-levels
Per-hue-range saturation/lightness, the RAW editor stylelb:hsl-seven

Verification

python tools/check_color_levels.py lch (3 cases):

CaseCriterionMeasured
identity (defaults)≤1 code per pixel against the sourcemax 0
chroma to zeroneutral everywhere (|R−G|, |G−B| ≤ 2)0
hue ring +180°at least 80% of the ring row visibly changes colour72/72

LCh↔RGB lives inside babl and cannot be recomputed in Python, so there is no formula replay here — but "C to zero must give neutral grey" and "H +180° must recolour the whole ring" cover the conversion direction and the ring topology, and identity at 0 codes shows the round trip does not drift.

Known issues

  • H is meaningless when C≈0 (near-neutral); the operator treats it as H=0, and moving H then changes nothing.
  • H's 360° and 0° are the same point, so output low/high of 360 and 0 are equivalent; the UI does not say so.

Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs.
