lb:calculations 混合与通道 双输入 · 逐像素

PS 计算：两路通道按混合模式合成，输出灰度图或 alpha 蒙版

lb:calculations · 菜单 颜色 → SuperMrWang → Blend → Calculations · 双输入（input + aux）

对应 Photoshop 的 图像 → 计算：从两路各取一个通道（可以各自反相），按混合模式 算出灰度结果，输出成灰蒙版或 alpha 蒙版。

Replicates Photoshop's Image → Calculations: take one channel from each of two sources (each optionally inverted), blend them, and output a grey or alpha mask.

PS 的「结果为选区」在 GEGL 里没法直接建立选区（算子只能输出像素），所以用 alpha 蒙版代替：把它当作图层的不透明度，或转成选区。PS 的「新建文档」也用 灰蒙版代替——灰蒙版单独复制一份就是灰度文档。

想要选区 / 通道：手动三步 / Getting a selection or channel by hand

GEGL 算子只能产出像素，碰不到选区、通道、图层这些图像对象，所以 PS 计算对话框 里的 Result 下拉在这里只能落到「灰蒙版 / alpha 蒙版」。要选区或通道，不改代码也 能做到：

  1. Ctrl+Shift+D 复制图层——必做。GEGL 滤镜是直接改当前图层的像素，不像 PS 的计算那样不碰原图，在副本上跑才不会把原图换掉。
  2. 在副本上跑 Colors → SuperMrWang → Blend → Calculations，Output 选 Mask (alpha)。这一步是关键：alpha 版把灰度写在图层的 alpha 上，才能用 「alpha → 选区」；选灰蒙版的话 alpha 恒为 1，转出来是全选。
  3. 拿选区：Filters → Python-Fu → Console 粘一行
   img = Gimp.get_images()[0]
   img.select_item(Gimp.ChannelOps.REPLACE, img.get_selected_layers()[0])

（select_item 就是「把某个 item 的 alpha 变成选区」，图层和通道都收。） 要通道就接着用 选择 → 保存到通道（gimp-selection-save）。

需要成品的灰度图层当文档用，就在第 2 步选 Mask (grey)，然后「图层 → 复制图层 → 粘贴为新图像」。

plugin/blend 里的 Python 插件版把这几步做成了对话框里的 Result 选项（选区 / 新建 Alpha 通道 / 灰图层 / 写入图层 alpha），但插件目前是停用状态，见根目录 README「Python 插件版」。

GEGL ops can only return pixels — they cannot create selections, channels or layers — so PS's Result drop-down collapses to grey / alpha mask here. The three steps above get you the other two by hand. Note that the duplicate in step 1 is mandatory: a GEGL filter rewrites the layer it runs on, unlike PS's Calculations.

行为细节 / Behaviour notes

  • aux 没接时第二路退化为本图，即「同一张图的两个通道互算」——这是计算最 常用的场景（例如 R 与 G 相减做蒙版），单输入就能直接用。
  • 差值类模式（Difference / Subtract / Divide）在混合后裁到 0..1，与 8bit 行为一致。
  • 深色 / 浅色在单通道上下文里等价于变暗 / 变亮（只有一个通道，没有整像素概念）。
  • 灰蒙版输出 alpha = 1，alpha 蒙版输出 alpha = 灰度值。
  • 通道编号：枚举第 0 位留给 Composite 占位（enum_value_skip，不出现在 下拉列表里），这样 Red/Green/Blue/Luminance/Alpha 的编号才和 common/blend.h 的 LB_CH_* 对得上。少这个占位会让整张表错一位——默认的 Luminance 实际取到蓝通道。
  • 源 2 的透明像素不参与计算：源层是抠图、文字层或带透明背景的图层时， 透明区的 RGB 是 0，当作「黑数据」算进去会把蒙版算成一片黑。这里用源 2 的 alpha 当覆盖率：alpha = 0 处蒙版输出 0（不选中），半透明柔边按比例衰减。 源 2 通道选 Alpha 时，那个 alpha 是数据不是覆盖率，不重复相乘。 Transparent pixels of source 2 take no part: on a cut-out the holes hold RGB 0, which would compute a solid black mask. Source 2's alpha is used as coverage — 0 gives a 0 mask (not selected), and soft mattes fade. When source 2's channel is alpha, that value is data, not coverage.
  • 源层比主图小 / 带偏移：aux 没覆盖到的像素按黑色参与计算（蒙版那里就是 0）。PS 的计算要求两个来源同尺寸，这里不强制，缺的部分当黑。

Calculations

lb:calculations Blend two inputs · per-pixel

Photoshop's Image → Calculations: pull one channel from each of two sources, invert either, blend, and output a grey or alpha mask.

lb:calculations · menu Colors → SuperMrWang → Blend → Calculations · two inputs (input + aux)

Replicates Photoshop's Image → Calculations: take one channel from each of two sources (each optionally inverted), blend them into a greyscale result, and output it as a grey mask or an alpha mask.

How it maps to Photoshop

PhotoshopHere
Source 1: layer + channel + invertinput + source1-channel + invert-source1
Source 2: layer + channel + invertaux + source2-channel + invert-source2
Blending / Opacityblend-mode / opacity
Maskmask-channel + invert-mask
Result: new document / new channeloutput-mode = grey mask; the grey layer works as a document or channel

Photoshop's "Result: selection" cannot be produced straight from a GEGL operator (operators only return pixels), so an alpha mask stands in for it: use it as the layer's opacity or convert it to a selection. "New document" is likewise replaced by a grey mask — copy that layer into a new image and you have a greyscale document.

Getting a selection or channel by hand

A GEGL op produces pixels and cannot touch selections, channels or layers, so the Result drop-down of Photoshop's dialog collapses to "grey mask / alpha mask" here. You can still get the other two without changing code:

  1. Ctrl+Shift+D to duplicate the layer — mandatory. A GEGL filter rewrites the pixels of the layer it runs on, unlike Photoshop's Calculations, so running on a copy is what keeps the original intact.
  2. On the copy run Colors → SuperMrWang → Blend → Calculations with Output set to Mask (alpha). This step matters: the alpha version writes the grey values into the layer's alpha, which is what "alpha → selection" needs; with a grey mask the alpha is always 1 and the conversion selects everything.
  3. To get the selection, open Filters → Python-Fu → Console and paste one line:
   img = Gimp.get_images()[0]
   img.select_item(Gimp.ChannelOps.REPLACE, img.get_selected_layers()[0])

(select_item is exactly "turn an item's alpha into a selection" and accepts layers and channels.) For a channel, follow up with Select → Save to Channel (gimp-selection-save).

If you want a finished greyscale layer to use as a document, pick Mask (grey) in step 2 and then "Layer → Duplicate Layer → Paste as New Image".

The Python plug-in in plugin/blend turns these steps into Result options in the dialog (selection / new alpha channel / grey layer / write into layer alpha), but that plug-in is currently disabled — see "Python plug-in" in the root README.

Behaviour notes

  • With no aux connected the second source falls back to the input, i.e. "blend two channels of the same image" — the most common use of Calculations (R minus G for a mask, for instance) works with a single input.
  • Difference-like modes (Difference / Subtract / Divide) are clipped to 0..1 after blending, matching 8-bit behaviour.
  • Darker / Lighter Color degenerate to Darken / Lighten here: there is only one channel, so there is no whole-pixel notion.
  • A grey mask outputs alpha = 1; an alpha mask outputs alpha = the grey value.
  • Channel numbering: enum value 0 is a Composite placeholder (enum_value_skip, not shown in the drop-down) so that Red/Green/Blue/Luminance/Alpha line up with LB_CH_* in common/blend.h. Without the placeholder the whole table shifts by one — the default Luminance would silently read the blue channel.
  • Transparent pixels of source 2 take no part. On a cut-out, text layer or any layer with a transparent background the holes hold RGB 0, and counting them as "black data" computes a solid black mask. Source 2's alpha is used as coverage: alpha = 0 gives a 0 mask (not selected) and a soft matte fades proportionally. When source 2's channel is alpha, that value is data, not coverage, so it is not multiplied in again.
  • A source layer smaller than the input or offset: uncovered pixels take part as black (which means 0 in the mask). Photoshop requires both sources to match in size; this operator does not, and treats the missing part as black.
