HSV Dual Extract

lb:hsv-dual 分量 整块区域

HSV 分量曲线工作流的提取器：把一张图拆成「R = HSV 饱和度、G = HSV 明度、B = 色相/360」的数据图，一张图同时携带三个分量

把一张图打包成一张数据图：R = HSV 饱和度、G = HSV 明度、B = 色相/360，全部 0…1。alpha 恒为 1。

原图 ──lb:hsv-dual──> (R=S, G=V, B=H/360)
                          │
                 ┌────────┼────────┐
              S(红)     V(绿)    H(蓝)
                 └────────┼────────┘
                          ▼
                    lb:hsv-compose  ──> 真实颜色

为什么要挤进同一张图

HSV 的三个分量互相耦合：

V = max(R,G,B)              S = (max − min) / V
H = 由三者比例决定（60° 一档的线性插值）

想让「只改 S、V 与 H 不动」成立，合成器必须同时读到三者。拆成三张灰度图的话，只能靠 GIMP 的 HSV 分量混合模式逐层替换——那是 HSV Split (Curves) 的旧做法：三层、每层 extract → 曲线 → encode，三次编码、三次量化。

一张图 + 三条曲线 + 一次合成，同样精确，但少两层、少一半滤镜。

输入输出

格式含义
inputR'G'B'A float滤镜栈的编码域缓冲，与 component-extract 同域
outputR'G'B'A float数值是数据不是颜色：0.6 / 0.8 / 0.583 = S 60%、V 80%、色相 210°

转换由 babl 的 HSVA float 完成，与 GIMP 的 HSV 分量模式同一口径；babl 的输出本来就是 0…1 归一化（h/360、s、v），本算子只做通道重排。

alpha 恒写 1：分量层必须不透明，透明度交给组蒙版。

实测

tools/check_hsv_split.py 里 dual → compose 恒等往返：32 位浮点 0.0002 码， 8 位 0.49 码（就是量化本身）。灰像素（S = 0）的色相在 babl 侧无定义，算子把非有限值折成 0，不会把 NaN 漏进缓冲。

注意

  • 输出是数据图，不要直接看它当照片。
  • 它和 lb:hsv-compose 配对使用，只装一个没有意义。

只要这一个

Windows 模块 hsv-dual.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 hsv-dual.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

HSV Dual Extract

lb:hsv-dual Component area

Packs HSV saturation, value and hue into a single data image — three curves, one compose, instead of three separate layers that each quantise on the way back.

Menu: Colors → SuperMrWang → Component → HSV Dual Extract (a filter op)

Overview

Packs an image into one data image: R = HSV saturation, G = HSV value, B = hue/360, all 0…1. Alpha is always 1.

input ── lb:hsv-dual ──> (R=S, G=V, B=H/360)
            │
            ├── S curve (red)
            ├── V curve (green)
            ├── H curve (blue)
            ▼
     lb:hsv-compose ──> real colour

Why pack all three into one image

HSV's three components are coupled:

V = max(R,G,B)              S = (max − min) / V
H = set by the ratio between them (linear within 60° steps)

For "change S only, leave V and H alone" to hold exactly, the composer has to read all three at once. Split into three greyscale images and you can only swap them back layer by layer with GIMP's HSV component blend modes — the old HSV Split (Curves) route: three layers, each doing extract → curves → encode, three encodes and three quantisations.

One image, three curves, one compose is just as exact with two fewer layers and half the filters.

Input and output

FormatMeaning
inputR'G'B'A floatthe filter stack's encoding-domain buffer, same domain as component-extract
outputR'G'B'A floatthe numbers are data, not colour: 0.6 / 0.8 / 0.583 = S 60%, V 80%, hue 210°

The conversion is babl's HSVA float, the same one GIMP's HSV component mode uses; babl already returns normalised 0…1 values (h/360, s, v), so this operator only reorders channels.

Alpha is written as 1 unconditionally: a component layer has to be opaque, and transparency belongs on a group mask.

Verification

tools/check_hsv_split.py runs the dual → compose identity round trip: 0.0002 codes in 32-bit float, 0.49 codes in 8-bit (which is the quantisation itself). Grey pixels (S = 0) have no defined hue on the babl side; the operator folds non-finite values to 0 so no NaN leaks into the buffer.

Notes

  • The output is a data image — do not read it as a photo.
  • It only works paired with lb:hsv-compose.

Just this one

Windows module hsv-dual.dll, drop it into %LOCALAPPDATA%\gegl-0.4\plug-ins; Linux module hsv-dual.so, drop it into ~/.local/share/gegl-0.4/plug-ins, then restart GIMP. Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs. The full bundle is on the download page.
