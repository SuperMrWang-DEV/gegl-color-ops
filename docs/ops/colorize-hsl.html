Colorize

lb:colorize-hsl 色彩 逐像素

复刻 经典图像编辑器「色相/饱和度」里的「着色」复选框

复刻 经典图像编辑器的「色相/饱和度」对话框里的「着色」复选框，按实测标定，不是凭经验的近似（旧版实现用「颜色填充层 + Overlay 叠灰」，与经典图像编辑器无关，偏差很大，已废弃）。标定过程与数据见 colorize-cal/RESULTS.md。

  • GEGL id：lb:colorize-hsl
  • 菜单：Colors → SuperMrWang → Color → Colorize
  • 类型：GeglOperationPointFilter（逐像素，无邻域）
  • 参数：hue（0…360，绝对色相）、saturation（0…100，绝对值）、lightness（−100…100）

算法

在 sRGB 编码值（R~G~B~A float，感知域而非线性光）上取 HSL 的 L，然后：

$$t = \frac{\text{lightness}}{100},\qquad L' = \begin{cases} L + t\,(1-L), & t > 0 \\[4pt] L\,(1+t), & t < 0 \\[4pt] L, & t = 0 \end{cases}$$
$$\text{out} = \operatorname{HSL2RGB}\!\left(\text{hue},\ \frac{\text{saturation}}{100},\ L'\right)$$

就这些。三条结论撑起整个模型：

  1. 输入像素的 H 与 S 被完全丢弃。 等 L、等 S、色相绕一整圈的色环，过完着色后 同一带内输出离散度是 0.00 码 —— 输出只由输入 L 决定。
  2. 三根滑杆都是绝对量，不是增量。 色相 0/30/60/120/180/240/300 精确落回同名 色相；饱和度 25/50/75 落回 HSL S = 0.250/0.500/0.750；明度 0 时 L' = L。
  3. 明度滑杆是 L 的线性函数，中点 L=0.5 时位移正好 t/2，两端不动。0 和 1 之外 自动钳位（l=+100 全白、l=−100 全黑）。

色相滑杆不回绕：负值被钳到 0（实测 −20 给出纯红，不是 340°）。这一条已在算子里显式处理，value_range 也限定在 0…360。

验收

python tools/check_colorize_ps.py —— gegl CLI 渲染标定图，与经典图像编辑器26.10 的 16 位导出逐像素比（单位：8 位码）：

指标结果
参数组合104 组（明度步长 5 全扫、饱和度步长 5、色相步长 20 + 非整数档、8 组三滑杆组合）
样本数每组 512×256，合计 1363 万像素
中位偏差0.008 码
95% 偏差0.016 码
最大偏差0.03 码

0.03 码就是 1 个 16 位 LSB（65535 满量程的 1/65535 ≈ 0.0039 码 × 8），来自经典图像编辑器那边的浮点截断，不是模型误差。

注意：tools/contact_sheet.py 的 read_png 把 16 位按 v*255//65535 整数下取整，会把 32895 读成 127 而不是 128，凭空造出 1 码的假偏差。验收脚本因此改用 bc-cal/readpng.py 的浮点读取（v/257）。

与 lb:hue-saturation 的区别

lb:hue-saturation 是增量模式（在像素自己的 H/S/L 上加偏移，六个色相区间可分别调），对应经典图像编辑器未勾选「着色」时的行为。lb:colorize-hsl 是绝对模式：扔掉原有的颜色，只保留明暗，整幅图变成一个单色调。两者互补，不能互相替代。

只要这一个

Windows 模块 colorize-hsl.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 colorize-hsl.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

Colorize

lb:colorize-hsl Color per-pixel

The classic editor's Colorize checkbox from Hue/Saturation — input hue and saturation are discarded, only lightness survives.

Reproduces the "Colorize" checkbox in the classic editor's Hue/Saturation dialog, calibrated against measurements rather than approximated (the old build used a fill layer plus an Overlay grey and had nothing to do with the classic editor; it is gone). The calibration data is in colorize-cal/RESULTS.md.

  • GEGL id: lb:colorize-hsl
  • Menu: Colors → SuperMrWang → Color → Colorize
  • Type: GeglOperationPointFilter (per-pixel, no neighbourhood)
  • Parameters: hue (0…360, absolute hue), saturation (0…100, absolute), lightness (−100…100)

Algorithm

Take HSL's L on sRGB encoded values (R~G~B~A float, the perceptual domain, not linear light), then:

$$t = \frac{\text{lightness}}{100},\qquad L' = \begin{cases} L + t\,(1-L), & t > 0 \\[4pt] L\,(1+t), & t < 0 \\[4pt] L, & t = 0 \end{cases}$$
$$\text{out} = \operatorname{HSL2RGB}\!\left(\text{hue},\ \frac{\text{saturation}}{100},\ L'\right)$$

That is all. Three findings carry the whole model:

  1. The input pixel's H and S are discarded entirely. A hue ring with equal L and equal S, one full turn around the wheel, comes out with a spread of 0.00 code values inside a single band — the output depends on input L alone.
  2. All three sliders are absolute, not relative. Hues 0/30/60/120/180/240/300 land exactly on the hue of the same name; saturations 25/50/75 land on HSL S = 0.250/0.500/0.750; lightness 0 leaves L' = L.
  3. The lightness slider is linear in L, moving exactly t/2 at the midpoint L=0.5 and nothing at either end. Outside 0 and 1 it clamps (l=+100 is white, l=−100 is black).

The hue slider does not wrap: negative values clamp to 0 (measured −20 gives pure red, not 340°). The operator handles that explicitly and value_range is 0…360.

Acceptance

python tools/check_colorize_ps.py renders the calibration chart through the gegl CLI and compares it with classic image editor 26.10's 16-bit export, pixel by pixel (in 8-bit code values):

MetricResult
Parameter sets104 (all lightness steps of 5, saturation steps of 5, hue steps of 20 plus fractional ones, 8 three-slider combinations)
Samples512×256 each, 13.63 million pixels in total
Median0.008 code
95th percentile0.016 code
Max0.03 code

0.03 code is one 16-bit LSB, coming from floating-point truncation on the the classic editor side rather than model error.

Note: tools/contact_sheet.py's read_png converts 16-bit with v*255//65535 (integer floor), which reads 32895 as 127 instead of 128 and invents a fake 1-code deviation. The acceptance script therefore uses the float reader in bc-cal/readpng.py (v/257).

Difference from lb:hue-saturation

lb:hue-saturation is the relative mode (offset the pixel's own H/S/L, with six hue ranges adjustable separately), i.e. the classic editor with Colorize unchecked. lb:colorize-hsl is the absolute mode: it throws the existing colour away, keeps only the tonal structure, and turns the whole image into a monochrome tint. They are complementary, not interchangeable.

Just this one

Windows module colorize-hsl.dll, drop it into %LOCALAPPDATA%\gegl-0.4\plug-ins; Linux module colorize-hsl.so, drop it into ~/.local/share/gegl-0.4/plug-ins, then restart GIMP. Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs.
