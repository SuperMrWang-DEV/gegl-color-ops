Lens Correction（SuperMrWang → Distort）

lb:lens-correction 扭曲 Custom

PS「滤镜 → 镜头校正」里最常动的三项：桶形 / 枕形畸变、暗角、横向色差。一个算子一次重采样全解决，参数挂在图层滤镜栈上，原像素一个字节不动。

lb:lens-correction · 菜单 SuperMrWang → Distort → 镜头校正… · 单输入

PS「滤镜 → 镜头校正」里真正会动的三项——桶形 / 枕形畸变、暗角、横向色差——一个算子一次重采样全解决。GIMP 自带的 gegl:lens-distortion 只有畸变，没有暗角和色差；把三项分开挂三条滤镜，就得重采样三遍、画质掉三轮。

归一化半径：为什么是半对角线

所有半径都按画面半对角线归一化，四角恰好落在 r = 1：

r = |p − c| / (0.5 · √(w² + h²))

用短边归一化的话，同一组 k1 在 4:3 和 3:2 上看到的角落形变不一样——角落是畸变最明显的地方，那里不一致，参数就没有可移植性。用对角的另一半同理，只是把 1 挪到了别处。半对角线让「r = 1」和「画面四角」是同一件事。

畸变 / Distortion

Brown–Conrady 的径向项，只取前两阶：

s(r) = 1 + k1·r² + k2·r⁴
src  = c + (p − c) · s(r) · zoom
  • k1 > 0：从更外面取样 → 画面收缩 → 去桶形畸变（DxO / Lightroom 里 「桶形」滑杆往正方向拉）。
  • k1 < 0：画面膨胀，加桶形 / 鱼眼味道。
  • k2 是 r⁴ 项，只在角落附近咬得住：k1 修不干净的「角落还差一点」，用它补。 常见量级在 0.01–0.05，给到 ±0.5 是为了极端鱼眼。

r → s(r) 必须单调递增，否则同一块画面会被折回去两次，边缘出现镜像重影。 k1 = -0.5 已经接近边界（s'(1) = 1 + 3k1 + 5k2 ≈ -0.5），量程就夹在 ±0.5，再大不是「更强的效果」而是碎图。

自动缩放 / Auto scale

s(1) = 1 + k1 + k2 就是角落的采样倍率。自动缩放直接除以它：

zoom = 1 / (1 + k1 + k2)

于是角落映射回角落，画面只是被压进中心一点，不会在四个角留下透明缺口。关掉它（auto-zoom = off）就能看到那四个缺口——这也是为什么它默认开。 zoom 是在自动缩放之上再乘一个手调系数，PS 的「缩放」滑杆是同一件事。

暗角 / Vignette

t    = smoothstep(mid, mid + feather, r)
gain = 1 + vignette/100 · t
  • 负值压暗、正值提亮，-100 就是角落全黑。
  • midpoint（默认 0.55）是开始衰减的半径，feather（默认 0.45）是过渡宽度。 feather 太小会看到一圈硬边同心环，这是暗角最容易做丑的地方。
  • 暗角按输出半径算，不按畸变后的源半径：它描述的是成像面上的照度衰减， 与几何校正无关。所以畸形调完再压暗角，位置不会跟着跑。

横向色差 / Lateral CA

r_red  = r · (1 + ca_red  / halfdiag · r²)
r_blue = r · (1 + ca_blue / halfdiag · r²)
  • 位移按角落处的像素给：ca_red = 2 表示红通道在四角向外偏 2 px，中心 不动（r² 让它在中心附近几乎为零）。24 MP 的机器上常见量级是 ±1–3 px。
  • 绿通道不参与。横向色差是镜头色散让三个颜色的成像尺寸略有不同，绿通常 落在中间、也是合焦参考，修它等于把整幅往外拉。
  • 红蓝一般反号：一边大一边小，紫边就是这么来的。

快路径

几何三项全关时不做逐像素采样：

全默认gegl_buffer_copy 直接拷0.09 s
只有暗角整块读入 → 乘增益 → 写回0.05 s

色差让采样次数从 1 变 3，这是它贵的原因；不需要色差时别让它在栈上留一个非零值。768×1024 上分别是 0.07 / 0.05 / 0.22 / 0.56 s。插件的实时预览是缩到 560 长边再挂滤镜，一次 30 ms 上下，拖滑杆跟手。

和 PS 差在哪

有：三项一个对话框、非破坏滤镜、11 个参数全可脚本化、四档越界、五档重采样、自动缩放、暗角 / 色差各自独立（PS 也是）。

没有：镜头配置文件（.lcp / lensfun 数据库）自动匹配——那要一份镜头数据库和一个按 EXIF 查表的入口；几何校正（梯形 / 旋转 / 横向偏移）；用边缘检测自动估 k1 的那个「自动」按钮。三者都不是重采样本身的问题，是「找参数」的问题。手上有 EXIF 的人可以自己算，没有的人照 PS 的习惯拖滑杆就行。

Lens Correction

lb:lens-correction Distort Custom

Distortion, vignetting and lateral CA in one resample, with an auto scale that keeps the corners in frame.

lb:lens-correction · menu SuperMrWang → Distort → Lens Correction… · single input

The three Lens Correction controls people actually turn: barrel / pincushion distortion, vignetting and lateral chromatic aberration. One operator, one resample. GIMP's own gegl:lens-distortion handles distortion only; stacking the three as separate filters would resample the picture three times and lose sharpness at each pass.

Normalised radius

Every radius is measured against the half diagonal, so the four corners sit exactly at r = 1:

r = |p − c| / (0.5 · √(w² + h²))

Normalising to the short edge would make one k1 pair produce different corner shapes on 4:3 and 3:2 — and the corners are where distortion is most visible, so that is the one place the numbers must mean the same thing.

Distortion

The first two terms of the Brown–Conrady radial series:

s(r) = 1 + k1·r² + k2·r⁴
src  = c + (p − c) · s(r) · zoom
  • k1 > 0 samples from further out, shrinking the picture — this removes barrel distortion and is the direction Lightroom's "barrel" slider moves.
  • k1 < 0 inflates it, adding barrel / fisheye character.
  • k2 is the r⁴ term and only bites near the corners: it cleans up what k1 leaves behind. Typical values are 0.01–0.05; the ±0.5 range exists for extreme fisheye work.

r → s(r) has to stay monotonic. Once it folds back, one slice of the picture gets sampled twice and the border mirrors. k1 = -0.5 is already near that cliff, which is why the range stops there — past it you get a broken image, not a stronger effect.

Auto scale

s(1) = 1 + k1 + k2 is the corner sampling ratio, so auto scale simply divides by it: zoom = 1 / (1 + k1 + k2). The corners land back on the frame and the picture is only pulled slightly inward — no transparent notches. Turn it off to see those notches; that is why it is on by default. The manual zoom multiplies on top, the same thing Photoshop's "Scale" slider does.

Vignette

t    = smoothstep(mid, mid + feather, r)
gain = 1 + vignette/100 · t

Negative darkens, positive lightens (-100 is a black corner). midpoint (default 0.55) is where the falloff starts, feather (0.45) its width; too small a feather and you see a hard concentric ring, which is the easiest way to make a vignette look cheap.

The vignette is computed from the output radius, not the distorted source radius: it describes illumination falloff on the sensor and should not move when the geometry changes.

Lateral CA

r_red  = r · (1 + ca_red  / halfdiag · r²)
r_blue = r · (1 + ca_blue / halfdiag · r²)

The shift is given in pixels at the corners: ca_red = 2 moves the red channel 2 px outward at the corners while the centre stays put (the r² makes it vanish near the middle). On a 24 MP frame the usual amount is ±1–3 px.

Green does not participate. Lateral CA means the three colours image at slightly different scales; green is both the middle one and the focus reference, so shifting it would drag the whole picture outward. Red and blue normally take opposite signs — that mismatch is what a purple fringe is.

Fast paths

With all three geometric controls at zero the operator does not sample at all:

CaseWhat happens1600×2400
Everything defaultgegl_buffer_copy0.09 s
Vignette onlyread band, multiply, write back0.05 s
Distortion, no CAone nohalo sample per pixel1.10 s
Distortion + CAthree samples (R, G, B)2.69 s
Distortion + CA, bilinearthree linear samples0.92 s

CA triples the sampler cost. Leave it at zero when you do not need it. On 768×1024 the same rows read 0.07 / 0.05 / 0.22 / 0.56 s. The plug-in previews on a 560 px copy, about 30 ms per update, so the sliders track the hand.

Compared with Photoshop

Has: all three in one dialog, a live (non-destructive) filter, eleven scriptable properties, four edge policies, five resamplers, auto scale, and independent vignette / CA controls.

Missing: lens profile lookup (.lcp / lensfun from EXIF), geometric correction (perspective / rotate / shift), and the "Auto" button that estimates k1 from edge detection. None of those are resampling problems — they are about finding the numbers. With EXIF in hand you can compute them; without it, drag the sliders the way you would in Photoshop.

Regression

tools/check_lens_correction_gimp.py, 28 checks: the operator attaches as a layer filter, properties read back, identity parameters are byte-for-byte identical, the source pixels survive append_filter, sample radius in both directions of k1 (the test image encodes its own radius as R = 255·r, so the expected values are read off the pixels), auto scale keeps the corners opaque, transparent vs clamp edge policy, three vignette sample points, positive vignette lightening, CA moving only red and blue in opposite directions, extreme parameters not exploding, and 0.077 s for a fully loaded 240×240 pass.
