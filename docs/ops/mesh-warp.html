Mesh Warp (live)

lb:mesh-warp 扭曲 整块区域

自由变形（PS 的「变形/网格变形」那一路）：一张 cols×rows 的Bezier 控制网，每个交点带 u/v 两个方向的切向，反解时用 Newton把目标像素解回参数 (u,v)，再取原位网格上的颜色。非破坏——网格串挂在滤镜栈上，重新打开对话框能接着拖。

plugin/mesh-warp 的 C 版：FFD + 双三次 Bezier 面片，挂成图层上的实时滤镜。网格串存在滤镜上，像素不动，重跑对话框会读回来接着拖。

图层 ──▶ ┌──────────────────────────┐ ──▶ 画布
         │ lb:mesh-warp（滤镜栈里） │      网格串 = 唯一属性
         └──────────────────────────┘

菜单：SuperMrWang → Distort → Mesh Warp (live)…。破坏性那版是 Python 的「自由变形（网格 + 把手）」，两者并存。

属性

只有一个 mesh 字符串：

cols,rows; x,y,ux,uy,vx,vy[,auto]; …        # 默认 U 分割线
u:0,1,2,3                                   # 自己加过线时才写
v:0,1,2

x,y 是交点位置，ux,uy / vx,vy 是两个方向的切向（每参数单位）， auto=1 表示把手按邻居自动重算并限幅。格式与 plugin/_shared/mesh_warp.py 的 format_mesh_string 一致，两边互读。

算法要点

  • 每格用 16 个控制点的 Bezier 面片（PS 的网格变形同款），目标像素用 Newton 反解 (u,v)，源坐标取 uv 在原位格上的位置——弄反了整幅图会平移一次。
  • Newton 必须限步（0.75 格）并钳在 [0,cols]×[0,rows]，否则在格界上无限震荡。
  • 反解初值按目标画布的 w/h 归一化；拿 mesh 自己的 w 会在预览与应用两路 收敛到不同分支（实测差 28 px）。
  • 把手要按邻居弦长自动限幅，否则片会甩过头、格子自交，画面上撕一道。
  • 与 Python 版在折点附近 Newton 可能落到另一支：逐像素对拍 mean ≈ 0.2 级， 十几个像素最大差 ~110 级，属已知口径差，回归按这个容差卡。

CLI

gegl in.png -o out.png -- lb:mesh-warp mesh="3,3;10,10,60,0,0,45,1;…"

值里不能有空格（GEGL CLI 按空格拆参数），写错只会拿到原图、不报错。

只要这一个

Windows 模块 mesh-warp.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

Mesh Warp (live)

lb:mesh-warp Distort area

The free-transform grid (FFD with bicubic Bezier patches) as a live GEGL filter — one mesh string on the filter stack, pixels untouched, re-running the dialog reads it back.

The C version of plugin/mesh-warp: free-form deformation with bicubic Bezier patches, attached as a real-time filter on the layer. The grid string lives on the filter, the pixels stay untouched, and running the dialog again reads the grid back so you can keep dragging.

layer ──▶ ┌──────────────────────────┐ ──▶ canvas
          │ lb:mesh-warp (filter)    │      the mesh string is the only property
          └──────────────────────────┘

Menu: SuperMrWang → Distort → Mesh Warp (live)…. The destructive version is the Python “Free Transform (Mesh + Handles)”; both stay available.

Property

A single mesh string:

cols,rows; x,y,ux,uy,vx,vy[,auto]; …        # default U breakpoints
u:0,1,2,3                                   # written only after you add lines
v:0,1,2

x,y is the intersection point, ux,uy / vx,vy the two tangent vectors (per parameter unit), and auto=1 means the handles follow their neighbours and are clamped automatically. The format matches format_mesh_string in plugin/_shared/mesh_warp.py, so both directions read each other.

Algorithm notes

  • Each cell is a Bezier patch with 16 control points (the same construction as Photoshop's mesh warp). Target pixels are inverted to (u,v) with Newton, and the source coordinate is taken from the uv position in the original grid — swap that around and the whole image shifts once.
  • Newton must clamp its step (0.75 cell) and stay inside [0,cols]×[0,rows], otherwise it oscillates forever on a cell boundary.
  • The inversion's initial guess is normalised by the target canvas width and height; using the mesh's own width makes the preview and the full-resolution pass converge to different branches (28 px apart in measurement).
  • Handles are clamped to the neighbouring chord lengths, otherwise a patch overshoots, cells self-intersect and a tear appears on screen.
  • Near fold points the C and Python solvers may land on different Newton branches: pixel-by-pixel agreement is mean ≈ 0.2 levels with a dozen pixels off by up to ~110 levels. That is a known difference in convention, and the regression allows for it.

CLI

gegl in.png -o out.png -- lb:mesh-warp mesh="3,3;10,10,60,0,0,45,1;…"

The value cannot contain spaces (the GEGL CLI splits on whitespace); a wrong form just hands back the original image without an error.

Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs.
