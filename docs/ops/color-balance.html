Color Balance

lb:color-balance 色彩 整块区域

经典图像编辑器 色彩平衡：阴影 / 中间调 / 高光各自调 C-R、M-G、Y-B 三对色轴the classic editor Color Balance: shadow, midtone and highlight each carry threeaxis pairs (C-R, M-G, Y-B).

对应 经典图像编辑器的「色彩平衡」调整。两个模式：

  • 不保留明度（默认）：经典图像编辑器的逐通道曲线，见下面「算法」一节。
  • 保留明度：MATLAB 零和矩阵（系数减中位数 → 高光 in/(1−α) → 阴影 (in−α)/(1−α) → 中间调 in^γ），与 经典图像编辑器 实测最大差 3.0 码，未做改动。

算法（不保留明度）

一个通道（C-R 动 R、M-G 动 G、Y-B 动 B）只由自己那条滑杆决定，与其它两个通道无关。 三个色调区间的参数先合并成一条曲线：

$$G = g_{\text{阴影}}\cdot g_{\text{中间调}}\cdot g_{\text{高光}},\qquad b = \begin{cases} |s_{\text{阴}}|, & s_{\text{阴}} < 0 \\ 0, & \text{否则} \end{cases}, \qquad W = \begin{cases} 255-s_{\text{高}}, & s_{\text{高}} > 0 \\ 255, & \text{否则} \end{cases}$$
$$u = \frac{v-b}{W-b},\qquad \text{out} = 255\,u^{G}\quad (u \ge H)$$

近黑端另有一段「趾部」：G < 1 时 u^G 在 0 处斜率无穷，经典图像编辑器 实际是有限斜率起步。 把 [b, h0] 这一段换成三次 Hermite：

$$h_0 = b + H\,(W-b),\qquad y_1 = 255\,H^{G},\qquad \text{out} = \operatorname{Hermite}\!\left(\frac{v-b}{h_0-b},\ S_u H,\ y_1,\ G\,y_1\right)$$
  • 指数：中间调 2^(∓s/100)，阴影和高光各只有它的一半 2^(∓s/200)； 算子用实测表（cb-tables.h 的 CB_G），不套公式。
  • Su（归一化起点斜率）与 H（趾部宽度占比）都只随复合指数 G 变化， 与「这个 G 是哪个区间给的」无关：单区间档与组合档落在同一条曲线上（表 CB_TOE）。 G ≥ 0.85 时 H 衰减到 0，趾部自然消失。
  • 忽略趾部的话，中间调 +100 在 v≈4 处会差 16 码；补上后全档 ≤ 0.3 码。

参数由 cb-cal 的 经典图像编辑器 标定得到（经典图像编辑器 26.10、16 位、600 档单区间 + 9 组合）， 完整推导与精度见 ../../cb-cal/RESULTS.md。

不要手改 cb-tables.h，它由 cb-cal/gen_cb_tables.py 从标定数据生成。

与两篇知乎文章的关系

工程早期按下面第 1 篇的「三段独立通道曲线、依次作用」实现，实测下来在高光正向和 阴影负向上偏到 30 码级，组合档更差。本轮重新标定后确认：三段不是依次作用，而是 指数相乘、黑场/白场各取一端的参数合并；单段曲线也不是文章里的 1 − k·s 线性指数。 第 2 篇的零和矩阵（保留明度）与实测吻合，保留原样。

Color Balance

lb:color-balance Color area

The classic editor's Color Balance — one merged levels-style curve per channel, measured against the classic editor to 0.3 code values, plus the legacy preserve-luminosity mode.

the classic editor's Color Balance, in two modes:

  • Preserve luminosity off (default): the classic editor's per-channel curve, see "Algorithm" below.
  • Preserve luminosity on: the MATLAB zero-sum matrix (subtract the median from the coefficients → highlights in/(1−α) → shadows (in−α)/(1−α) → midtones in^γ), left unchanged; max 3.0 code values from the classic editor.

Algorithm (preserve luminosity off)

One channel (C-R drives R, M-G drives G, Y-B drives B) is decided by its own slider alone, independent of the other two. The three tonal-range parameters first merge into a single curve:

$$G = g_{\text{shadow}}\cdot g_{\text{midtone}}\cdot g_{\text{highlight}},\qquad b = \begin{cases} |s_{\text{sh}}|, & s_{\text{sh}} < 0 \\ 0, & \text{otherwise} \end{cases}, \qquad W = \begin{cases} 255-s_{\text{hi}}, & s_{\text{hi}} > 0 \\ 255, & \text{otherwise} \end{cases}$$
$$u = \frac{v-b}{W-b},\qquad \text{out} = 255\,u^{G}\quad (u \ge H)$$

Near black there is a toe: for G < 1, u^G has infinite slope at 0, while the classic editor starts with a finite slope. The segment [b, h0] is replaced by a cubic Hermite:

$$h_0 = b + H\,(W-b),\qquad y_1 = 255\,H^{G},\qquad \text{out} = \operatorname{Hermite}\!\left(\frac{v-b}{h_0-b},\ S_u H,\ y_1,\ G\,y_1\right)$$
  • Exponents: midtones 2^(∓s/100), shadows and highlights half of that 2^(∓s/200); the operator reads measured tables (CB_G in cb-tables.h) rather than evaluating the formula.
  • Su (normalised initial slope) and H (toe width as a fraction) depend on the composite exponent G alone, not on which range produced it: single-range and combined settings fall on the same curve (table CB_TOE). At G ≥ 0.85, H decays to 0 and the toe disappears on its own.
  • Ignoring the toe, midtones +100 is off by 16 code values at v≈4; with it, the whole range is within 0.3.

The parameters come from the the classic editor calibration in cb-cal (the classic editor 26.10, 16-bit, 600 single-range settings + 9 combinations); the full derivation and accuracy are in ../../cb-cal/RESULTS.md.

Do not edit cb-tables.h by hand — it is generated from the calibration data by cb-cal/gen_cb_tables.py.

Relation to the two Zhihu articles

The project first implemented article 1's model — three independent channel curves applied in sequence — and measured it drifting by 30 code values on highlights in the positive direction and shadows in the negative direction, worse still for combinations. Re-calibration showed that the three ranges do not apply in sequence: their exponents multiply and the black/white point parameters merge. Nor is a single range the linear 1 − k·s exponent the article proposes. Article 2's zero-sum matrix (preserve luminosity) does match the measurements and is kept as is.
