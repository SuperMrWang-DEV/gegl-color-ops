Color Temperature & Tint

lb:color-temperature-tint 色彩 逐像素

PS 2026「色彩与自然饱和度」里的色温 / 色调：中性灰跟着偏蓝-黄、绿-洋红，黑白两端不动

按实测逆向出来的 Photoshop 2026「色彩与自然饱和度」调整图层里的色温和色调 两个滑块。PS 27.0 把这两个滑块塞进了原来的 vibrance 图层（官方名 Color and vibrance），Action Manager 里还是老的 vibrance 类，只是多带 temperature / tint 两个整数键，所以这里把白平衡部分单独拆成一个算子，便于叠加到任何管线里。

  • GEGL id：lb:color-temperature-tint
  • 菜单：Colors → SuperMrWang → Color → Color Temperature & Tint PS
  • 类型：GeglOperationPointFilter（逐像素，无邻域）
  • 参数：temperature（−100…100，负冷正暖）、tint（−100…100，负绿正洋红）

算法

编码值 → 解码到线性 → 3 次多项式(20 项) → clamp 到 [0,1] → 编码

三个动作，每个都有明确来源：

步骤为什么
在线性域拟合编码域拟合时 PS 的硬裁切只能被逼近成一团糊；实测负色温区域中位误差到过 90 码
clampPS 是「线性值被压到负数后切 0」。这是整条管线里唯一的强非线性，交给 clamp 精确复现，不要指望多项式
17×17 参数网格 + 双线性插值映射随 (色温, 色调) 变化很快，25 一档跨得太大（网格间误差 10–90 码）；加密到 12/13 一档后降到 1–5 码
烘成 33³ LUT逐像素算 20 项 + 两次 powf 太慢，一张图只烘一次

系数一共 17×17×20×3 = 17340 个数，在 common/temp-tint.h 里，由 tools/gen_temp_tint_tables.py 从 vibrance-cal/temp_tint_grid17_lin.json 生成 —— 要改数值请改上游数据再重新生成，不要手抄。

多项式顶点顺序与标定脚本的 terms() 一致：常数项，然后 d=1..3，每个 d 内按 i=0..d、j=0..d-i 枚举 r^i g^j b^(d-i-j)。输入先居中到 [−1,1] （r' = 2r−1），否则正规方程在 0..1 上病态，系数会解出上百倍。

标定方法

  1. vibrance-cal/make_probe_all.py 生成 32³ = 32768 色块的全色域探针 （1024×2048，横排 128 块，必须嵌 sRGB ICC，否则 PS 按工作空间解释后 饱和色会被裁，早期数据全废在这上面）。
  2. vibrance-cal/batch_vib2026.jsx 驱动 PS 2026 逐点套参数另存 PNG。
  3. vibrance-cal/fit_censored.py 对每个网格点拟合。截断样本（输出 0 或 255） 不含幅值信息但含「这一侧被削平」的信息，用带删失的迭代回归处理： 先在未截断样本上拟合，再把方向错的截断样本按铰链目标补进去重拟合。
  4. vibrance-cal/refit_lin17.py 跑完 289 个网格点，输出 JSON； tools/gen_temp_tint_tables.py 再生成头文件。

已知偏差

除最后一行那种角落，全平面中位误差 ≤ 5 码。角落里不是实现问题，是 PS 自己 在那里不连续：

色温 ≤ −50 且色调 ≥ +38 的对角线上（大致 |色温| ≈ 色调 且都超过 55）， PS 会让某个通道的线性值穿过 0，整通道从 255 塌到 0。实测同一块中性灰 (123,132,132)：

参数PS 输出
(−62, 50)(122, 148, 239)
(−50, 62)(126, 140, 248)
(−62, 62)(117, 148, 0)
(−75, 75)(113, 152, 0)

也就是说相邻一格，结果不是「接近」而是「跨了一个台阶」。连续模型只能在 插值时把两侧混起来，逐像素不可能复刻。要真补上，只能在网格上做局部细分 （产品网格装不下非均匀细分，得整张加密到 6 一档 = 1089 点），收益不划算。

顺带记一下走过的弯路，免得以后重犯：这套映射不是线性矩阵（线性 sRGB 上 最小二乘残差 p99 数十码）、不是通道独立（outR 对 G/B 的敏感度达 247 码）、 不是可分离（M(60,60) ≠ M(tint60)·M(temp60)，误差 0.41）、不是在 Adobe RGB 里做三通道增益（内部样本中位 9.6–100 码）。多项式 + clamp 是目前 唯一撑得住的形式。

性能

对整张图 temperature/tint 是常量：prepare() 插值系数、烘 33³ LUT （约 7 万次 powf，量级是毫秒），process() 只剩每像素 8 次查表 + 7 次乘加。 恒等参数直接 memcpy，不碰像素。

与 lb:vibrance 的关系

PS 2026 的「色彩与自然饱和度」是先色温色调、再 Vibrance的顺序（实验依据： 把色温处理后的图喂给 PS 2025 的纯 Vibrance，与 PS 一次调完的结果中位差 1.4 码； 顺序反了差 36 码）。

两个算子在工程里是分工的，不互相调用：本算子只做白平衡，lb:vibrance 只做 Vibrance。要复刻 PS 2026 那个图层，把本算子叠在 lb:vibrance 前面即可 ——

lb:color-temperature-tint  →  lb:vibrance

顺序由图层栈承担，所以两边的参数表各只有一份，白平衡结果与单独跑本算子逐位相同。
