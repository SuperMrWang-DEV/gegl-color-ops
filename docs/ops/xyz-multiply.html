Photo Filter

lb:xyz-multiply 混合与通道 逐像素

PS「照片滤镜」的复刻：滤镜色在 XYZ 域做正片叠底，密度当不透明度，另有保留明度开关。

这个算子就是 PS 的「照片滤镜」/ This is Photoshop's Photo Filter

PS 的照片滤镜（滤镜 → 调整 → 照片滤镜）内部等价于「纯色填充 + 正片叠底 + 密度」，本算子按实测把整条链路复刻出来。参数一一对应：

PS 照片滤镜lb:xyz-multiply说明
滤镜（Filter）颜色overlay_colorPS 的 20 多个预设只是快捷方式，本质仍是颜色
密度（Density）0–100%opacity 0–1除以 100
保留明度（Preserve Luminosity）preserve_luminosity默认开，与 PS 出厂设置一致
—（PS 没有）white_mode参照白点，默认 D50（PS 的 Lab 白点）

算法（实测反推，不是猜的）

  1. sRGB 线性化，用标准 Bradford（锥响应矩阵，不是适配矩阵本身）转到 D50 XYZ；
  2. 逐通道乘 k = (1-d) + d · (滤镜色XYZ / D50白点)，d = 密度；
  3. 转回编码值；若开保留明度，再做 W3C / PDF 的 SetLum + ClipColor （编码值上、Rec.601 权重 0.3/0.59/0.11）。

前两步在线性 sRGB 里等价于一个常数 3×3 矩阵 M = XYZ2sRGB · A⁻¹ · diag(k) · A · sRGB2XYZ，每 process 只算一次。

判据（都能在 photo-filter-cal/ 里复现）：

  • 纯红、密度 50% 时 128 灰 → G 通道 92。线性光乘给 92.6，编码域乘只会给 64。
  • 纯红、密度 100%、保留明度时 128 灰 → (218, 90, 90)，SetLum 手算恰是 (217.6, 89.6, 89.6)；换成 Lab 保 L\*、乘性还原、Rec.709 权重都对不上（中位差 5～45 码）。
  • 反推的滤镜色 XYZ (0.453, 0.222, 0.0166) 与「纯红转到 D50 再除以 D50 白点」 (0.4522, 0.2225, 0.0169) 差不到 1%；按 D65 归一化则差 4.4% —— 所以是 D50。

Photo Filter

lb:xyz-multiply Blend per-pixel

Photoshop's Photo Filter, reproduced end to end — colour fill + multiply + density in linear sRGB, with W3C preserve-luminosity.

This operator is Photoshop's Photo Filter. Internally PS's Filter → Adjustments → Photo Filter is equivalent to "solid colour fill + multiply + density", and this operator reproduces the whole chain from measurement. The parameters map one for one:

PS Photo Filterlb:xyz-multiplyNotes
Filter colouroverlay_colorPS's twenty-odd presets are shortcuts; it is still a colour underneath
Density 0–100%opacity 0–1divided by 100
Preserve Luminositypreserve_luminosityon by default, matching PS's factory setting
— (PS has none)white_modereference white point, D50 by default (PS's Lab white)

Algorithm (matched by measurement, not guessed)

  1. Linearise sRGB and convert to D50 XYZ with the standard Bradford cone-response matrix (not the adaptation matrix itself);
  2. multiply each channel by k = (1-d) + d · (filter colour XYZ / D50 white), where d is the density;
  3. convert back to encoded values; if preserve-luminosity is on, apply the W3C / PDF SetLum + ClipColor (on encoded values, Rec.601 weights 0.3/0.59/0.11).

Steps 1–2 in linear sRGB are equivalent to one constant 3×3 matrix M = XYZ2sRGB · A⁻¹ · diag(k) · A · sRGB2XYZ, computed once per process.

The evidence (all reproducible from photo-filter-cal/):

  • pure red at 50% density turns 128 grey into a G of 92. Multiplying in linear light gives 92.6; multiplying encoded values would give only 64.
  • pure red, 100% density, preserve luminosity: 128 grey becomes (218, 90, 90), and SetLum by hand is exactly (217.6, 89.6, 89.6); preserving L\* in Lab, multiplicative restoration or Rec.709 weights all miss (median 5–45 code values).
  • the back-solved filter colour XYZ (0.453, 0.222, 0.0166) is within 1% of "pure red converted to D50 divided by the D50 white" (0.4522, 0.2225, 0.0169), while normalising by D65 is off by 4.4% — hence D50.

GroupSettingsMaxMedian
256-step greyscale, no preserve-luminosity90.71 code0.12–0.40

python photo-filter-cal/model_pf.py         # model vs PS
python tools/check_photo_filter.py          # operator vs PS (end to end)
