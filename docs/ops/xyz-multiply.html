Photo Filter

lb:xyz-multiply 混合与通道 逐像素

经典图像编辑器「照片滤镜」的复刻：滤镜色在 XYZ 域做正片叠底，密度当不透明度，另有保留明度开关。

这个算子就是 经典图像编辑器的「照片滤镜」/ This is the classic editor's Photo Filter

经典图像编辑器的照片滤镜（滤镜 → 调整 → 照片滤镜）内部等价于「纯色填充 + 正片叠底 + 密度」，本算子按实测把整条链路复刻出来。参数一一对应：

经典图像编辑器照片滤镜lb:xyz-multiply说明
滤镜（Filter）颜色overlay_color经典图像编辑器的 20 多个预设只是快捷方式，本质仍是颜色
密度（Density）0–100%opacity 0–1除以 100
保留明度（Preserve Luminosity）preserve_luminosity默认开，与经典图像编辑器出厂设置一致
—（经典图像编辑器 没有）white_mode参照白点，默认 D50（经典图像编辑器的 Lab 白点）

算法（实测反推，不是猜的）

  1. sRGB 线性化，用标准 Bradford（锥响应矩阵，不是适配矩阵本身）转到 D50 XYZ；
  2. 逐通道乘一个增益 $k$，$d$ = 密度：
$$k_c = (1-d) + d\cdot\frac{\bigl[\text{XYZ}_{\text{滤镜}}\bigr]_c}{\bigl[\text{XYZ}_{D50}\bigr]_c}$$
  1. 转回编码值；若开保留明度，再做 W3C / PDF 的 SetLum + ClipColor：
$$L = 0.3R + 0.59G + 0.11B,\qquad \text{out}_{ch} \leftarrow \text{out}_{ch} + (L_{\text{in}}-L_{\text{out}})$$

（在编码值上算，Rec.601 权重；之后 ClipColor 把越界像素按比例收回色域。）

前两步在线性 sRGB 里等价于一个常数 $3\times3$ 矩阵，每 process 只算一次：

$$M = A_{\text{XYZ}}^{-1}\cdot\operatorname{diag}(k)\cdot A_{\text{sRGB}}$$

判据（都能在 photo-filter-cal/ 里复现）：

  • 纯红、密度 50% 时 128 灰 → G 通道 92。线性光乘给 92.6，编码域乘只会给 64。
  • 纯红、密度 100%、保留明度时 128 灰 → (218, 90, 90)，SetLum 手算恰是 (217.6, 89.6, 89.6)；换成 Lab 保 L\*、乘性还原、Rec.709 权重都对不上（中位差 5～45 码）。
  • 反推的滤镜色 XYZ (0.453, 0.222, 0.0166) 与「纯红转到 D50 再除以 D50 白点」 (0.4522, 0.2225, 0.0169) 差不到 1%；按 D65 归一化则差 4.4% —— 所以是 D50。

实测精度（经典图像编辑器 2025）

组档数最大差中位差

保留明度档的大误差只出现在裁剪边界（整幅彩色图 12288 个通道值里 55～96 个），是 经典图像编辑器的取整顺序与 W3C 参考实现不同造成的，非边界点的中位差在 0.7 码以内。

Photo Filter

lb:xyz-multiply Blend per-pixel

The classic editor's Photo Filter, reproduced end to end — colour fill + multiply + density in linear sRGB, with W3C preserve-luminosity.

This operator is the classic editor's Photo Filter. Internally the classic editor's Filter → Adjustments → Photo Filter is equivalent to "solid colour fill + multiply + density", and this operator reproduces the whole chain from measurement. The parameters map one for one:

the classic editor Photo Filterlb:xyz-multiplyNotes
Filter colouroverlay_colorthe classic editor's twenty-odd presets are shortcuts; it is still a colour underneath
Density 0–100%opacity 0–1divided by 100
Preserve Luminositypreserve_luminosityon by default, matching the classic editor's factory setting
— (the classic editor has none)white_modereference white point, D50 by default (the classic editor's Lab white)

Algorithm (matched by measurement, not guessed)

  1. Linearise sRGB and convert to D50 XYZ with the standard Bradford cone-response matrix (not the adaptation matrix itself);
  2. multiply each channel by a gain, where $d$ is the density:
$$k_c = (1-d) + d\cdot\frac{\bigl[\text{XYZ}_{\text{filter}}\bigr]_c}{\bigl[\text{XYZ}_{D50}\bigr]_c}$$
  1. convert back to encoded values; if preserve-luminosity is on, apply the W3C / PDF SetLum + ClipColor:
$$L = 0.3R + 0.59G + 0.11B,\qquad \text{out}_{ch} \leftarrow \text{out}_{ch} + (L_{\text{in}}-L_{\text{out}})$$

(on encoded values, Rec.601 weights; ClipColor then scales out-of-gamut pixels back.)

Steps 1–2 in linear sRGB are equivalent to one constant $3\times3$ matrix, computed once per process:

$$M = A_{\text{XYZ}}^{-1}\cdot\operatorname{diag}(k)\cdot A_{\text{sRGB}}$$

The evidence (all reproducible from photo-filter-cal/):

  • pure red at 50% density turns 128 grey into a G of 92. Multiplying in linear light gives 92.6; multiplying encoded values would give only 64.
  • pure red, 100% density, preserve luminosity: 128 grey becomes (218, 90, 90), and SetLum by hand is exactly (217.6, 89.6, 89.6); preserving L\* in Lab, multiplicative restoration or Rec.709 weights all miss (median 5–45 code values).
  • the back-solved filter colour XYZ (0.453, 0.222, 0.0166) is within 1% of "pure red converted to D50 divided by the D50 white" (0.4522, 0.2225, 0.0169), while normalising by D65 is off by 4.4% — hence D50.

Measured accuracy (the classic editor 2025)

GroupSettingsMaxMedian
256-step greyscale, no preserve-luminosity90.71 code0.12–0.40
256-step greyscale, preserve-luminosity31.86 code0.26–0.42
Colour 64×64, no preserve-luminosity30.65 code0.35–0.39
Colour 64×64, preserve-luminosity35.65 code0.56–0.69

The large errors in the preserve-luminosity groups occur only at clipping boundaries (55–96 of the 12288 channel values in a full colour chart) and come from the classic editor rounding in a different order than the W3C reference; away from those boundaries the median is within 0.7 code values.

# run photo-filter-cal/batch_pf.jsx in the classic editor       # 12 greyscale settings
# run photo-filter-cal/batch_pf_color.jsx in the classic editor # 6 colour settings
python photo-filter-cal/model_pf.py         # model vs the classic editor
python tools/check_photo_filter.py          # operator vs the classic editor (end to end)
python tools/check_xyz_multiply.py --all    # operator vs an independent reference
