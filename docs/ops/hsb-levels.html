HSB Levels

lb:hsb-levels 色阶家族 整块区域

HSB（=HSV）三个分量各自设输入 / 输出黑白场与伽马

菜单：SuperMrWang → Levels → HSB Levels（Filter 类）

概述

对 HSB（即 HSV，取色器上那三个数）的 H / S / B 各自做独立色阶。和 HSL Levels 长得很像，但 S 和 B 是另一套量，同一个滑块值在两个算子里手感不同，别混着用。

色彩空间

工作在 babl 的 HSVA float 上，RGB↔HSV 交给 babl。

分量量程定义
H0–360°与 HSL 同一个色相角
S0–100%S = (max−min)/max = 1 − min/V（HSV 的 S）
B0–100%B = V = max(R,G,B)，即最亮的那个通道

HSL 的 S 是 (max−min)/(1−|2L−1|)，HSV 的 S 是 (max−min)/max——同一块颜色两边的数值可以差很多（比如纯红：HSL 的 S=100%，HSV 的 S 也是 100%，但浅粉色 HSL 的 S=100% 时 HSV 只有约 20%）。所以「把 S 压到 60%」这两个算子给出的画面完全不同。

$$z = (h-\text{ia}) \bmod 360,\qquad S_{\text{in}} = (\text{ib}-\text{ia}) \bmod 360,\qquad S_{\text{out}} = (\text{ob}-\text{oa}) \bmod 360$$
$$h' = \bigl(\text{base} + \text{span}\cdot t^{1/\gamma}\bigr) \bmod 360,\qquad (t,\ \text{base},\ \text{span}) = \begin{cases} \left(\dfrac{z}{S_{\text{in}}},\ \text{oa},\ S_{\text{out}}\right), & z \le S_{\text{in}} \\[10pt] \left(\dfrac{z-S_{\text{in}}}{360-S_{\text{in}}},\ \text{oa}+S_{\text{out}},\ 360-S_{\text{out}}\right), & z > S_{\text{in}} \end{cases}$$

$S_{\text{in}}$ 或 $S_{\text{out}}$ 为 0（黑白场重合）时按整圈 $360°$ 处理。

$$u = \operatorname{clamp}\!\left(\frac{x-x_{\text{lo}}}{x_{\text{hi}}-x_{\text{lo}}},\,0,\,1\right), \qquad \text{out} = o_{\text{lo}} + u^{1/\gamma}\,\bigl(o_{\text{hi}}-o_{\text{lo}}\bigr)$$

$o_{\text{lo}} > o_{\text{hi}}$ 时输出反相；结果夹在 $[\min(o_{\text{lo}},o_{\text{hi}}),\ \max(o_{\text{lo}},o_{\text{hi}})]$ 内。

规则细则

  • H 环形重映射：主弧（黑场 → 白场）映到输出弧，剩余弧按比例跟进， 两段共用 gamma；整圈连续，默认参数逐位还原。黑白场重合按整圈处理 = 纯色相旋转。
  • S/B 线性：clamp → 归一化 → gamma → 输出范围，输出反向即反相。
  • 黑白场交叉自动交换。
  • alpha ≤ 0 透传。
  • B 归零 = 全黑（V 是最大通道，压到 0 三通道全 0）；B 的反向输出会得到 「亮部变暗、暗部变亮」的负片式结果，但色相与饱和度仍保留各自的映射。

与 lb:hsl-levels 的选择

  • 只想改「颜色有多艳」而不动亮度 → 两者都行，但 HSL 的 S 与感知饱和度更 接近，HSV 的 S 在暗部会虚高（暗红 S 也是 100%）。
  • 要单独控制「最亮通道」→ 用 HSB 的 B，它等于 max，压 B 就是压高光上限。
  • 要按「中间调亮度」调 → 用 HSL 的 L 或 lab-levels 的 L。

验证

python tools/check_color_levels.py hsb（3 项）：

用例判据实测
恒等（默认参数）与源图逐像素 ≤1 码最大 0
饱和度归零全图中性（|R−G|、|G−B| ≤2）0

公式对拍的参数：H 整体 +40°（0/360 → 40/40 的整圈旋转）、S 15/100 → 0/100 γ=1.2、B 0/100 → 10/90，覆盖色相环绕与两段 gamma 方向。

已知事项

  • 黑（B=0）像素的 S 与 H 都没有定义，算子按 0 处理；B 抬起来之后颜色仍是 黑的（V 决定亮度上限）。
  • 8 位精度下 B 很低的深色区只有几个量化台阶，B 曲线拉陡会出现断层。

只要这一个

Windows 模块 hsb-levels.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 hsb-levels.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

HSB Levels

lb:hsb-levels Levels area

Levels on H, S and B (the numbers your colour picker shows) — nearly identical to HSL Levels, but S and V are different quantities.

Menu: Colors → SuperMrWang → Tone → HSB Levels (a filter op)

Overview

Independent levels for HSB (that is, HSV — the three numbers on a colour picker): H, S and B. It looks a lot like HSL Levels, but S and B are different quantities, so the same slider value feels different in the two operators. Do not mix them up.

Colour space

The operator works on babl's HSVA float; RGB↔HSV is babl's job.

ComponentRangeDefinition
H0–360°the same hue angle as HSL
S0–100%S = (max−min)/max = 1 − min/V (HSV's S)
B0–100%B = V = max(R,G,B), the brightest channel

HSL's S is (max−min)/(1−|2L−1|), HSV's is (max−min)/max — the same colour can sit at very different numbers on the two scales (light pink is HSL S=100% but HSV S≈20%). So "push S down to 60%" gives visibly different pictures in the two operators.

$$z = (h-\text{ia}) \bmod 360,\qquad S_{\text{in}} = (\text{ib}-\text{ia}) \bmod 360,\qquad S_{\text{out}} = (\text{ob}-\text{oa}) \bmod 360$$
$$h' = \bigl(\text{base} + \text{span}\cdot t^{1/\gamma}\bigr) \bmod 360,\qquad (t,\ \text{base},\ \text{span}) = \begin{cases} \left(\dfrac{z}{S_{\text{in}}},\ \text{oa},\ S_{\text{out}}\right), & z \le S_{\text{in}} \\[10pt] \left(\dfrac{z-S_{\text{in}}}{360-S_{\text{in}}},\ \text{oa}+S_{\text{out}},\ 360-S_{\text{out}}\right), & z > S_{\text{in}} \end{cases}$$

A zero $S_{\text{in}}$ or $S_{\text{out}}$ (coincident black / white points) is treated as the full $360°$ circle.

$$u = \operatorname{clamp}\!\left(\frac{x-x_{\text{lo}}}{x_{\text{hi}}-x_{\text{lo}}},\,0,\,1\right), \qquad \text{out} = o_{\text{lo}} + u^{1/\gamma}\,\bigl(o_{\text{hi}}-o_{\text{lo}}\bigr)$$

An inverted output ($o_{\text{lo}} > o_{\text{hi}}$) gives a negative-style inverse; the result is clamped to $[\min(o_{\text{lo}},o_{\text{hi}}),\ \max(o_{\text{lo}},o_{\text{hi}})]$.

Rules

  • Circular hue remap: the main arc (black point → white point) maps onto the output arc, the rest follows proportionally, both sharing the gamma; continuous around the circle, bit-exact at defaults. Black and white point at the same angle means the whole circle, i.e. a pure hue rotation.
  • S and B are linear: clamp → normalise → gamma → output range; an inverted output is an inverse.
  • Crossed black and white points swap automatically.
  • alpha ≤ 0 passes through.
  • B to zero is pure black (V is the max channel, so 0 means all three are 0). An inverted B output gives a negative-style "bright goes dark, dark goes bright" result while hue and saturation keep their own mappings.

Choosing between this and lb:hsl-levels

  • Only want "how saturated" without touching brightness → either will do, but HSL's S is closer to perceived saturation; HSV's S runs high in the shadows (a dark red is still S=100%).
  • Want to control "the brightest channel" directly → use HSB's B, which is exactly max; pulling B down caps the highlights.
  • Want to work on "midtone lightness" → use HSL's L or lab-levels' L.

Verification

Replay parameters: H +40° overall (a full rotation from 0/360 to 40/40), S 15/100 → 0/100 with γ=1.2, B 0/100 → 10/90, covering hue wrapping and both gamma directions.

Known issues

  • Black pixels (B=0) have no defined S or H; the operator treats them as 0, and raising B keeps them black (V decides the brightness ceiling).
  • At 8-bit precision a very dark colour has only a few quantisation steps, so a steep B curve shows banding.
