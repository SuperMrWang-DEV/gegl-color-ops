它补的是「通道分解 → 灰度 → 重新编码 → 混合模式还原」这条三步流程中间缺的一环。 现在每个色彩模式都有自己的分量色阶，直接在原图上按分量调，一步到位： lb:hsl-levels、lb:hsb-levels、lb:lch-levels、lb:cmyk-levels、lb:hsi-levels。

停用标记在 ops/gray-to-component/.disabled（含废弃原因）；要临时恢复编译就删掉 这个文件再 ./build.sh。下面的公式与实测结论对旧工程文件仍有参考价值。

通道灰度调色工作流里的编码器：把分解出来的分量灰度层，重新编码成 「携带该分量」的彩色层，交给 GIMP 的分量混合模式读回去。

原图 ──分解──> 分量灰度层（H / S / L / C …）
                    │
                    ▼
            lb:gray-to-component   ← 本算子：灰度 → 该分量的彩色表示
                    │
                    ▼
        混合模式还原（GIMP「颜色」组 9 个模式 + Lighten 叠合）

为什么需要这一步：灰度像素的色相和饱和度是无定义的。把分解出的 H 灰度层 直接设成「色相」混合模式毫无效果——混合模式从灰里读不出色相。必须先把它编 码成色环上的真实颜色，混合模式才有东西可读。GIMP 的分解和混合模式都是现成 的，唯独中间这一步没有，本算子补的就是这一环。

模式表（编码公式经 hsl-cal 恒等往返实测校准）

GIMP 3 把分量类混合模式集中在「颜色」组，共 9 个：Hue / Saturation / Color / Value / LCh Hue / LCh Chroma / LCh Color / LCh Lightness / Luminance。本算子 每个都能喂，另外多给三个 RGB 单通道模式。

模式灰度 g 的语义输出编码配哪个混合模式还原
hueHSL 色相 h/360hsl_to_rgb(g·360°, S=1, L=0.5)，饱和度亮度拉满的色相轮Hue（HSV_HUE）
saturationHSV 饱和度 shsv_to_rgb(sat_hue, s, V=1)，默认红相Saturation（HSV_SATURATION）
colorHSL 色相 h/360hsl_to_rgb(g·360°, color_sat, L=0.5)，饱和度由参数固定Color（HSL_COLOR）
valueHSV 明度 V(g,g,g) 中性灰（V 就是最大通道）Value（HSV_VALUE）
lightnessCIE 明度 L/100Lab(g·100, 0, 0) 直写LCh Lightness（LCH_LIGHTNESS）
luminance同上（CIE 亮度 Y）与 lightness 逐字节相同Luminance（LUMINANCE）
red / green / blue该通道值(g,0,0) / (0,g,0) / (0,0,g)Lighten 三层叠合
lch-hueCIE 色相 h/360Lab(lch_l, C·cos h, C·sin h)，C = lch_cLCh Hue（LCH_HUE）
lch-color同上（h，C 由参数固定）与 lch-hue 逐字节相同LCh Color（LCH_COLOR）
lch-chromaCIE 色度 C/chroma_scaleLab(lch_l, C·cos h₀, C·sin h₀)，h₀ = lch_hLCh Chroma（LCH_CHROMA）

两组「同编码」不是偷懒，是混合模式的语义决定的：

  • luminance ≡ lightness：Luminance 读 CIE 亮度 Y，中性灰的 Lab L 与 Y 单调对应，同一份 Lab(L,0,0) 同时给出正确的 L 和 Y。
  • lch-color ≡ lch-hue：LCh Color 只读色相 + 色度，而 lch-hue 的色度 本来就由 lch-c 固定住了。单列一条纯粹是让人按 GIMP 的模式名对号入座。

Color 的单通道困境：Color 模式要同时读色相和饱和度，可一层灰度只有一个 标量。本算子的取舍是「灰度携带色相，饱和度由 color-sat 给定」——想整幅换色 同时压饱和度，就把 color-sat 调到 45%，比先 hue 再叠一层降饱和简单。

三个校准出来的硬结论（hsl-cal 实测，误差按 0–255 计）：

  1. HSL 的 S ≠ HSV 的 S。GIMP 的 Saturation 模式读的是 HSV 语义，拿 HSL 分解 出的 S 层直接编码，误差高达 214/255。本算子的 saturation 模式按 HSV 语义 编码，恒等往返误差 <2。
  2. HSL 色相与 CIE 色相不可线性互转。把 h·360 直接当 LCh 色相用，误差 139/255。两套色轮必须各自分解、各自编码——这就是 hue 和 lch-hue 两个 模式不能合并的原因。
  3. 编码层要工作在 float32。8-bit 图像下 Lab/LCh 编码写入图层会被量化， 色相/色度被打碎（这也是普通 8-bit 图上这套流程精度有限的固有原因）； float32 下连超出 sRGB 色域的 LCh 值都能原样往返。

参数

参数默认说明
modehue见上表
sat-hue0（红）saturation 模式用的色相。该层只提供饱和度，色相在还原时不进入结果，取值不影响最终画面
color-sat100color 模式固定的饱和度百分比。100% 时输出与 hue 相同；调低即「换色 + 降饱和」
lch-l54LCh 模式用的固定明度。混合模式只读色相/色度时此值不进结果，取中庸值以留在常见色域内
lch-c30lch-hue / lch-color 用的固定色度。越大越鲜艳，过大可能超出 sRGB 色域
lch-h30lch-chroma 模式用的固定色相角（0=红），同样不进结果
chroma-scale100lch-chroma 的满量程（灰度 1.0 对应多少色度）。sRGB 的蓝/品红 C 可达 ~130，需要覆盖宽色域时调大，但必须与分解侧一致

典型用法

换色相（保留明暗和饱和度）：

  1. 原图复制一层 → lb:gray-to-component 选 hue，输入是「色相」分解出的灰度层；
  2. 该层混合模式设 Hue；
  3. 在灰度层上做色阶/曲线/反相——色相就跟着转，褶皱阴影全在。

只调饱和度：同上，saturation 模式 + Saturation 混合模式。

换色同时压饱和：color 模式 + Color 混合模式，color-sat 设 40–60%。 一层就把色相和饱和度一起换掉，明度还是原图的。

只要 HSV 明度：value 模式 + Value 混合模式——输出中性灰，Value 读的 就是最大通道，曲线拖灰度直接改明度。

Lab 空间调色（不碰明度）：lch-chroma + LCh Chroma，拖灰度的曲线只改 鲜艳度；lch-hue + LCh Hue 只转色相；lch-color + LCh Color 则把色度 一并钉在 lch-c 上。

RGB 单通道重组：三个 red/green/blue 模式各编码一层，混合模式都用 Lighten 自下而上叠——max((r,0,0),(0,g,0),(0,0,b)) 正好还原 (r,g,b)。

验收

tools/check_gray_to_component.py（39 项，gimp-console 跑）：

  • A. 编码公式：17 级灰度斜坡喂算子，Lab 域模式（含 luminance / lch-color 两个别名）直读 Lab 输出对拍；RGB 域模式读回 RGB 与镜像的 HSL/HSV 公式对拍， color-sat 跑 100 / 40 两档、sat-hue 跑 0 / 210 两档确认参数真的进了公式； 含端点语义（hue 0=红 / 0.5=青）、value（0=黑 / 1=白 / 中性）、color-sat=0 退化成灰、两组别名输出逐分量相同。
  • B. 恒等往返（金标准，与 hsl-cal 同一方法）：24 个探针色做分解 → 编码 → 混合还原，逐像素比对原图，全部 ≤2/255：hue→Hue、saturation→Saturation、 value→Value、lightness→LCh Lightness、luminance→Luminance、lch-hue→LCh Hue、 lch-chroma→LCh Chroma（量程 100 / 132 两档）、RGB 三通道→Lighten 叠合、 hue+saturation 串联。Color / LCh Color 是双分量模式，恒等条件要求底层 饱和度 / 色度与参数一致，所以各配一套专用探针：Color 用 S=100% 与 S=60% 两组色环，LCh Color 用 C=30 的 LCh 圆环。
  • 透明像素：32×8 棋盘（85/256 全透明）逐像素比对 alpha，透明处 Lab 必须为 0。

技术备注

  • 输出格式钉成 CIE Lab alpha float：Lab/LCh 模式零转换直写（a=C·cos h、 b=C·sin h 就是 CIE LCh 的定义式）；HSL/RGB 模式用 babl_fish 把整行转 Lab， 与 GIMP 内部转换同源，不引入自实现转换的漂移。
  • RGB 域模式的透明像素必须在 rgb_line 里落位：整行交给 babl_process 时 它会重写 out_line 的每一个像素，只在 out_line 里写 0 会被中间行（未初始化） 覆盖，导致透明像素的 alpha 变成随机值。早先 2×1 的小用例靠堆内存恰好为 0 蒙过去了，换成 32×8 棋盘才暴露——现已修正。
  • 无 aux pad，可直接作为 GIMP 3 非破坏滤镜挂在灰度图层上（不受 Gimp.DrawableFilter 拒收 aux 算子的限制），整条工作流全程非破坏。
  • 透明像素（alpha≤0）输出保持透明。
  • 输入 YA float：分解出的灰度层是 RGBA 时由 babl 自动转成 CIE 亮度。

lb:gray-to-component Blend area 已废弃Retired

Retired — no longer built or shipped; this page is an archive. Every colour model now has its own component levels, so the old decompose → colour-encode → blend-mode route is obsolete.

Retired. The encoder in the "decompose → grey → re-encode → blend-mode" workflow; component levels now do the job in one step.

Retired (2026-11-15). This operator is no longer compiled or shipped; this page is an archive.

It filled the missing link in the three-step "channel decompose → grey → re-encode → blend mode" workflow. Every colour model now has its own component levels, so you adjust components directly on the original image in one step: lb:hsl-levels, lb:hsb-levels, lb:lch-levels, lb:cmyk-levels, lb:hsi-levels.

The disable marker is ops/gray-to-component/.disabled (with the reason); delete it and run ./build.sh to build it temporarily. The formulas and measurements below are still useful for old project files.

The encoder of the channel-grey grading workflow: take a decomposed component grey layer and re-encode it into a colour layer "carrying" that component, so GIMP's component blend modes can read it back.

image ──decompose──> component grey layer (H / S / L / C …)
                          │
                          ▼
                  lb:gray-to-component   <- this operator: grey -> colour form
                          │
                          ▼
        restore with a blend mode (GIMP's nine "Color" group modes + Lighten)

Why the step is needed: a grey pixel has no defined hue or saturation. Putting a decomposed H grey layer into Hue blend mode does nothing — the mode cannot read a hue out of grey. It first has to be encoded into a real colour on the wheel. GIMP has the decomposition and the blend modes; the middle step was missing, and this operator was it.

Mode table (encoding formulas calibrated by identity round trips in hsl-cal)

GIMP 3 collects component blend modes in the "Color" group, nine of them: Hue / Saturation / Color / Value / LCh Hue / LCh Chroma / LCh Color / LCh Lightness / Luminance. This operator feeds each of them, plus three single-channel RGB modes.

ModeMeaning of grey gOutput encodingBlend mode to restore
hueHSL hue h/360hsl_to_rgb(g·360°, S=1, L=0.5), a hue wheel at full saturation and mid lightnessHue (HSV_HUE)
saturationHSV saturation shsv_to_rgb(sat_hue, s, V=1), red hue by defaultSaturation (HSV_SATURATION)
colorHSL hue h/360hsl_to_rgb(g·360°, color_sat, L=0.5), saturation fixed by a parameterColor (HSL_COLOR)
valueHSV value V(g,g,g) neutral grey (V is the max channel)Value (HSV_VALUE)
lightnessCIE lightness L/100Lab(g·100, 0, 0) written directlyLCh Lightness (LCH_LIGHTNESS)
luminancesame (CIE luminance Y)byte-identical to lightnessLuminance (LUMINANCE)

lch-colorsame (h, C fixed by parameter)byte-identical to lch-hueLCh Color (LCH_COLOR)
lch-chromaCIE chroma C/chroma_scaleLab(lch_l, C·cos h₀, C·sin h₀), h₀ = lch_hLCh Chroma (LCH_CHROMA)

The two "same encoding" pairs are not laziness, they follow from what the blend modes read:

  • luminance ≡ lightness: Luminance reads CIE Y, and a neutral grey's Lab L maps monotonically to Y, so one Lab(L,0,0) gives both correctly.
  • lch-color ≡ lch-hue: LCh Color reads hue and chroma only, and lch-hue's chroma is already fixed by lch-c. The separate entry exists so you can match GIMP's mode names.

The single-channel problem with Color: Color mode reads hue and saturation together, but one grey layer holds a single scalar. The trade-off here is "grey carries hue, saturation comes from color-sat" — to recolour and desaturate at once, set color-sat to 45%, simpler than hue first and a desaturating layer on top.

Three hard, calibrated conclusions (measured in hsl-cal, error in 0–255):

  1. HSL's S ≠ HSV's S. GIMP's Saturation mode reads HSV semantics; encoding an HSL S layer directly is off by up to 214/255. This operator's saturation mode encodes with HSV semantics, and the identity round trip is < 2.
  2. HSL hue and CIE hue do not convert linearly. Using h·360 directly as an LCh hue is off by 139/255. The two wheels must be decomposed and encoded separately — which is why hue and lch-hue cannot be merged.
  3. The encoding layer must run at float32. In 8-bit, Lab/LCh encodings written into the layer get quantised and hue/chroma break up (an inherent precision limit of the whole workflow on 8-bit images); at float32 even LCh values outside sRGB round trip exactly.

ParameterDefaultNotes

Typical uses

Rotate hue (keeping tone and saturation):

  1. Duplicate the layer → lb:gray-to-component with mode hue, fed by the hue decomposition;
  2. set that layer's blend mode to Hue;
  3. run levels/curves/invert on the grey layer — the hue follows, and every fold and shadow stays.

Saturation only: same, mode saturation with Saturation.

Recolour and desaturate at once: mode color with Color, color-sat at 40–60%. One layer swaps hue and saturation together; lightness stays the original's.

HSV value only: mode value with Value — the output is neutral grey, Value reads the max channel, and a curve on the grey edits brightness directly.

Lab-space grading (lightness untouched): lch-chroma + LCh Chroma changes vividness only; lch-hue + LCh Hue rotates hue only; lch-color + LCh Color pins chroma to lch-c as well.

RGB channel recomposition: one layer each of red/green/blue, all in Lighten, stacked bottom-up — max((r,0,0),(0,g,0),(0,0,b)) restores exactly (r,g,b).

Verification

tools/check_gray_to_component.py (39 cases, run in gimp-console):

  • A. Encoding formulas: a 17-step grey ramp through the operator; Lab-domain modes (including the luminance / lch-color aliases) compared against the Lab output directly, RGB-domain modes against mirrored HSL/HSV formulas with color-sat at 100 and 40 and sat-hue at 0 and 210, confirming the parameters really reach the maths, plus endpoint semantics (hue 0 = red / 0.5 = cyan), value (0 = black / 1 = white / neutral), color-sat=0 degenerating to grey, and both alias pairs agreeing component-wise.
  • B. Identity round trips (the gold standard, same method as hsl-cal): 24 probe colours through decompose → encode → blend, compared per pixel with the original, all ≤ 2/255: hue→Hue, saturation→Saturation, value→Value, lightness→LCh Lightness, luminance→Luminance, lch-hue→LCh Hue, lch-chroma→LCh Chroma (ranges 100 and 132), the three RGB channels→Lighten, and hue+saturation in series. Color / LCh Color are two-component modes whose identity needs the underlying saturation/chroma to match the parameters, so each gets dedicated probes: Color with S=100% and S=60% rings, LCh Color with a C=30 LCh ring.
  • Transparent pixels: a 32×8 checkerboard (85/256 fully transparent), alpha compared per pixel; transparent areas must be Lab 0.

Technical notes

  • The output format is pinned to CIE Lab alpha float: the Lab/LCh modes write straight through with zero conversion (a=C·cos h, b=C·sin h is the definition of CIE LCh), while the HSL/RGB modes use babl_fish to convert each row to Lab, the same conversion GIMP uses internally, so no hand-written conversion drift creeps in.
  • Transparent pixels in the RGB-domain modes must be placed in rgb_line: handing a whole row to babl_process rewrites every pixel of out_line, so writing 0 only into out_line got overwritten by the intermediate row (uninitialised), leaving random alpha on transparent pixels. An earlier 2×1 case passed only because the heap happened to be zero; a 32×8 checkerboard exposed it. Fixed.
  • No aux pad, so it can sit on a grey layer as a GIMP 3 non-destructive filter (it is not blocked by Gimp.DrawableFilter's refusal of aux operators), making the whole workflow non-destructive.
  • Transparent pixels (alpha ≤ 0) stay transparent.
  • Input YA float: an RGBA grey layer is converted to CIE luminance by babl automatically.

Retired — no download

This operator is no longer compiled or shipped. For per-channel grading use the HSL, HSB, LCh, CMYK and HSI levels instead — one step, no decompose-then-encode round trip. The source stays in ops/gray-to-component/; the reason is in the .disabled file there.
