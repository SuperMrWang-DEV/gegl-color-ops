LCh Dual Extract

lb:lch-dual 分量 整块区域

LCh 分量曲线工作流的提取器：把一张图拆成「R = 明度 L、G = 彩度 C、B = 色相/360」的数据图，一张图同时携带三个分量

把一张图打包成一张数据图：R = 明度 L*/100、G = 彩度 C*/140、 B = 色相/360，全部 0…1。alpha 恒为 1。

原图 ──lb:lch-dual──> (R=L/100, G=C/140, B=h/360)
                          │
                 ┌────────┼────────┐
              L(红)     C(绿)    h(蓝)
                 └────────┼────────┘
                          ▼
                    lb:lch-compose  ──> 真实颜色

为什么是极坐标

Lab 的 a、b 是直角坐标：C² = a² + b²、h = atan2(b, a)。一条一维曲线改 a，彩度和色相都跟着变——画面上看就是「整体偏色」。想「只加彩度」「只转色相」，就得先在极坐标里表达，那正是本算子做的事。

转成 (L, C, h) 之后，三条曲线各自独立，再由 lb:lch-compose 一起算回颜色。 LCh Split (Curves) 的旧版用三张分量层 + 三个 LCh 混合模式，还要把分量值编码成「混合模式读得出来的颜色」（色相层得造等 L、等 C 的色相圆）；一层写法把这些全部省掉。

量程（实测标定，babl D50）

分量babl 单位数据图
L*0…100L/100
C*0…约 133.8（sRGB 全色域）C/140
h0…360°h/360

彩度取 140 而不是 135：sRGB 最饱和的点是纯蓝，C*≈133.8，留一点余量让整圈都装得下。8 位图上 1 码 ≈ 0.55 个 C* 单位，往返量化误差仍在 0.5 码内。

实测

tools/check_lch_split.py 里 dual → compose 恒等往返：32 位浮点 0.0005 码， 8 位 0.49 码。中性灰（C=0）的色相在 babl 侧无定义，算子把非有限值折成 0。

注意

  • 输出是数据图，不要直接看它当照片。
  • 它和 lb:lch-compose 配对使用，量程必须一致（改一边就要改另一边）。

只要这一个

Windows 模块 lch-dual.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 lch-dual.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

LCh Dual Extract

lb:lch-dual Component area

Packs lightness, chroma and hue into one data image in polar form — so a curve can add chroma or rotate hue without dragging the other two along.

Menu: Colors → SuperMrWang → Component → LCh Dual Extract (a filter op)

Overview

Packs an image into one data image: R = lightness L*/100, G = chroma C*/140, B = hue/360, all 0…1. Alpha is always 1.

input ── lb:lch-dual ──> (R=L/100, G=C/140, B=h/360)
            │
            ├── L curve (red)
            ├── C curve (green)
            ├── h curve (blue)
            ▼
     lb:lch-compose ──> real colour

Why polar coordinates

Lab's a and b are rectangular: C² = a² + b², h = atan2(b, a). A 1D curve on a changes chroma and hue together — on screen that reads as a cast. "Add chroma only" or "rotate hue only" has to be expressed in polar form first, which is what this operator does.

Once the image is (L, C, h), the three curves are independent and lb:lch-compose computes the colour back. The old LCh Split (Curves) used three component layers and three LCh blend modes, and had to encode each component as a colour the blend mode could read (the hue layer needed a ring of constant L* and C*) — a single-layer pipeline drops all of that.

Ranges (measured, babl D50)

Componentbabl unitsData image
L*0…100L/100
C*0…about 133.8 (full sRGB gamut)C/140
h0…360°h/360

Chroma is divided by 140 rather than 135: the most saturated sRGB point is pure blue at C*≈133.8, and the extra headroom lets the whole circle fit. In 8-bit one code is about 0.55 C* units, so the round-trip quantisation stays within 0.5 codes.

Verification

tools/check_lch_split.py runs the dual → compose identity round trip: 0.0005 codes in 32-bit float, 0.49 codes in 8-bit. Neutral grey (C = 0) has no defined hue on the babl side; the operator folds non-finite values to 0.

Notes

  • The output is a data image — do not read it as a photo.
  • It only works paired with lb:lch-compose, and the two must share the same ranges — change one and you have to change the other.

Just this one

Windows module lch-dual.dll, drop it into %LOCALAPPDATA%\gegl-0.4\plug-ins; Linux module lch-dual.so, drop it into ~/.local/share/gegl-0.4/plug-ins, then restart GIMP. Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs. The full bundle is on the download page.
