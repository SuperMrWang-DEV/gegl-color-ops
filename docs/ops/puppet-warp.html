Puppet Warp (live)

lb:puppet-warp 扭曲 整块区域

木偶变形的非破坏版本：把钉子串挂在滤镜栈上，改参数只是让这条滤镜重算，原像素不动。对话框（Python 插件）拖完钉子点应用时写的也是这里的 pins 串，重跑对话框会从滤镜里把钉子读回来。

把 plugin/puppet-warp 那套解算（MLS 相似 / MLS 仿射 / ARAP）搬进 C，做成一条挂在图层上的实时滤镜：钉子串存在滤镜上，原像素一个字节都不动。

图层 ──▶ ┌──────────────────────────┐ ──▶ 画布
         │ lb:puppet-warp（滤镜栈里）│      钉子 / 模式 / 影响半径
         └──────────────────────────┘      都是这条滤镜的属性

点应用只是把 pins 写进滤镜 config，重算一遍；再跑一次对话框会把钉子读回来，接着拖。存成 XCF 再打开，钉子还在，随时能改、能临时关掉。

菜单：SuperMrWang → Distort → Puppet Warp (live)…。同一子菜单里还有 Python 版那个破坏性的「木偶变形」，两版并存：要能回改参数用这一条，要直接烤进像素用那一条（对话框里选「覆盖当前图层」也一样）。

属性

属性说明
pinssx,sy,dx,dy; …：钉子放下的位置 → 拖到的位置，图层像素坐标
modesimilarity（保形）/ affine（放开拉伸）/ arap（大弯折最准）
radius影响半径，长边的百分比；圈外严格恒等。ARAP 不用它（全局弱锚定）

为什么是 C

非破坏只认 GEGL 算子（Gimp.DrawableFilter.new），Python 插件只能读写像素。 MLS 是逐像素闭式解，天生 tile 安全；ARAP 在 48 节点网格上用带状 LDL 解，分解一次、12 轮迭代复用，反向场用「钉子原位/现位互换」再解一遍——和 Python 版同一套公式，回归逐像素对拍（check_warp.py / _pw_probe.py）。

两个坑

  • 场要缓存，但不能直接 free。 GEGL 的 process 会被多线程按 tile 调， 三态槽（FREE / RESERVED / READY）+ LRU 才安全，否则正在用的数组被别人释放。
  • CLI 传参是 pins=值，不是 --pins=值，而且值里不能有空格（GEGL 按空格拆）。 写错不会报错，只会拿到一张原图——对拍脚本一开始就是这么假通过的。

只要这一个

Windows 模块 puppet-warp.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

Puppet Warp (live)

lb:puppet-warp Distort area

The puppet-warp solver (MLS similarity, MLS affine, ARAP) as a live GEGL filter on the layer — the pin list lives on the filter stack, not in the pixels.

The solver behind plugin/puppet-warp (MLS similarity / MLS affine / ARAP) moved into C and attached to the layer as a real-time filter: the pin list is stored on the filter, and not a single pixel of the layer is written.

layer ──▶ ┌──────────────────────────┐ ──▶ canvas
          │ lb:puppet-warp (filter)  │      pins / mode / radius
          └──────────────────────────┘      are the filter's properties

Pressing Apply only writes pins into the filter config and re-renders; running the dialog again reads the pins back so you can keep dragging. Save as XCF, reopen, the pins are still there — editable, and switchable off at any time.

Menu: SuperMrWang → Distort → Puppet Warp (live)…. The destructive Python version sits in the same submenu; both stay available — use this one if you want the settings back, the other one (or “Replace this layer” in this dialog) to bake the result into pixels.

Properties

PropertyMeaning
pinssx,sy,dx,dy; …: where a pin was placed → where it was dragged, in layer pixels
modesimilarity (shape-preserving) / affine (stretch allowed) / arap (best for large bends)
radiusfalloff radius as a percentage of the long side; strictly identity outside it. ARAP ignores it (global weak anchoring)

Why C

Non-destructive editing only exists for GEGL ops (Gimp.DrawableFilter.new); a Python plug-in can only read and write pixels. MLS is a per-pixel closed form and inherently tile-safe. ARAP solves a 48-node grid with a banded LDL: factor once, reuse over 12 iterations, and solve again for the reverse field with the pins' original and current positions swapped — the same formulas as the Python version, checked pixel by pixel in the regression (check_warp.py / _pw_probe.py).

Two traps

  • The field has to be cached, but never freed directly. GEGL calls process per tile from several threads; a three-state slot (FREE / RESERVED / READY) plus LRU is what keeps another thread from releasing an array still in use.
  • The CLI takes pins=value, not --pins=value, and the value cannot contain spaces (GEGL splits on whitespace). A wrong form does not error — it just hands back the original image, which is exactly how the comparison script first passed with everything wrong.

Just this one

Windows module puppet-warp.dll, drop it into %LOCALAPPDATA%\gegl-0.4\plug-ins, then restart GIMP. Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs. The full bundle is on the download page.
