HSI Dual Extract

lb:hsi-dual 分量 整块区域

HSI 分量曲线工作流的提取器：把一张图拆成「R = 饱和度、G = 强度、B = 色相/360」的数据图，一张图同时携带三个分量

把一张图打包成一张数据图：R = 饱和度、G = 强度、B = 色相/360，全部 0…1。 alpha 恒为 1。

原图 ──lb:hsi-dual──> (R=S, G=I, B=H/360)
                          │
              ┌───────────┼───────────┐
          S 曲线(红)   I 曲线(绿)   H 曲线(蓝)
              └───────────┼───────────┘
                          ▼
                    lb:hsi-compose  ──> 真实颜色

为什么三个分量挤在一张图里

HSI 的定义与 GIMP 现成的分量混合模式一个都对不上：

I = (R+G+B)/3          HSV 的 V = max        ✗
S = 1 − min/I          HSL 的 S ≠            ✗
H = 余弦定义的角度      HSV 的参数角          ✗ 最多差 1.117°

色相那一条尤其容易被忽略：HSI 的色相角是

cos H = [(R−G) + (R−B)] / (2·√((R−G)² + (R−B)(G−B)))

它量的是色度矢量在等亮度平面里的真实夹角；HSV 的色相是六边形投影上的参数角。两者只在 0°/30°/60°… 重合，15°、45°、75°… 处各偏 ±1.08°。

所以就算把色相层接到「HSV 色相」模式上，也有两个问题：角度不是同一个（差 1°，饱和色上折算几个码值），而且那个模式保留的是 HSV 的 S/V，HSI 的 S、I 会被带走——实测换一条色相曲线，I 偏 0.085（约 22 码）。于是三个分量只能联合算，一层搞定。

输入输出

格式含义
inputR'G'B'A float滤镜栈的编码域缓冲
outputR'G'B'A float数值是数据不是颜色：0.85 / 0.45 / 0.583 = S 85%、I 45%、色相 210°

转换用的是本仓库 common/color-levels.h 里那一套，与 lb:hsi-levels 同一份代码： I = (R+G+B)/3、S = 1 − min/I、色相按余弦式。

alpha 恒写 1：分量层必须不透明，透明度交给组蒙版。

实测

tools/check_hsi_split.py 里 dual → compose 恒等往返：32 位浮点图 0.0001 码， 8 位图 0.499 码（只剩量化）。改任一条曲线后，结果落在「只有那个分量变了」的 HSI 点上：S、I 误差 < 0.0001，色相角误差 0.0013°。

注意

  • 输出是数据图，不要直接看它当照片。
  • 它和 lb:hsi-compose 是配对使用的。只装一个没有意义。
  • HSI 的色域是六边形棱锥，不是立方体：S、I 推到极端时逆变换会出 sRGB 色域， 出界部分由 compose 裁掉。

只要这一个

Windows 模块 hsi-dual.dll，放进 %LOCALAPPDATA%\gegl-0.4\plug-ins；Linux 模块 hsi-dual.so，放进 ~/.local/share/gegl-0.4/plug-ins，然后重启 GIMP。这里的每个模块都是独立的 GEGL 模块，只链接 GIMP 自带的 GEGL 与 babl，不依赖本项目里的其它模块——下这一个就够用，不会缺东西。要一次装齐，用整包。

HSI Triple Extract

lb:hsi-dual Component area

Packs HSI saturation, intensity and hue into one data image — HSI matches none of GIMP's component blend modes, so all three have to be computed together.

Menu: Colors → SuperMrWang → Component → HSI Triple Extract (a filter op)

Overview

Packs an image into one data image: R = saturation, G = intensity, B = hue/360, all 0…1. Alpha is always 1.

input ── lb:hsi-dual ──> (R=S, G=I, B=H/360)
            │
            ├── S curve (red)
            ├── I curve (green)
            ├── H curve (blue)
            ▼
     lb:hsi-compose ──> real colour

Why all three share one image

HSI's definition matches none of GIMP's ready-made component blend modes:

I = (R+G+B)/3          HSV's V = max        ✗
S = 1 − min/I          HSL's S differs      ✗
H = angle from a cosine HSV's parametric    ✗ off by up to 1.117°

Hue is the part that is easy to miss. HSI's hue angle is

cos H = [(R−G) + (R−B)] / (2·√((R−G)² + (R−B)(G−B)))

which measures the true angle of the chroma vector inside the constant-luminance plane; HSV's hue is a parametric angle on a hexagonal projection. The two agree only at 0°/30°/60°… and are off by ±1.08° at 15°, 45°, 75°…

So even wiring the hue layer to "HSV hue" mode has two problems: the angles are not the same (about 1°, a few codes on saturated colours), and that mode preserves HSV's S and V, dragging HSI's S and I along — measured, a single hue curve moves I by 0.085 (about 22 codes). All three components therefore have to be computed jointly, in one layer.

Input and output

FormatMeaning
inputR'G'B'A floatthe filter stack's encoding-domain buffer
outputR'G'B'A floatthe numbers are data, not colour: 0.85 / 0.45 / 0.583 = S 85%, I 45%, hue 210°

The conversion uses the code in this repository's common/color-levels.h, shared with lb:hsi-levels: I = (R+G+B)/3, S = 1 − min/I, hue by the cosine formula.

Alpha is written as 1 unconditionally: a component layer has to be opaque, and transparency belongs on a group mask.

Verification

tools/check_hsi_split.py runs the dual → compose identity round trip: 0.0001 codes on a 32-bit float image, 0.499 codes on 8-bit (quantisation only). After editing any one curve the result lands on the HSI point where only that component moved: S and I within 0.0001, hue angle within 0.0013°.

Notes

  • The output is a data image — do not read it as a photo.
  • It is only meaningful together with lb:hsi-compose.
  • HSI's gamut is a hexagonal pyramid, not a cube: pushing S or I to the extremes sends the inverse transform outside sRGB, and compose clips what falls out.

Just this one

Windows module hsi-dual.dll, drop it into %LOCALAPPDATA%\gegl-0.4\plug-ins; Linux module hsi-dual.so, drop it into ~/.local/share/gegl-0.4/plug-ins, then restart GIMP. Every module here is a standalone GEGL module: it links only against the GEGL and babl that ship with GIMP, never against another module of this project, so one download is all it needs. The full bundle is on the download page.
