色彩算子A complete set of
colour operators for GIMP 3

47 个 lb: 前缀的 GEGL 算子，覆盖色阶、色彩平衡、自然饱和度、 白平衡、通道混合、蒙版生成。每个都是单文件 C，装完即用，能当非破坏滤镜挂在图层上。47 GEGL operators with the lb: prefix, covering levels, colour balance, vibrance, white balance, channel mixing and mask building. Each one is a single C file, works out of the box, and mounts on a layer as a non-destructive fx filter.

三分钟装上Set up in three minutes

  1. 解开压缩包Unpack the archive

    把包里的模块（Windows .dll / Linux .so / macOS .dylib）放进 GEGL 的用户插件目录，目录不存在就自己建一个：Drop the modules (Windows .dll, Linux .so, macOS .dylib) into GEGL's user plug-in directory — create it if it doesn't exist:

    Windows  %LOCALAPPDATA%\gegl-0.4\plug-ins
Linux    ~/.local/share/gegl-0.4/plug-ins
macOS    ~/Library/Application Support/gegl-0.4/plug-ins

  2. 重启 GIMPRestart GIMP

    没有安装步骤，也没有注册表。GEGL 启动时扫描这个目录，GIMP 跟着加载。No installer, no registry. GEGL scans that directory at startup and GIMP picks the modules up.

  3. 在菜单里找Find them in the menu

    菜单栏顶层就有 SuperMrWang（和「颜色」「图层」平级）：色阶家族收在一级目录 Levels 子菜单里（Levels / LAB / HSL / HSB / LCH / CMYK / HSI）， 分量家族的 dual / compose 与 gray-to-component 收在一级目录 Component 里， 其余按 Tone / Color / Blend / Mask / Sharpen / Noise / Distort 七组排开； 也可以按 / 搜算子名直接调。The filters live in a top-level SuperMrWang menu: the levels family is grouped in a top-level Levels submenu (Levels / LAB / HSL / HSB / LCH / CMYK / HSI), the component family (dual / compose pairs and gray-to-component) in a top-level Component submenu, and the rest in seven groups — Tone / Color / Blend / Mask / Sharpen / Noise / Distort. You can also press / and search by operator name.

47 个算子47 operators

按「找算子时的念头」分了九组，和 GIMP 菜单里的分组一致—— 七个色阶收在 Levels 一级目录里，分量家族收在 Component 一级目录里， 锐化 / 杂色 / 扭曲三组在 2026-11 补齐。 点任一算子进去看算法、参数与实测误差。Nine groups organised by the question you ask when hunting for an operator, matching the GIMP menu grouping — the levels family and the component family each sit in their own top-level submenu, and Sharpen / Noise / Distort joined them in November 2026. Open any operator for its algorithm, parameters and measured error.

来源与标定方式Where the numbers come from

多数是按黑盒标定做的：拿目标实现（多为常见修图软件的调整图层）做对照，逐档采样、 拟合公式，再在 16 位精度上把残差压到几码以内——只看输入输出，不读对方的代码。 少数是直接实现公开的数学定义（Lab / LCh / HSL 色阶就是换了个色彩空间做同一件事）。Most were built by black-box calibration: sample a reference implementation (usually a well-known photo editor's adjustment layers) step by step, fit the formula, then press the residual down to a few code values at 16-bit precision — inputs and outputs only, no source reading. A few implement published mathematical definitions directly (the Lab / LCh / HSL levels are the same model in a different colour space).

所以每篇算法说明里都有误差表、以及「哪一段没能对上、偏差多大」。没有说成 「完全一致」的地方，都是实测过确实对不上——例如色温 / 色调对角线上的硬裁切。That's why every algorithm note carries an error table plus a note on which part didn't match and by how much. Anything not described as identical was measured and genuinely doesn't match — the hard clipping along the colour temperature / tint diagonals, for example.

算法来源在文件头 reference 字段里逐条标注，源码与文档在同一个仓库。Sources are listed per operator in the reference field of each file header; source and docs share one repository.
