七个 Python 插件

两件事原生 GIMP 做不顺：灰度图变不成能用的东西（复制图层 → 新建通道 → 粘贴 → 蒙版转选区，四步），以及曲线选不到分量（只有 R/G/B/Alpha，没有 H、S、LCh）。前两个插件把转换压成一次右键；其余五个把图层 拆成分量层各挂一条原生曲线，恒等时精确还原——所以调曲线就等于在那个色彩空间 里调那一维。HSV 与 LCh 各拆三层，HSL 与 Lab 因为有一对分量耦合、拆成两层， HSI 三个分量都借不到模式、干脆合成一层（见下文）。

分量曲线这五个都收在菜单的 Shortcut 子菜单里 （颜色 → SuperMrWang → Shortcut，图层右键同理）：它们本来就是 「一次点击替代一串手工步骤」的东西，以后这类一键操作也往这个子菜单里放。

选区 Layer to Selection一键转选区

把点击的图层变成当前选区。GEGL 算子跑完留下的灰度图， 一步就能接着用——当蒙版用（选区）的场合就归它。

通道

可选 Gray（亮度）/ R / G / B / Alpha——彩色图层选 Gray 时按亮度算， 不是 HSL 明度（纯红 ≈ 54/255，而不是 130）。

组合方式

替换 / 加 / 减 / 交，与 GIMP 选区菜单一致；可反相 （选暗部而不是亮部）。

偏移图层

图层比画布小、带偏移也没问题：只在自己位置生效，界外不选中。

通道 Layer to Channel一键转通道

把点击的图层变成一条新的 Alpha 通道，留档复用—— 后续用通道到选区、或拿通道当图层蒙版都行。

恒为灰度

语义明确

彩色图层先按亮度转成灰度，黑白图层原样——然后把这些灰度值写进通道 （黑 = 不选中、白 = 完全选中、中间灰 = 部分选中）。没有「取 R 通道」 这类选项——要的就是明暗，不给单色通道捣乱的机会。

通道名与反相

可反相、可自定义通道名（默认沿用图层名），建好后状态栏会提示通道名。 想把它变回选区：在「通道」面板右键该通道 → 通道到选区 （GIMP 原生）。

彩色图层的 Gray 是亮度，不是 HSL 明度：纯红 ≈ 54/255， 而不是 HSL 明度的 130——和你在 PS 里按亮度去色的结果一致。 实现上走临时副本去色（GIMP 3.2 的 LUMA 模式），用完即删，活动图层还原。

曲线 HSV SplitH / S / V

GIMP 的曲线只能选 R / G / B / Alpha——想单独曲「色相」或 「饱和度」没有入口。这个插件把图层拆成三张分量层、每层给一条曲线， 再按 HSV 分量模式叠回去：恒等时逐位还原，所以改曲线就等于曲那个分量。

生成的结构

穿透组
HSV split        组 · 穿透（带 alpha 时组上还有蒙版）
  ├─ 3 · Value      模式 HSV 明度
  ├─ 2 · Saturation 模式 HSV 饱和度
  ├─ 1 · Hue        模式 HSV 色相   ← 垫底
  └─ 原图层（不动，可以隐藏）

每层三条滤镜：extract（抽分量）→ curve （你调的那条）→ encode（一个 lb:gray-to-component 滤镜，把灰度编码成携带该分量的彩色）。

层序不能反：分量混合模式只替换一个分量，另外两个从下行读。最底层 必须自带真实色相（全饱和色环），所以 Hue 垫底、Value 在顶。反过来的话 最底是灰，上面两层读到 S=0，怎么换都是灰——把原图层一隐藏就整幅崩掉。

为什么是在做曲线

恒等曲线时三层合成回来逐位还原原图，所以改一条曲线就等于 「在 HSV 空间里曲那一个分量」。GIMP 内置曲线只能选 R/G/B/Alpha——H、S、LCh 这些分量它读不到，这正是缺口。

实测精度

32 位浮点与 8 位图的恒等往返都是 0.5 码；真实 512×512 图逐像素 比对最大 1 码，仅 0.335% 的通道值有差异。剩下的误差是 8 位量化， 编码本身没有查表误差——旧版三条曲线才有 256 点 LUT。

把原图层隐藏掉，三层自己叠出来还是 0.5 码；半透明区域的 透明度由组蒙版保住（三层必须不透明，否则混合模式会按 alpha 做 lerp）。

曲线 LCh SplitL / C / h

同样的思路换到 CIE LCh：明度、彩度、色相三条曲线。 LCh 是「颜色」组里唯一完整、且没有 legacy 包袱的一组分量模式， 感知均匀，做明暗与彩度分级比 HSV 稳。

量程是标定出来的

D50

component-extract 报的不是原始单位：lab-l = L/100、 lch-h = h/360，而 lch-c = C/200（sRGB 内只到 0.656）。编码时算子按 chroma-scale = 200 把灰度乘回真实 C*， 所以彩度层不用再插一条 scale 曲线——曲线的 0.656 处就是 sRGB 最大彩度 （纯蓝 131.21）。

编码路径的坑

色相模式对色相误差极其敏感：ΔH=0.5° 在 C*=90 时就是 9.6 个码值。 所以色相编码不用全饱和色轮，而用等 L 等 C 的色相圆 （L*=70、C*=39.8）——角度严格线性，插值误差从 0.22° 降到 0.002°。

实测精度

浮点恒等往返 ≤ 0.02 码，8 位 ≤ 0.5 码，真实照片 512×512 最大 0.03 码（超过 1.5 码的像素 0 个）。8 位图会被自动收进组里： 不分组时逐层量化会让色相偏到 11 码级。

选 LCh 还是 HSV：HSV 的 V/S 是相对量，调 S 会随 V 变； LCh 的 L/C 是感知均匀的绝对量，做亮度、彩度分级更稳。论完整度也是 LCh 更高 ——GIMP 的 HSV 组里那个「HSL 颜色」其实混了模型，而 LCh 组 H/C/L/Color 四项 齐全，另有一个 Luminance。

曲线 HSL SplitH / S / L

GIMP 给 HSV 和 LCh 都配了分量混合模式，唯独 HSL 没有。 这个插件不是拿 HSV 去近似 HSL，而是把两者精确换算：色相本来就是 同一个函数，S 与 L 则合进一张数据图，由算子联合还原。恒等时精确还原原图， 调哪条曲线就只动那个 HSL 分量。

生成的结构

两层
HSL split        组 · 穿透（带 alpha 时组上还有蒙版）
  ├─ 2 · Hue        模式 HSV 色相   ← 只替换色相
  ├─ 1 · S / L      模式 正常       ← 一条算子链算完整 HSL 色
  └─ 原图层（不动，可以隐藏）

S 曲线挂红通道、L 曲线挂绿通道，色相曲线在 Hue 层。把 Hue 层关掉、 只留 S/L 层，看到的就是「原色相 + 调过的 S/L」——很好用的中间状态。

为什么只有两层

HSL 的 S 与 L 是耦合的：C = (1−|2L−1|)·S、 V = L + C/2、S_hsv = C/V。要精确换回 HSV 的 S/V，编码器必须同时读到两者，而每层的曲线只看得到自己那一个分量—— 两个独立的 1D 曲线表达不了二元映射。所以 S 与 L 合进一张数据图 （R=S、G=L），由 lb:hsl-compose 联合还原；算出来的已经是 完整颜色，第三层就多余了。

硬凑三层的代价

把 HSL 的 L 直接当 V 用：S=0.25 偏 25 码、S=1 偏 64 码 （差的正好是 C/2）；再加一条按「典型 S」校准的曲线，实际 S 一变就偏到 77 码；S、L 一起调最坏 102 码。

适配算子内部用 babl 的 HSLA float 做转换，与 GIMP 自己的 HSL（component-extract 的 hsl-s / hsl-l）同一口径，所以往返没有查表误差：浮点 0.00001 码、 8 位 0.002 码。改 S 曲线后结果的 HSL 饱和度 = f(原 S)，明度与色相 误差 0.0001 码。依赖 lb:hsl-dual / lb:hsl-compose 两个算子，缺了没有一维回退，插件会直接报错。

曲线 Lab SplitL / a / b

Lab 的 a、b 是直角坐标，GIMP 一条 分量模式也对不上；L* 倒是能借 LCh 明度（同一个量）。所以这个 插件把 a 与 b 合进一张数据图联合还原，L* 单独一层——恒等时精确还原原图， 调 a 只动 a、调 b 只动 b。

生成的结构

两层
Lab split        组 · 穿透（带 alpha 时组上还有蒙版）
  ├─ 2 · L          模式 LCh 明度   ← 只替换 L*
  ├─ 1 · a / b      模式 正常       ← 一条算子链算完整 Lab 色
  └─ 原图层（不动，可以隐藏）

a 曲线挂红通道、b 曲线挂绿通道，L 曲线在 L 层（值通道）。数据图里 中性灰落在 0.502，所以 a 曲线在 0.5 附近往上抬就是往洋红推、往下压是往 绿推；b 曲线同理（上=黄、下=蓝）。

为什么 a/b 必须合一层

a、b 是直角坐标，GIMP 没有「a」「b」分量模式。LCh 的 C/h 是它们的 极坐标形式，但每层的曲线只看得到自己那一个标量：C 那一层 不知道 b 变成了多少，所以两条独立的一维曲线拼不出 (a,b) 的二元映射。 合进一张数据图后由 lb:lab-compose 一起读，就精确了。

L* 为什么可以借 LCh 明度

Lab 的 L* 与 LCh 的 L* 是同一个量（babl 里就是同一个通道），所以 「LCh 明度」模式换 L* 是逐位精确的，不是近似。整条链的误差只剩浮点 舍入：0.010 码（8 位 0.499 码）。

量程按 babl 的 CIE Lab float（D50 白点，与 GIMP 的 Lab 空间同口径）：a' = (a*+128)/255、L' = L*/100。 改 a 曲线后结果落在「a* 换了、b* 与 L* 都没动」的 Lab 点上，误差 0.0026 码。超 sRGB 色域的 Lab 点会被裁——那是色域的事实。 依赖 lb:lab-dual / lb:lab-compose 两个算子， 缺了没有一维回退，插件会直接报错。

曲线 HSI SplitH / S / I

HSI 的 I 是 (R+G+B)/3，色相又用余弦定义——GIMP 的六条分量 模式一条也对不上，连「借 HSV 色相换角」都会把 I 带走 22 码。于是三个分量 合进同一层：红=S、绿=I、蓝=色相，三条曲线各管一个分量。

生成的结构

一层
HSI split          组 · 穿透（带 alpha 时组上还有蒙版）
  └─ 1 · HSI S/I/H   模式 正常   ← 一条算子链算完整 HSI 色
  └─ 原图层（不动，可以隐藏）

滤镜栈：decompose（lb:hsi-dual）→ S 曲线（红） → I 曲线（绿） → H 曲线（蓝） → compose （lb:hsi-compose）。三层分量各占一个通道，互不串门。

为什么只有一层

HSL 能拆两层、Lab 能拆两层，是因为各有一个分量借得到现成模式 （HSL 色相 ≡ HSV 色相；Lab 的 L* ≡ LCh 的 L*）。HSI 一个都没有： I=(R+G+B)/3 不是 V 也不是 L。更麻烦的是色相——就算接到 「HSV 色相」模式，那一步保留的是 HSV 的 S/V，HSI 的 I 会被带走 0.085（约 22 码）。所以三个分量只能一起算。

两种色相角不是一回事

HSI 的色相是余弦定义（等亮度平面里的真实夹角），HSV 的是六边形投影上的 参数角；两者只在 0°/30°/60° 重合，中间最多差 1.117°。数据图里存 的是 HSI 的角度，lb:hsi-compose 也按 HSI 的余弦式逆变换， 所以全程不需要换算，往返 0.0001 码。

平均强度 I 比 HSV 的 max 更接近感知亮度，这也是 HSI 常见于图像 分析与曝光校正的原因。S、I 推到极端时逆变换会出 sRGB 色域（HSI 的色域是 六边形棱锥，不是立方体），出界部分按 0/1 裁掉。依赖 lb:hsi-dual / lb:hsi-compose 两个算子，缺了没有回退，插件会直接报错。

和 .dll / .so 一个思路：免编译、解压即用。 区别只是 Python 插件放进 GIMP 的用户插件目录 （%APPDATA%\GIMP\3.x\plug-ins 或 ~/.config/GIMP/3.x/plug-ins），不是 GEGL 的； 包里的「安装说明.txt」写得很全。七个都装也行，分量曲线那几个都在同一个 Shortcut 子菜单里。

三步装上

  1. 拿代码

    git clone https://github.com/SuperMrWang-DEV/gegl-color-ops.git
cd gegl-color-ops

  2. 拷进 GIMP 插件目录

    一条脚本把 plugin/ 下的 .py 全部拷进 GIMP 的 plug-ins 目录（Windows / Linux 通用；带 .disabled 标记的 插件会跳过）：

    bash install-plugin.sh

    或者直接用上面下载区的七个 .zip，把 .py 解进同一个目录（每个插件一个子目录也行，GIMP 会扫描下去）。

  3. 重启 GIMP，找菜单

    颜色 → SuperMrWang 下是 Apply Image / Calculations，分量曲线 收在 Shortcut 子菜单里（HSV / LCh / HSL / Lab / HSI Split (Curves)）；图层右键 → SuperMrWang 下七个都在，分量曲线同样在 Shortcut 里；选择 → SuperMrWang 下是 Layer to Selection / Channel（不依赖右键、方便写脚本）。

脚本调用

七个动作都是标准 PDB 过程，脚本里直接调（参数留空走默认值）：

PDB 过程参数用途
lb-plugin-layer-to-selection channel / invert / operation 图层 → 选区
lb-plugin-layer-to-channel invert / name 图层 → 灰度 Alpha 通道
lb-plugin-hsv-split-curves group 图层 → H/S/V 三层分量曲线
lb-plugin-lch-split-curves group 图层 → L/C/h 三层分量曲线
lb-plugin-hsl-split-curves group 图层 → S/L 层 + Hue 层（HSL 精确适配）
lb-plugin-lab-split-curves group 图层 → a/b 层 + L* 层（Lab 精确适配）
lb-plugin-hsi-split-curves group 图层 → 一层三联曲线（S / I / H）

实现：转换类直接读图层像素（array 的 C 级切片，100 万像素约 4 毫秒）， 不走复制粘贴；灰度内容走零拷贝快路径，彩色图层才临时复制一份做去色。 有活动选区时写通道会先把选区挂起再恢复——GIMP 的 shadow 合并遵守选区， 不挂起的话通道会被截成选区那一块。图层组没有自己的像素，会明确报错提示 先合并组。与 plugin/gray-mask 的分工：gray-mask 走复制/粘贴， 会带上图层蒙版等显示效果；这两个插件读原始像素、更快。 分量曲线类用 gegl:component-extract 抽分量、 gimp:curves 当可调曲线，编码交给本仓库的 lb:gray-to-component——没装这个算子时自动退回三条曲线， 所以只装 Python 插件也能跑。HSL 版例外：它靠 lb:hsl-dual + lb:hsl-compose 把 S/L 联合还原（二维映射没有一维替代）， 缺这两个算子会直接报错，而不是给一个偏几十码的近似。Lab 版与 HSI 版同理： 前者靠 lb:lab-dual + lb:lab-compose，后者靠 lb:hsi-dual + lb:hsi-compose。

回归

tools/check_layer_to_mask.py，23 条断言跑在 gimp-console 的 python-fu-eval 里：灰度值、反相、偏移图层、彩色亮度、四个单通道、 通道值/名字/反相、彩色转通道=亮度、选区不被截断、四种组合方式。

分量曲线另有五个脚本：check_hsv_split.py（24 条）、 check_lch_split.py（35 条）、check_hsl_split.py （28 条）、check_lab_split.py（38 条）与 check_hsi_split.py（37 条）——结构、滤镜栈顺序、浮点与 8 位 恒等往返、曲线与直接改分量的数学期望对照、alpha 穿透、不分组、非法输入、 编码路径量程。全部跑在真实的 GIMP 3.2 里，不是 mock。 编码算子自己还有 check_gray_to_component.py（39 条）， 九个混合模式的恒等往返全在 2 码以内。
