选区 Layer to Selection一键转选区

把点击的图层变成当前选区。GEGL 算子跑完留下的灰度图， 一步就能接着用——当蒙版用（选区）的场合就归它。

通道

可选 Gray（亮度）/ R / G / B / Alpha——彩色图层选 Gray 时按亮度算， 不是 HSL 明度（纯红 ≈ 54/255，而不是 130）。

组合方式

替换 / 加 / 减 / 交，与 GIMP 选区菜单一致；可反相 （选暗部而不是亮部）。

偏移图层

图层比画布小、带偏移也没问题：只在自己位置生效，界外不选中。

通道 Layer to Channel一键转通道

把点击的图层变成一条新的 Alpha 通道，留档复用—— 后续用通道到选区、或拿通道当图层蒙版都行。

恒为灰度

语义明确

彩色图层先按亮度转成灰度，黑白图层原样——然后把这些灰度值写进通道 （黑 = 不选中、白 = 完全选中、中间灰 = 部分选中）。没有「取 R 通道」 这类选项——要的就是明暗，不给单色通道捣乱的机会。

通道名与反相

可反相、可自定义通道名（默认沿用图层名），建好后状态栏会提示通道名。 想把它变回选区：在「通道」面板右键该通道 → 通道到选区 （GIMP 原生）。

彩色图层的 Gray 是亮度，不是 HSL 明度：纯红 ≈ 54/255， 而不是 HSL 明度的 130——和你在 PS 里按亮度去色的结果一致。 实现上走临时副本去色（GIMP 3.2 的 LUMA 模式），用完即删，活动图层还原。

曲线 HSV SplitH / S / V

GIMP 的曲线只能选 R / G / B / Alpha——想单独曲「色相」或 「饱和度」没有入口。这个插件把图层拆成三张分量层、每层给一条曲线， 再按 HSV 分量模式叠回去：恒等时逐位还原，所以改曲线就等于曲那个分量。

生成的结构

穿透组
HSV split        组 · 穿透（带 alpha 时组上还有蒙版）
  ├─ 3 · Value      模式 HSV 明度
  ├─ 2 · Saturation 模式 HSV 饱和度
  ├─ 1 · Hue        模式 HSV 色相   ← 垫底
  └─ 原图层（不动，可以隐藏）

每层三条滤镜：extract（抽分量）→ curve （你调的那条）→ encode（一个 lb:gray-to-component 滤镜，把灰度编码成携带该分量的彩色）。

层序不能反：分量混合模式只替换一个分量，另外两个从下行读。最底层 必须自带真实色相（全饱和色环），所以 Hue 垫底、Value 在顶。反过来的话 最底是灰，上面两层读到 S=0，怎么换都是灰——把原图层一隐藏就整幅崩掉。

为什么是在做曲线

恒等曲线时三层合成回来逐位还原原图，所以改一条曲线就等于 「在 HSV 空间里曲那一个分量」。GIMP 内置曲线只能选 R/G/B/Alpha——H、S、LCh 这些分量它读不到，这正是缺口。

实测精度

32 位浮点与 8 位图的恒等往返都是 0.5 码；真实 512×512 图逐像素 比对最大 1 码，仅 0.335% 的通道值有差异。剩下的误差是 8 位量化， 编码本身没有查表误差——旧版三条曲线才有 256 点 LUT。

把原图层隐藏掉，三层自己叠出来还是 0.5 码；半透明区域的 透明度由组蒙版保住（三层必须不透明，否则混合模式会按 alpha 做 lerp）。

把原图层隐藏掉，三层自己叠出来还是 0.5 码；半透明区域的 透明度由组蒙版保住（三层必须不透明，否则混合模式会按 alpha 做 lerp）。

曲线 LCh SplitL / C / h

同样的思路换到 CIE LCh：明度、彩度、色相三条曲线。 LCh 是「颜色」组里唯一完整、且没有 legacy 包袱的一组分量模式， 感知均匀，做明暗与彩度分级比 HSV 稳。

量程是标定出来的

D50

component-extract 报的不是原始单位：lab-l = L/100、 lch-h = h/360，而 lch-c = C/200（sRGB 内只到 0.656）。编码时算子按 chroma-scale = 200 把灰度乘回真实 C*， 所以彩度层不用再插一条 scale 曲线——曲线的 0.656 处就是 sRGB 最大彩度 （纯蓝 131.21）。

编码路径的坑

色相模式对色相误差极其敏感：ΔH=0.5° 在 C*=90 时就是 9.6 个码值。 所以色相编码不用全饱和色轮，而用等 L 等 C 的色相圆 （L*=70、C*=39.8）——角度严格线性，插值误差从 0.22° 降到 0.002°。

实测精度

浮点恒等往返 ≤ 0.02 码，8 位 ≤ 0.5 码，真实照片 512×512 最大 0.03 码（超过 1.5 码的像素 0 个）。8 位图会被自动收进组里： 不分组时逐层量化会让色相偏到 11 码级。

选 LCh 还是 HSV：HSV 的 V/S 是相对量，调 S 会随 V 变； LCh 的 L/C 是感知均匀的绝对量，做亮度、彩度分级更稳。论完整度也是 LCh 更高 ——GIMP 的 HSV 组里那个「HSL 颜色」其实混了模型，而 LCh 组 H/C/L/Color 四项 齐全，另有一个 Luminance。

和 .dll / .so 一个思路：免编译、解压即用。 区别只是 Python 插件放进 GIMP 的用户插件目录 （%APPDATA%\GIMP\3.x\plug-ins 或 ~/.config/GIMP/3.x/plug-ins），不是 GEGL 的； 包里的「安装说明.txt」写得很全。四个都装也行，菜单入口各自独立。

三步装上

  1. 拿代码

    git clone https://github.com/SuperMrWang-DEV/gegl-color-ops.git
cd gegl-color-ops

  2. 拷进 GIMP 插件目录

    一条脚本把 plugin/ 下的 .py 全部拷进 GIMP 的 plug-ins 目录（Windows / Linux 通用；带 .disabled 标记的 插件会跳过）：

    bash install-plugin.sh

    或者直接用上面下载区的四个 .zip，把 .py 解进同一个目录（每个插件一个子目录也行，GIMP 会扫描下去）。

  3. 重启 GIMP，找菜单

    颜色 → SuperMrWang 下是 HSV / LCh Split (Curves)； 图层右键 → SuperMrWang 下四个都在； 选择 → SuperMrWang 下是 Layer to Selection / Channel （不依赖右键、方便写脚本）。

脚本调用

四个动作都是标准 PDB 过程，脚本里直接调（参数留空走默认值）：

PDB 过程参数用途
lb-plugin-layer-to-selection channel / invert / operation 图层 → 选区
lb-plugin-layer-to-channel invert / name 图层 → 灰度 Alpha 通道
lb-plugin-hsv-split-curves group 图层 → H/S/V 三层分量曲线
lb-plugin-lch-split-curves group 图层 → L/C/h 三层分量曲线

实现：转换类直接读图层像素（array 的 C 级切片，100 万像素约 4 毫秒）， 不走复制粘贴；灰度内容走零拷贝快路径，彩色图层才临时复制一份做去色。 有活动选区时写通道会先把选区挂起再恢复——GIMP 的 shadow 合并遵守选区， 不挂起的话通道会被截成选区那一块。图层组没有自己的像素，会明确报错提示 先合并组。与 plugin/gray-mask 的分工：gray-mask 走复制/粘贴， 会带上图层蒙版等显示效果；这两个插件读原始像素、更快。 分量曲线类用 gegl:component-extract 抽分量、 gimp:curves 当可调曲线，编码交给本仓库的 lb:gray-to-component——没装这个算子时自动退回三条曲线， 所以只装 Python 插件也能跑。
