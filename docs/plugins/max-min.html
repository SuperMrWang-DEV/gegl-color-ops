最大 / 最小值（Max / Min）

plugin/max-min 蒙版 Mask

Photoshop 的「最大值 / 最小值」滤镜：每个像素取邻域内的最大或最小值。 最大值把亮区往外推、吞掉暗处的小点；最小值收亮区、啃掉残留的白边。 GIMP 3 已经不带这个功能了——gegl:dilate / gegl:erode 没被编进官方构建，plug-in-dilate 也早在 2.10 之后移除。 所以这里用的是本项目自己的算子 lb:max-min。

菜单位置
  • SuperMrWang → Mask → 最大值 / 最小值
  • 图层右键 → SuperMrWang → Mask → 最大值 / 最小值

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-max-min(image, drawables, mode, radius, shape, affect-alpha)

标准 PDB 过程，参数留空走默认值。

依赖

用本项目自己的算子 lb:max-min（GIMP 3 已不带 dilate / erode）。插件包里已附带这个模块，按 readme 放进 GEGL 模块目录即可。

  • lb:max-min

两个方向，一件事的两面

形态学

最大值（膨胀）：每个像素取邻域内的最大值，亮区向外长一圈，暗处的小点被吞掉。 最小值（腐蚀）：取最小值，亮区向内收缩，白底上的黑点被抹掉、抠图残留的白边 被啃干净。

  • 扩边 / 收边 · 蒙版、通道上加减一圈
  • 去灰尘点 · 最小值收拾亮斑，最大值收拾暗斑
  • 发光底图 · 最大值先撑开高光，再叠回去就是柔光晕
  • 做厚度 · 最小值内缩一层，与原图求差就是描边

GIMP 里为什么得自己写

2.10 之前有「滤镜 → 通用 → 膨胀 / 腐蚀」，之后交给 GEGL 的 gegl:dilate / gegl:erode。这两个属于 GEGL 的 workshop 算子，官方 Windows 构建没有把它们编进去：本机 3.2.8 上 gegl --list-all 查不到，PDB 里也没有 plug-in-dilate。

仅剩的原生相关过程是 gimp-selection-grow / -shrink， 但它们只作用于选区，改不了一张蒙版或一个图层的像素。

四个参数

对应 PS 的对话框
  • 模式 · 最大值（膨胀）/ 最小值（腐蚀）
  • 半径 · 1–100 像素，r=1 即 3×3，边缘向外长一圈
  • 形状 · 方形（方窗）/ 圆形（圆盘），对应 PS 的「方形度 / 圆度」
  • 影响 alpha · 默认关，PS 同样不动图层透明度

半径语义与 PS 一致：r 表示检查 (±r, ±r) 的邻域，不是窗口边长——所以 r=1 得到 的正是 3×3。

彩色图上会偏色，这是对的

PS 对 RGB 复合图是逐通道取极值的，红蓝交界处因此冒出紫边。插件照这个语义做， 不对通道做任何均衡或换算。

要没有偏色就把目标换成单色的：蒙版、通道、灰度层。蒙版只有一张平面，取极值就是 纯粹的扩边 / 收边。

逐位正确：在缓冲自己的精度里比较

u8 / u16 / f32

极值只需要大小关系，但结果值必须原样搬出来。所以三个精度各展开一份代码： u8 比 u8、u16 比 u16、float32 比 float32，中途不做任何格式转换。把 u16 读成 float 再写回，个别像素就会差 1 码，这里不给它机会。

不做色彩管理、不做 gamma 换算——PS 的这两个滤镜同样是直接对通道值取极值。

边缘不会暗一圈

画布外按复制边缘像素处理。对取极值来说，这与「只算窗口内的像素」逐位等价： 补进来的永远是边缘那一列 / 那一行的副本，不引入新值，也就不像模糊那样在边上留暗边。

速度

方窗可分离：先横向、再纵向，两遍都与半径无关——3MP 图上 r=1 和 r=100 都只要 几十毫秒。圆盘每行半宽不同、不能分离，代价随半径线性增长（3MP、r=100 约 1.2 秒）。

图层上是非破坏滤镜：参数随时可改、眼睛图标随时可关。蒙版和通道没有 滤镜栈（GIMP 3 实测：往蒙版 append 一条滤镜，API 不报错，但渲染不受影响），所以这两类 目标是直接写像素，靠撤销退回。回归：check_max_min.py 27 项（对 O(r²) 暴力 实现逐位比对，u8 / u16 / f32 × 方 / 圆 × 三档半径，含跨分带与超图半径）+ check_max_min_plugin.py 12 项（PDB、滤镜挂载、蒙版写像素、错误分支）。

Max / Min

plugin/max-min Mask Mask

Photoshop's Maximum / Minimum filter: every pixel takes the largest or smallest value in its neighbourhood. Maximum pushes bright areas outwards and swallows small dark specks; minimum shrinks bright areas and eats leftover fringes. GIMP 3 no longer has it — gegl:dilate / gegl:erode are not built into the official Windows binaries and plug-in-dilate was removed after 2.10 — so this uses the project's own lb:max-min operator.

Menu location
  • SuperMrWang → Mask → Maximum / Minimum
  • Layer right-click → SuperMrWang → Mask → Maximum / Minimum

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-max-min(image, drawables, mode, radius, shape, affect-alpha)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

Uses this project's own lb:max-min operator, because GIMP 3 no longer ships dilate / erode. The module is inside the plug-in zip — drop it into the GEGL module folder.

  • lb:max-min

Two directions, one operation

morphology

Maximum (dilate) takes the largest value around each pixel: bright areas grow a ring outwards and small dark specks disappear. Minimum (erode) takes the smallest: bright areas shrink, dark specks vanish and the fringe left after a cut-out is chewed away.

  • Grow / shrink a mask or channel by a ring
  • Despeckle — minimum for bright specks, maximum for dark ones
  • Glow base — maximum spreads the highlights before blending back
  • Thickness — erode and subtract from the original for an outline

Why it has to be written here

Up to 2.10 there was Filters > Generic > Dilate / Erode; afterwards GEGL's gegl:dilate / gegl:erode took over. Those are workshop operators and are not compiled into the official Windows build: on 3.2.8 gegl --list-all does not list them and there is no plug-in-dilate in the PDB at all.

The only native leftovers are gimp-selection-grow / -shrink, and those work on selections only — they cannot change a mask or a layer's pixels.

Four parameters

mirrors PS
  • Mode — maximum (dilate) / minimum (erode)
  • Radius — 1–100 px; r=1 is a 3×3 window, one ring outwards
  • Shape — square or round, i.e. PS's “Preserve: Squareness / Roundness”
  • Affect alpha — off by default; PS leaves layer opacity alone too

Radius means the same thing as in PS: it checks a (±r, ±r) neighbourhood, not a window edge length — so r=1 gives exactly 3×3.

Colour fringing is correct

PS applies this per channel on an RGB composite, which is why red/blue edges pick up a magenta fringe. The operator does the same and makes no attempt to balance channels.

For no fringing, target a single-plane drawable: a mask, a channel or a greyscale layer. On a mask the operation is pure grow / shrink.

Bit-exact: compared in the buffer's own precision

u8 / u16 / f32

A maximum only needs ordering, but the value still has to be carried out untouched. So there are three copies of the kernel: u8 compares u8, u16 compares u16, float32 compares float32, with no format conversion in between. Reading a u16 as float and writing it back moves some pixels by one code — that is not allowed here.

No colour management, no gamma conversion: PS's Maximum / Minimum also work straight on channel values.

No darkened border

Outside the canvas the edge pixels are replicated. For a min/max that is bit-identical to only counting the in-canvas part of the window: the replicated values are copies of an edge pixel that is already inside it. Unlike a blur, nothing darkens at the border.

Speed

A square window is separable — one horizontal pass, one vertical, both independent of the radius: on a 3 MP image r=1 and r=100 both take tens of milliseconds. A disc has a different half-width per row and cannot be split; its cost grows linearly with the radius (3 MP at r=100 is about 1.2 s).

On a layer this is a non-destructive filter: change the parameters or toggle it off at any time. Masks and channels carry no filter stack (measured on GIMP 3: appending a filter to a mask neither errors nor has any effect on rendering), so those two are baked into pixels and undone with undo. Regression: check_max_min.py (27 checks against an O(r²) brute force — u8 / u16 / f32 × square / round × three radii, plus band seams and a radius larger than the image) and check_max_min_plugin.py (12 checks: PDB, filter attachment, mask baking, error branches).
