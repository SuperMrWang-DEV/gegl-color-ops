HSI Split (Curves)

plugin/hsi-split-curves 曲线 Retouch 修饰

HSI 的 I 是 (R+G+B)/3，色相又用余弦定义——GIMP 的六条分量 模式一条也对不上，连「借 HSV 色相换角」都会把 I 带走 22 码。于是三个分量 合进同一层：红=S、绿=I、蓝=色相，三条曲线各管一个分量。

菜单位置
  • SuperMrWang → Retouch → HSI Split (Curves) · single
  • 图层右键 → SuperMrWang → Retouch → HSI Split (Curves) · single

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-hsi-split-curves(image, drawables, group)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

  • lb:hsi-dual
  • lb:hsi-compose

只有一个模式

single
HSI split          组 · 穿透（带 alpha 时组上还有蒙版）
  └─ 1 · HSI S/I/H   模式 正常   ← 一条算子链算完整 HSI 色
  └─ 原图层（不动，可以隐藏）

滤镜栈：decompose（lb:hsi-dual）→ S 曲线（红） → I 曲线（绿） → H 曲线（蓝） → compose （lb:hsi-compose）。三层分量各占一个通道，互不串门。

为什么没有 multi

HSI 一个分量模式都借不到：I=(R+G+B)/3 不是 V 也不是 L； 色相用余弦定义，接到「HSV 色相」模式上换角时保留的是 HSV 的 S/V， I 会被带走 0.085（约 22 码）。所以三个分量只能一起算。

别的四个插件有 multi（拆成两张或三张分量层）：那几家至少有一个分量能借到 现成的分量混合模式——HSV、LCh 三个都有，HSL 借色相，Lab 借明度。HSI 一个 都没有，硬拆就是不准，所以这里只有 single。

两种色相角不是一回事

HSI 的色相是余弦定义（等亮度平面里的真实夹角），HSV 的是六边形投影上的 参数角；两者只在 0°/30°/60° 重合，中间最多差 1.117°。数据图里存 的是 HSI 的角度，lb:hsi-compose 也按 HSI 的余弦式逆变换， 所以全程不需要换算，往返 0.0001 码（8 位 0.5 码）。

平均强度 I 比 HSV 的 max 更接近感知亮度，这也是 HSI 常见于图像 分析与曝光校正的原因。S、I 推到极端时逆变换会出 sRGB 色域（HSI 的色域是 六边形棱锥，不是立方体），出界部分按 0/1 裁掉。依赖 lb:hsi-dual / lb:hsi-compose 两个算子，缺了没有回退，插件会直接报错。

HSI Split (Curves)

plugin/hsi-split-curves Curves Retouch

HSI's I is (R+G+B)/3 and its hue comes from a cosine definition, so none of GIMP's six component modes match — even borrowing HSV hue to rotate the angle drags I by 22 codes. All three components therefore share one layer: red = S, green = I, blue = hue, one curve each.

Menu location
  • SuperMrWang → Retouch → HSI Split (Curves) · single
  • Layer right-click → SuperMrWang → Retouch → HSI Split (Curves) · single

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-hsi-split-curves(image, drawables, group)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

  • lb:hsi-dual
  • lb:hsi-compose

One mode only

single
HSI split group · pass-through (plus a mask when there is alpha)
 └─ 1 · HSI S/I/H mode  Normal  ← one operator chain computes the whole HSI colour
 └─ original layer (untouched, can be hidden)

Filter stack: decompose (lb:hsi-dual) → S curve (red) → I curve (green) → H curve (blue) → compose (lb:hsi-compose). Each component owns one channel and none of them leaks into another.

Why there is no multi

HSI cannot borrow a single component mode: I=(R+G+B)/3 is neither V nor L, and hue is a cosine definition, so wiring it into "HSV hue" mode preserves HSV's S/V and drags I by 0.085 (about 22 codes). The three components can only be computed together.

The other four plug-ins do have multi (two or three component layers) because each of them can borrow at least one native component blend mode — HSV and LCh have all three, HSL borrows hue, Lab borrows lightness. HSI has none, so splitting it would simply be inaccurate. Hence single only.

The two hue angles are not the same thing

HSI's hue is a cosine definition — the true angle inside the constant-luminance plane — while HSV's is a parametric angle on a hexagonal projection. They agree at 0°/30°/60° and differ by up to 1.117° in between. The data image stores the HSI angle and lb:hsi-compose inverts with the HSI cosine form, so nothing is ever converted halfway: the round trip is 0.0001 codes (0.5 codes in 8-bit).

Watch out

Average intensity I is closer to perceived brightness than HSV's max, which is why HSI turns up in image analysis and exposure correction. Pushing S or I to the extremes sends the inverse outside sRGB (HSI's gamut is a hexagonal pyramid, not a cube) and whatever falls out is clipped at 0/1. Depends on lb:hsi-dual / lb:hsi-compose; there is no fallback, the plug-in raises an error if either is missing.
