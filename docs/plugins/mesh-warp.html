自由变形

plugin/mesh-warp 变形 Distort

木偶变形是「拖内容」，这一支是「给内容套一张自由曲面」：图层上盖一张 网格，拖交点改形状；选中交点会露出两个把手，拖把手能把网格线弯成曲线—— 鼓包、收腰、翻边这些直线格子做不到的形状，就靠这一步。

菜单位置
  • SuperMrWang → Distort → 自由变形（网格 + 把手）…

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-mesh-warp(image, drawables, mesh, output)

标准 PDB 过程，参数留空走默认值。

依赖

怎么用

拖点、再拖把手

选图层 → 菜单 → 直接拖网格交点就是变了形。点一下交点选中它， 周围会冒出四个小圆点——那是把手的两端（对称，拖哪头都一样）， 按住拖，网格线就弯成曲线。

右键点交点把那个点复位，选中后按 Delete 也行；右边有「重置选中」 和「全部重置」。网格密度可以换 2×2 到 6×6 格——PS 默认那档是 3×3； 不够用就 Alt+点击自己加线（见下）。

虚线是原位网格，实线蓝的是变形后的网格，两者差多少一眼能看出来。

输出三档，第一档是 非破坏滤镜（对话框默认）：网格挂在 lb:mesh-warp 这条滤镜上，像素一个字节都不动，随时能改参数 或关掉，重跑对话框会从滤镜里把网格读回来接着拖。另外两档是 覆盖当前图层、复制到新图层（把结果烤进像素）。

非交互也能跑

网格是过程参数 mesh：第一段是格数，后面按行优先每个交点 六个（或七个）数—— x,y,ux,uy,vx,vy,auto，前两个是交点位置，中间四个是两个 把手向量，最后一个 1/0 表示把手自动还是已手拖。写两个数就只给位置， 其余按恒等网格补齐：

lb-plugin-mesh-warp 图层 mesh="3,3; 100,200; 150,180" output=replace

对话框点应用时就是把网格写成这个字符串再跑一遍，所以脚本能完整复现。

自己加分割线

Alt + 点击

拖点不够用的时候，按住 Alt 在画面上点一下，就在点到的位置多一条网格线—— 方向跟着离得最近的那条线（竖向的线更近就加竖线）。下拉里的档位会变成 custom，因为格数不再是正方形了。上限 12 条。

这跟 PS 的 Alt+拖网格线是同一件事：局部加密。左边第 1 列可以只切成两半， 右边第 3 格还是整块——不是整张网格一起变密。

加过线的网格写回 mesh 参数时会多两段 u:0,1.33,1.83,2.67,4 和 v:…，记的是每条线在参数空间 里的位置。老串没有这两段，读回来就是等分。

加一条线要付什么代价

格界不再等距，但参数空间仍线性对应原图，所以「哪个像素来自哪儿」一个字 没变，变的只是插值。新线的交点和切向都从原曲面上取，于是画面几乎不动：温和 变形（±10 px）实测曲面偏差 0.6 px、整张偏移场逐节点差 0.4 px。

大幅变形下它会变成一次重拟合（±60 px 时 2–5 px）。因为我们每个角只存 「位置 + 两个切向」，面片中间四个控制点的 twist 是靠四角位置估的，细分之后两侧 的 twist 对不上。PS 存的是整张控制点网，它的细分是精确的——这是表示上的差距， 不是算错。

加线时三处最容易错

① 参数范围必须跟着列数走。源坐标按 u/cols 铺，加一列就得把 整条轴按 (cols+1)/cols 缩放，漏了整张图平移一次。

② 切向要除以这个缩放系数。切向是「每参数单位」的导数，参数变短，同一个 像素跨度对应的导数就跟着变小。

③ 把手圆点按格宽换算。格宽不等时把手画在「节点 ± 切向×格宽/3」；顺手写成 「± 切向/3」的话，窄格的把手会戳到隔壁格外面，拖起来还差一档。

实测

插线本身是 O(节点数)，一瞬间的事；预览仍走 480 长边，一帧 100 ms 上下，多一条线 只多几片，手感不变。

回归里盯的是「插线前后画面不动」：恒等网格插完线必须仍判为恒等（一个像素都不 重采样）、新线的交点必须落在原曲面上（实测 0.00e+00 px）、两张偏移场逐节点差 < 0.5 px。

它是怎么算的

FFD + 双三次 Bezier 面片

标准做法叫 FFD（自由变形）：一格 = 一张 4×4 控制点的双三次 Bezier 曲面片，把参数 (u,v) 映到图像坐标。角点是交点本身，边上 8 个 点是「交点 ± 切向/3」——那把手的三个单位正好对应一个控制点，这也是 PS 里把手为什么画在离交点那么远的地方。

变形是反着做的：对每个目标像素 p，用 Newton 解 P(u,v) = p， 拿到参数 (u,v) 之后，源坐标取原位格上的位置，再交给重采样。 现场栅格（长边 140 个节点）算完后与木偶变形共用同一套 warp_rgba，所以两条变形路线在像素层面是同一段代码。

五个不下心就翻车的细节

① 源坐标是 uv 在原位格上的位置，不是曲面上的位置。曲面只回答 「这个像素该落在哪个 uv」，源图是按原尺寸铺开的。弄反了画面会整体 平移一次，看着像「没对齐」，很难往算法上想。

② 面片中间四个控制点要加 twist 项。只写「± 切向/3」的话，恒等 网格解出来每格中心也是偏的——曲面就不再是平面了。补 (P11-P10-P01+P00)/9 之后，恒等网格的场精确为 0。

③ 把手必须自动限幅。拖走中间交点 80 px，右边那格只剩 26 px 的弦 却还带着 66 px 的切向，控制多边形来回折、格子自交，反解出两个分支， 画面撕一道。所以拖节点时按邻居重算切向，并限到相邻弦长以内。

还有两个

④ Newton 要限步。曲面在交点附近被压扁时局部导数很小，一步能跨 掉一整格，落到隔壁导数大的地方再跳回来——实测在格界上无限来回震， 最后交出一个差 12 px 的解。单步限到 0.75 格就好了。

⑤ 换网格密度是「重新拟合」，不是无损。变密几乎看不出来 （3→6 格误差 1.6 px），变稀（5→2）形状会明显不一样——一张 2×2 网格 本来就只有一格，装不下复杂曲面。建议先定密度再拖。

把手是对称的：一个交点的切向被左右两格共用，所以跨格 C1 连续。 想要尖角目前做不到（PS 的把手也是成对拖的）。

实测

768×1024 图层、拖一个交点 + 弯一处把手：0.41 秒（含读写缓冲区）。 1600×2400 全流程 1.3 秒（解场 150 ms、重采样 1.16 s）。

网格变形是全局的：只要动了一处，整幅画面都要重采样，所以预览按 480 长边算，一次约 95 毫秒——比木偶变形（520 长边、只重采样一小块） 慢，这是代价，不是没优化。

和 PS 差在哪

有：网格交点 + 贝塞尔把手、2×2～6×6 密度、Alt+点击自己加分割线、 原位网格虚线对照、实时预览、脚本参数。没有：PS 的「变形预设」 （弧形 / 旗帜 / 鱼眼那排），也没有「拆分 / 合并格子」（加线是重新拟合， 不是保留原控制点的精确细分），以及木偶变形那边的「深度」层级。

参照物：Krita 的变形工具（Warp）用的是同一类双三次曲面网格， GIMP 自己的 Warp Transform 是「推/拉」画笔式的，都值得对照着看。 PhotoShop 的网格也是这个路子，所以手感能对上。

Free Transform (Mesh)

plugin/mesh-warp Distort Retouch

Puppet warp pulls the content around; this one puts a free-form surface over it. A Bezier grid is laid on the layer: drag a grid point to change the shape, select a point to reveal its handles, drag a handle and the grid line bends into a curve — which is how a bulge, a waist or a flipped edge becomes possible at all.

Menu location
  • SuperMrWang → Distort → Free Transform (Mesh)（网格 + 把手）…

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-mesh-warp(image, drawables, mesh, output)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

Using it

points, then handles

Pick a layer → menu → drag a grid point and the picture deforms. Click a point to select it: four small dots appear around it — the two ends of its handles (symmetric, either end drags the same). Drag one and the grid line bends.

Right-click a point to reset it; Delete does the same for the selected one, and the sidebar has Reset selected / Reset all. Grid density goes from 2×2 to 6×6 cells — Photoshop's default is 3×3. When that is not enough, Alt+click to add lines of your own (below).

The dashed lines are the original grid, the blue ones the deformed grid, so the amount of movement is obvious. Output either replaces the layer or copies to a new one.

By default the dialog attaches a non-destructive filter (lb:mesh-warp): the grid lives on the filter stack, no pixel is touched, and re-running the dialog reads it back so the surface stays editable.

From a script

The mesh is the mesh argument: the cell counts first, then six (or seven) numbers per grid point, row by row — x,y,ux,uy,vx,vy,auto: position, the two handle vectors, and 1/0 for “handle derived from the neighbours” vs “dragged by hand”. Two numbers are enough (position only), the rest of the lattice stays identity:

lb-plugin-mesh-warp layer mesh="3,3; 100,200; 150,180" output=replace

The dialog writes exactly this string when you press Apply, so a script can replay a manual warp.

Adding your own split lines

Alt + click

When dragging points is not enough, hold Alt and click on the picture and a grid line appears right there — its direction follows whichever line is nearest (a vertical one means a new vertical line). The density drop-down switches to custom, because the cells are no longer square. Twelve lines is the cap.

That is what Photoshop's Alt+drag on a grid line does: local refinement. Split column one in half and column three stays whole — the grid does not get denser everywhere.

A grid with added lines writes two extra chunks into the mesh argument, u:0,1.33,1.83,2.67,4 and v:…, holding each line's position in parameter space. Older strings have no such chunks and read back as evenly spaced.

What one line costs

The breaks are no longer even, but parameter space still maps linearly to the original image — which pixel comes from where does not change, only the interpolation. The new line takes its points and tangents from the existing surface, so the picture barely moves: at a mild deformation (±10 px) the measured surface deviation is 0.6 px and the whole offset field differs by 0.4 px.

Under heavy deformation it becomes a refit (2–5 px at ±60 px). Each corner only stores a position and two tangents, so the twist of the four middle control points is estimated from the corners; after splitting, the two sides disagree. Photoshop stores the whole control net, so its subdivision is exact — a difference in representation, not a bug.

Three easy mistakes when adding a line

1. The parameter range has to follow the column count. Source coordinates go as u/cols, so adding a column means scaling the whole axis by (cols+1)/cols — miss it and the picture shifts once.

2. Tangents must be divided by that same factor. A tangent is a derivative per parameter unit; shorter units mean a smaller derivative for the same pixel span.

3. Handle dots scale with cell width. With unequal cells a handle sits at "node ± tangent × cell / 3". Writing "± tangent / 3" makes handles in narrow cells stick out into the neighbour, and dragging is off by one notch.

Measured

Adding a line is O(nodes) — instant. The preview still runs at a 480 px long edge, around 100 ms a frame; one more line adds a few patches, not a change in feel.

The regression watches one thing: the picture must not move. An identity grid with an added line still has to classify as identity (not one pixel resampled), the new line's points must land on the existing surface (measured 0.00e+00 px), and the two offset fields must agree within 0.5 px per node.

How it is computed

FFD, bicubic Bezier patches

The textbook name is FFD (free-form deformation): each cell is a bicubic Bezier patch with 16 control points mapping (u,v) to image coordinates. The corners are the grid points, the eight edge control points are “point ± tangent/3” — three units of handle is exactly one control point, which is also why Photoshop draws the handle that far out.

The warp runs backwards: for every destination pixel p, Newton solves P(u,v) = p; the source coordinate is then the position of (u,v) on the original lattice, handed to the resampler. The field is solved on a raster (140 nodes on the long edge) and then goes through the very same warp_rgba as puppet warp — one resampler for both tools.

Three things that quietly break it

1. The source coordinate is the uv on the original lattice, not a point on the surface. The surface only answers “which uv lands on this pixel”; the source image stays laid out at its own size. Get this wrong and the whole picture shifts once — it looks like a misalignment, not a maths bug.

2. The four inner control points need the twist term. With only “± tangent/3” even an identity grid comes out bent at the cell centre — the surface is no longer a plane. Adding (P11-P10-P01+P00)/9 makes the identity field exactly zero.

3. The handles must be auto-limited. Drag the middle point 80 px and the right cell keeps a 66 px tangent on a 26 px chord: the control polygon folds back, the cell self-intersects, the inverse has two branches and the picture tears. So moving a point re-derives the tangents from its neighbours and clamps them to the shorter adjacent chord.

…and two more

4. Newton needs a step limit. Where the surface is squashed the local derivative is tiny, one step crosses a whole cell, lands where the derivative is large and jumps back — measured as endless oscillation on cell boundaries, ending 12 px off. Limiting a step to 0.75 cell fixes it.

5. Changing the grid density is a re-fit, not lossless. Denser is invisible (3→6 cells: 1.6 px); sparser visibly changes the shape — a 2×2 grid only has one cell to work with. Pick the density first, then drag.

Handles are symmetric: a point's tangent is shared by the cells on both sides, which keeps the surface C1 across cell borders. Sharp corners are not possible (Photoshop drags its handles in pairs too).

Measured

768×1024 layer, one point dragged plus one handle bent: 0.41 s including buffer read and write. 1600×2400 end to end: 1.3 s (field 150 ms, resampling 1.16 s).

This warp is global: move one point and every pixel needs resampling. The preview therefore runs at a 480 px long edge, about 95 ms per redraw — slower than puppet warp (520 px, only a patch resampled). That is the cost, not a missing optimisation.

Where it differs from Photoshop

Has: grid points with Bezier handles, 2×2 to 6×6 density, Alt+click to add split lines of your own, a dashed original grid for reference, live preview and a scriptable mesh. Does not have: Photoshop's warp presets (arc / flag / fisheye), nor splitting / merging cells into a new topology (adding a line is a refit, not the exact subdivision Photoshop gets from storing the whole control net), nor the depth ordering that puppet warp itself lacks.

Useful references: Krita's Warp transform uses the same kind of bicubic surface mesh, while GIMP's own Warp Transform is the push/pull brush. Both are worth comparing against.
