曲线（Curves）

plugin/curves 调色 Color

色阶只有三个点，曲线是任意形状——所以曲线才是调色的第一入口。本项目已经有 六个色彩空间的色阶家族，却一条曲线都没有：这是这套算子最明显的缺口。 GIMP 3 自带 gegl:curves，但它只有复合通道与单色通道两档，给不了 Lab 的 a/b 轴，也给不了 LCh 的彩度与色相。这里补齐四个空间，一条内核。

菜单位置
  • SuperMrWang → Curves → LAB / LCh / HSV / CMYK Curves…

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-curves-lab(image, drawable, curves, output)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

  • lb:lab-curves
  • lb:lch-curves
  • lb:hsv-curves
  • lb:cmyk-curves

一个内核，四个空间

common/curve.h

lb:lab-curves / lch-curves / hsv-curves / cmyk-curves 共用同一份曲线内核：控制点解析、单调三次插值、1024 点 LUT、采样。每个算子只负责声明 babl 格式与分量量程。

量程按 babl 的真实内部单位走，这一条踩过坑：CIE LCH(ab) float 是 物理量（L 0–100、C 0–132、h 0–360），而 HSVA 与 CMYKA 内部是 0–1。照 color-levels.h 的属性量程去写，HSV 的色相 偏移会完全不动——因为写回去的 18 被当成 18 个整圈。

为什么是单调三次，不是样条

自然样条与 Catmull-Rom 在控制点之间会过冲：画一条「先陡后平」的曲线， 样条会在平台段打出一个比控制点还亮的包。落在明度上是灰阶断层，落在 a/b 上就是 中性灰附近冒出一圈本不存在的色光。

这里用 Fritsch–Carlson：每一对切线被夹进半径 3·|割线| 的圆里，插值就再也 越不出相邻控制点的上下界。check_curves.py 里专门有一组陡缓曲线 验证平台段不越界。

色相不是曲线，是偏移曲线

0.5 = 不偏

色相是环形的，这两条路都走不通：照对角线画，首尾映射到不同高度，0° 与 360° 之间会撞出一条硬接缝；把首尾强行对齐，又做不了整体旋转——而整体旋转恰恰是 色相最常用的用法。

所以 LCh 与 HSV 的色相分量改用偏移曲线：横轴是输入色相，纵轴 0.5 表示 不偏。水平线换高度 = 整体旋转（±180°），曲线在中间弯 = 只动某几个 色带。两种用法都天然连续，不存在接缝。偏移量夹在 ±0.5，再多就等价于反着转。

零彩度像素直接跳过：灰阶没有色相，给它算一个随机角度只会引入噪点。

对话框画的 = 算子算的

曲线编辑器是 Python 自绘的，像素计算全在 GEGL 那一侧。为了让两条路不可能漂移， _shared/curve_math.py 按 common/curve.h 逐函数复刻了 一遍，回归里把同一串控制点喂给两边逐点比对（灰阶 64 级，最大差 ≤ 2 码）。

改任何一侧都必须同时改另一侧，否则那条对拍会红。

预览怎么来的

GEGL 滤镜是显示层：直接读 drawable 拿到的是没有滤镜的原始像素。所以预览 走「复制图层 → 挂滤镜 → merge_filter 烘焙 → 读像素 → 删副本」， 整段关掉 undo（临时图层不该出现在用户的历史里）。拖动时按 70 ms 去抖， 不是为了省算力，是为了别让每秒几十次图层复制把界面拖住。

结果是图层上的活滤镜：原像素一个字节不动，重开对话框会把曲线 读回来接着改；也可以选「烘焙进本层」直接落到像素。回归： check_curves.py 26 项（恒等 / 语义 / 不过冲 / 透明 / 容错 / C–Python 对拍）。 算子本身也能从命令行单独跑：gegl in.png -o out.png -- lb:lab-curves curves="L 0,0 0.5,0.7 1,1"。

Curves

plugin/curves Color Color

Levels gives you three points; a curve is any shape you like — which is why the curve is the first thing anyone reaches for. This project already had a levels family across six colour spaces and not a single curve: the most obvious gap in the set. GIMP ships gegl:curves, but it only offers the composite and one channel — no Lab a/b, no LCh chroma or hue. Four spaces here, one kernel.

Menu location
  • SuperMrWang → Curves → LAB / LCh / HSV / CMYK Curves…

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-curves-lab(image, drawable, curves, output)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

  • lb:lab-curves
  • lb:lch-curves
  • lb:hsv-curves
  • lb:cmyk-curves

One kernel, four spaces

common/curve.h

lb:lab-curves, lch-curves, hsv-curves and cmyk-curves share one kernel: point parsing, monotone cubic interpolation, a 1024-entry LUT, sampling. Each operator only declares its babl format and the range of its components.

Ranges follow babl's real internal units, and that cost an afternoon: CIE LCH(ab) float holds physical values (L 0–100, C 0–132, h 0–360) while HSVA and CMYKA are 0–1 internally. Writing to HSV as if it were 0–360 makes the hue shift do nothing — 18 gets read as eighteen full turns.

Why monotone cubic, not a spline

Natural splines and Catmull-Rom overshoot between control points: draw a “steep then flat” curve and the spline bulges above the flat section. On lightness that is a banding step; on a/b it is a ring of colour that was never in the picture.

Fritsch–Carlson keeps each tangent pair inside a circle of radius 3·|secant|, so the interpolant cannot leave the box between neighbouring points. One group in check_curves.py is exactly that curve.

Hue is an offset curve, not a curve

0.5 = no shift

Hue is circular, and both obvious approaches fail: a diagonal curve maps 0 and 1 to different heights and leaves a hard seam where 0° meets 360°; forcing the ends together kills whole-ring rotation, which is the main thing you want from a hue curve.

So the hue component of LCh and HSV uses an offset curve: x is the input hue, 0.5 means no shift. A flat line at another height rotates the whole ring (±180°); a bent line moves only some bands. Both stay continuous by construction. The shift is clamped to ±0.5 — beyond that it is just turning the other way.

Zero-chroma pixels are skipped: grey has no hue, and inventing an angle for it only adds noise.

What the dialog draws is what the operator computes

The editor is drawn in Python; every pixel is computed in the GEGL operation. So that the two cannot drift, _shared/curve_math.py mirrors common/curve.h function by function, and the regression feeds the same control points to both and compares them point by point (64-step grey ramp, max difference ≤ 2 codes).

Change either side and you have to change the other, or that check goes red.

How the preview works

A GEGL filter is a display layer: reading a drawable gives you the pixels without it. The preview therefore copies the layer, attaches the filter, merge_filters it, reads the pixels and deletes the copy — all with undo disabled, because a temporary layer has no business in the user's history. Dragging is debounced at 70 ms, not to save CPU but to keep dozens of layer copies per second from stalling the UI.

The result is a live filter on the layer: pixels stay untouched and re-running the dialog reads the curves back. “Bake into this layer” writes them into the pixels instead. Regression: check_curves.py, 26 checks (identity, semantics, no overshoot, alpha, tolerance, C–Python parity). The operators also run from the command line: gegl in.png -o out.png -- lb:lab-curves curves="L 0,0 0.5,0.7 1,1".
