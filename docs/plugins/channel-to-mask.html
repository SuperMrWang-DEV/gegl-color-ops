Channel to Mask（通道转图层蒙版）

plugin/channel-to-mask 蒙版 Mask

原生路线是「图层 → 蒙版 → 添加图层蒙版 → 通道」，弹窗里再挑一条通道， 而且一次只能伺候一个图层。这个插件把顺序倒过来：先在通道面板选一条， 再在图层面板选中要挂蒙版的图层，右键一次就好——多选几个就一次挂几个， 还能顺手反相。和 Layer to Channel 正好是一对反向操作。

只是原生方式的便捷实现　这里没有新算法： 像素结果全部出自 GIMP 自带的 PDB 过程，插件只负责把散在三处菜单、要跨三四步的动作 收成一次点击，并保证与手点原生菜单得到的结果逐位相同。

菜单位置
  • SuperMrWang → Mask → Channel to Mask
  • 图层右键 → SuperMrWang → Mask → Channel to Mask
  • 通道右键 → SuperMrWang → Mask → Channel to Mask

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-channel-to-mask(image, drawables, channel-name, invert)

标准 PDB 过程，参数留空走默认值。

依赖

不依赖任何自研算子：只读通道像素、只调 GIMP 自己的蒙版 PDB。

原生也能做，差在哪

四步 → 一步

GIMP 自带「从通道取蒙版」，但路径是固定的：先选中图层，菜单进 图层 → 蒙版 → 添加图层蒙版，类型选「通道」，弹窗里再挑一条通道。 三个图层就要走三遍。

这个插件只补三件事：从右键进来（点哪个图层就给哪个挂）、 一次多个（图层面板多选，逐个挂上同一份内容）、可反相 （按通道的补集遮罩，省一次反相操作）。像素结果与原生逐位相同， 包括中间灰那点漂移。

灰度值就是遮罩强度

  • 黑 = 完全遮住，白 = 完全露出，中间灰 = 半透明
  • 通道取通道面板里右键点中的那条；没点过就用面板里选中的那条， 图里只有一条通道时直接用它；也可以填名字指定
  • 图层还没有蒙版 → 按原生方式新建
  • 图层已有蒙版 → 先丢掉旧的再新建，结果与原生新建一致，再跑一次就是刷新

偏移的小图层不用管：蒙版跟图层同尺寸，取的是画布上同位置的通道值， 不会整块错位。

数值和原生一模一样

128 → 188

GIMP 3 没有「通道直接建蒙版」的入口，原生用户只能走两步：通道 → 选区 → 选区建蒙版。这个插件走的就是同一条路，调的是同一个 create_mask(SELECTION)，所以结果逐位相同——包括中间灰那点漂移： 默认 8 位图上，通道 128 建出来的蒙版是 188，不是 128。

32 位线性精度的图像上，通道本身就存线性值，直搬恰好正确，这条链路不漂。 插件不做任何补偿，原生怎样就怎样。

不依赖任何自研算子：只调 GIMP 自己的 gimp-image-select-item 与蒙版 PDB，不自己写像素缓冲。 从通道面板右键进来时，点的哪条就用哪条，不必再在别处选中一次； 真找不到源时会明确报错并列出可用的通道名，不会静默什么都不做。 图层组没有像素，会拒绝并提示先合并。

Channel to Mask

plugin/channel-to-mask Mask Mask

The native route is Layer → Mask → Add Layer Mask → Channel, then picking a channel in the dialog — one layer at a time. This plug-in reverses the order: pick a channel in the Channels dock, select the layers you want masked, right-click once. Several layers at a time, and an invert switch. It is the exact inverse of Layer to Channel.

Only a convenience wrapper over native behaviour — no new algorithms here: every pixel comes out of GIMP's own PDB procedures. The plug-in just folds a detour that lives in three different menus and takes three or four steps into a single click, and keeps the result bit-for-bit identical to doing it by hand.

Menu location
  • SuperMrWang → Mask → Channel to Mask
  • Layer right-click → SuperMrWang → Mask → Channel to Mask
  • Channel right-click → SuperMrWang → Mask → Channel to Mask

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-channel-to-mask(image, drawables, channel-name, invert)

A standard PDB procedure; leave an argument empty to take its default.

GIMP can do it — here is the difference

four steps → one

GIMP does have "mask from a channel", but the path is fixed: select the layer, menu to Layer → Mask → Add Layer Mask, choose the Channel type, then pick one in the dialog. Three layers means walking it three times.

This plug-in adds three things only: it lives in the right-click menu (mask the layer you clicked), it takes several layers at once (multi-select in the Layers dock, all get the same content), and it can invert (mask by the channel's complement). Pixel results are bit-for-bit identical to the native route, mid-grey drift included.

Grey level is mask strength

  • Black hides, white shows, mid grey is partial
  • The channel is the one you right-clicked in the Channels dock; with no click it falls back to the dock selection, then to the only channel in the image. A name overrides all of that
  • No mask yet → a new one is built the native way
  • Mask already there → dropped and rebuilt, identical to a fresh native one, so re-running refreshes it

Offset layers need no attention: the mask matches the layer's size and samples the channel at the same canvas position, so nothing lands shifted.

Numbers identical to native

128 → 188

GIMP 3 has no direct "channel to mask" entry, so the native route is two steps: channel → selection → mask from selection. This plug-in takes the same road and calls the same create_mask(SELECTION), so results match bit for bit — including the mid-grey drift: on a default 8-bit image a channel value of 128 produces a mask value of 188, not 128.

On 32-bit linear precision the channel itself holds linear values, the straight copy happens to be correct, and nothing drifts. The plug-in adds no compensation: whatever native does is what you get.

No dependency on this project's operators: it calls GIMP's own gimp-image-select-item and mask PDB, and never writes pixel buffers itself. Entering from a channel's right-click menu uses that very channel, so there is nothing to select first; when no source can be found it fails with an explicit message listing the available channels. Layer groups have no pixels, so it refuses and asks you to merge first.
