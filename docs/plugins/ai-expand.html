AI 扩图

plugin/ai-expand AI AI

把画布往外扩一圈，让本机 ComfyUI 把新长出来的地方画满——Photoshop 的 Generative Expand 就是这件事。走的还是 AI 填充那条 inpaint 管道，不新增任何节点； 区别只在蒙版是算出来的，不是手画的。

菜单位置
  • SuperMrWang → AI → AI Expand (Outpaint)…（四周 / 左右 / 单边）
  • SuperMrWang → AI → AI Expand (Outpaint, Advanced)…（底模 / 种子 / 羽化）

处理对象是整张画布：把画布往外扩，扩出来的那一圈当成蒙版交给 ComfyUI 画满。原图层一个像素都不重采样——结果是一层新图层，靠羽化蒙版把自己盖在旧画布之外。送出去的是硬蒙版（0/255，并往原图里多吃一圈），羽化斜坡只留给图层蒙版。

脚本调用
lb-plugin-ai-expand( image, drawables, prompt, negative, edges, amount, variations, pick) lb-plugin-ai-expand-advanced( image, drawables, prompt, negative, edges, amount, variations, pick, server, checkpoint, steps, cfg, seed, feather, timeout)

标准 PDB 过程，参数留空走默认值。

依赖

不依赖任何自研算子，也不用编译：扩出来的那一圈由你自己那台 ComfyUI 画，插件负责算蒙版、补边、发 HTTP、贴回。需要 plugin/_shared/ 里的 ai_client.py / comfy_ui.py / mask_io.py（下载包里带上了），以及一个在跑的 ComfyUI——没有的话菜单里的 AI 环境… 可以一键装。

扩哪几边、扩多少

七种组合

四周 / 左右 / 上下 / 只左边 / 只右边 / 只上边 / 只下边，每边一个像素数 （默认 256）。选「左右」时上下就是 0——不会顺手把画布长高，让人以为插件自己 乱动。

提示词描述的是整张图应该长什么样，不是只描述新区域：「黄昏的海边、湿沙、 远处的崖壁」。画布之外是什么模型看不见，只能靠这句话告诉它。

两张蒙版

新区域用边缘像素复制当起点（黑边会让模型把旁边的肤色一起压暗）。喂给模型 的是硬蒙版：只有 0 和 255，还往原图里多吃一圈。因为 ComfyUI 那条工作流 的终点是解码出图、没有合成节点，给它一张半透明的软蒙版，模型会把交界当成 「半褪色的区域」重建，亮度被拉起来——贴回去就是一圈亮边。

±24 px 的羽化斜坡只留给图层蒙版，这样整条链路只混合一次。结果贴回后还会 自动做两级修补：接缝低频色差补偿与颗粒匹配，都用的是多候选打分那套 quality.py。

尺寸的实话

扩完的整张画布要送进模型，而 SD 只在自己训练过的分辨率上画得对：744×1120 左右 各扩 240 之后是 1224×1120，SDXL 会按 1024 长边画，新带子回来要放大两三倍。 想要锐就用 Flux，或者一次只扩一边、扩得少一点。

实测（RTX 3070 Ti）：1224×1120 / 左右各 240，SDXL 两张候选 35 秒，Flux 一张 81 秒。纯色平面上的亮度亮边已经修掉（跨交界的亮度爬坡从 25 级 降到 3 级以内）；还剩一条 48 px 混合带里看得出「模型延续的内容没对齐」的影子， 尤其规则几何（窗框、地砖）——那是这种做法的下限，不是色差。

AI Expand (Outpaint)

plugin/ai-expand AI AI

Grow the canvas and let a local ComfyUI paint what is missing — Photoshop's Generative Expand. It runs on the very same inpaint pipeline as AI Inpaint and adds no new nodes; the only difference is that the mask is computed from the canvas edge instead of drawn by hand.

Menu location
  • SuperMrWang → AI → AI Expand (Outpaint)… (four sides / left-right / one)
  • SuperMrWang → AI → AI Expand (Outpaint, Advanced)… (model / seed / feather)

It works on the whole canvas: grow it, then hand the new ring to ComfyUI as a mask. The original pixels are never resampled — the result is a new layer whose feathered mask only covers the band outside the old canvas. The mask sent out is hard (0/255, grown into the original); the feathered ramp is only used by the layer mask.

Scripting
lb-plugin-ai-expand( image, drawables, prompt, negative, edges, amount, variations, pick) lb-plugin-ai-expand-advanced( image, drawables, prompt, negative, edges, amount, variations, pick, server, checkpoint, steps, cfg, seed, feather, timeout)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

Which sides, how much

seven choices

All four / left and right / top and bottom / left / right / top / bottom, with a pixel amount per side (256 by default). Choosing “left and right” leaves the top and bottom at exactly 0 — the canvas never grows where you did not ask it to.

The prompt describes the finished picture, not just the new band: “a quiet beach at sunset, wet sand, distant cliffs”. The model cannot see past the canvas, so this is the only place to say what belongs there.

Two masks, not one

The new area starts from replicated edge pixels — a black border makes the model darken the skin next to it. What the model receives is a hard mask: strict 0 and 255, grown a little into the original. ComfyUI's workflow ends at decode — there is no composite node — so a half-transparent mask reads as “a faded region to rebuild”, the model brightens it, and that repaint lands in exactly the band where the feather blends. The result was a visible bright frame.

The ±24 px ramp is only used by the layer mask, so the whole chain blends once. After pasting, the result gets the same two clean-up passes AI Inpaint uses: low-frequency seam compensation and grain matching, both from quality.py.

The honest bit about size

The whole grown canvas goes into the model, and SD only draws well near the resolution it was trained on: 744×1120 grown to 1224×1120 is drawn at 1024 on the long side, so the new band comes back and gets enlarged two or three times. Use Flux if you want it crisp, or grow one side at a time, and less.

Measured (RTX 3070 Ti): 1224×1120 with 240 px on each side, SDXL two candidates 35 s, Flux one candidate 81 s. The brightness ridge across the join is gone (the ramp went from 25 levels to under 3); what is left is a 48 px blend band where the model's continuation does not quite line up with the original — most visible on regular geometry such as window frames. That is the limit of the technique, not a colour error.
