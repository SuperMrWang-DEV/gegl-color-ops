AI 局部重绘

plugin/ai-inpaint AI AI

框一块地方，写一句提示词，剩下的交给本机 ComfyUI（Stable Diffusion）： 插件把选区连同周围上下文裁下来、连蒙版一起送过去，等画完再把结果当新图层贴回原位。 不需要联网，不需要账号，一张 1024×512 的图在本机显卡上约 9 秒。

菜单位置
  • SuperMrWang → AI → AI Inpaint…（简版：只问画什么）
  • SuperMrWang → AI → AI Inpaint (Advanced)…（全参数）
  • SuperMrWang → AI → AI Select by Name…（按名称自动选区）
  • SuperMrWang → AI → AI Environment…（装 / 起 ComfyUI，看底模）

处理对象是当前选区：先框出要改的地方，插件把这块连同周围一圈裁下来交给 ComfyUI，回来的图当新图层贴回原位，羽化过的选区做图层蒙版。没有选区它不会乱猜，会直接提示先框一块。

脚本调用
lb-plugin-ai-inpaint( image, drawables, prompt, preset, negative) lb-plugin-ai-inpaint-advanced( image, drawables, prompt, preset, negative, server, checkpoint, steps, cfg, seed, denoise, grow, grow-mask-by, feather, timeout, keep-mask, scale) lb-plugin-ai-select( image, drawables, object, sam2-model, threshold, grow, shift-x, shift-y, server, timeout) lb-plugin-ai-env(image)

标准 PDB 过程，参数留空走默认值。

依赖

不依赖任何自研算子，也不用编译：像素由你自己那台 ComfyUI 里的 Stable Diffusion 画，插件只负责裁图、发 HTTP、贴回。需要 plugin/_shared/ 里的 ai_client.py 与 prompt_tools.py（下载包里带上了），以及一个在跑的 ComfyUI——没有的话菜单里的 AI 环境… 可以一键装、一键起，安装器就在这个包的 ai-setup/ 目录里。

一次点击做了什么

五步
  1. 选区外扩 grow（默认 8 px，收拾接缝），外接框再带一圈上下文；
  2. 裁切框宽高对齐到 8——VAE 是 8× 下采样，不对齐回来就错位；长宽比补到 ≤ 2:1，见下面「六个坑」；
  3. 从可见合成读这块像素（图层比画布小时取到的是下面图层，不是黑）， 连同蒙版 PNG 发给 ComfyUI；
  4. 轮询 /history 等它画完；
  5. 结果读回成新图层，插在原图层正上方、偏移对回原地，羽化选区做图层蒙版。
AI Inpaint            新图层 · 带羽化图层蒙版
  └─ 原图层             不动，随时关掉对比

keep-mask 打开时，另存一条 "AI Mask" 通道，
以后想重新限定范围可以直接拿来用。

选区要紧

最容易踩

蒙版盖住多少，模型就重画多少——它没有「这副眼镜戴在脸上该多大」的尺度概念。 框满整个额头到脸颊，出来的就是一副盖住半张脸的巨大墨镜。贴着目标该在的位置 框一条，上下各留 8~16 px 就够。

边缘不用抠准：grow 会把选区外扩，feather（默认 4 px） 管贴回时的过渡。真要精确形状，先在选区上做好再跑。

三个框

简版只有这些

Prompt —— 这里该变成什么。写结果，不写动作：要去掉一只瓶子，写 empty wooden table, wood grain，别写 remove the bottle。 常用词可以直接写中文，prompt_tools 翻成英文再送（SD 本身只读英文， 中文提示词在它那里等于噪声）。

What to paint（preset）—— 主体下拉。猫 / 狗 / 人 / 花 / 树 / 咖啡 / 食物 / 车。选了以后提示词只补细节（颜色、姿态、环境）。 抹掉东西就选 Erase（keep the background）：它不往提示词里加字， 作用是告诉候选打分器「这一格要留空」——三张候选里「填得最平」的那张 才会胜出，而不是「画得最多」的那张。

Negative prompt —— 不要什么。默认已把画风压向照片： illustration, cartoon, flat graphic, poster, vector art, cgi。 这是修图插件，先让模型别往矢量插画跑；想要画风自己改这一栏。

多候选：出三张，自己挑

variations

一次采样可以出 2~4 张（variations，默认 3），先按接缝、糊／碎、 跨边缘色台阶、选区外改动、结构密度打分，然后弹一个缩略图挑选窗： 几张并排、标着序号和分数，点一下换一张，确认后只留选中的那张。

缩略图只看「选区 + 30% 边距」——候选图层往往比选区高好几倍，整块缩下去 三张会长得一模一样。勾掉「保留其余候选」就把没选中的删掉，默认留下当 隐藏图层，随时点眼睛换回来。

批处理与「重复上次」不弹窗，直接用打分最优那张： 一个会等鼠标的批处理任务等于卡死。pick 关掉也是这个行为。

参数框

GIMP 3 不会替插件生成参数对话框，得插件自己建。这一支在 run() 里 调 _shared/lb_dialog.py：交互模式弹框、取消就是取消， 批处理与「上次的值」直接放行，不再偷偷按默认值跑一遍。

这一课上过的不止这一支：不自己建框，参数就全部隐形， 永远按默认值执行。

依赖：一条命令下齐（模型 / 节点包 / 权重）

2026-11-24

插件是压缩包，可 AI 那几个功能要的东西都在 ComfyUI 那一侧：模型分五个目录、 Flux 要 ComfyUI-GGUF、按名称选区要 ComfyUI-RMBG 和 1.1 GB 权重。让用户照着文档放文件是这个项目最容易失败的地方，所以有一条入口 包干——先体检，再下缺的：

python tools/setup_comfy.py --check     # 缺什么、多大、装在哪
python tools/setup_comfy.py             # 默认：inpaint 两档 + 选区 + 抠图
python tools/setup_comfy.py --tier min  # 最小：只 SD1.5-inpaint（4.3 GB）
python tools/setup_comfy.py --tier full # 再加 Flux.1 Fill（12 GB）

它自己找 ComfyUI（便携包 / 源码目录 / setup_ai.py 装的 py/ 布局都认，目录来自 --home → 插件里选过的那个 → 常见路径）；节点包和它的 pip 依赖成对装（少了依赖那个节点会静默消失，比不装 更难查）；下载先写 .part 再改名，hf-mirror → huggingface.co 换源不丢进度，落盘尺寸对不上就重下； 开跑前算磁盘；最后只有节点/补丁变了才重启，重启会等到 /system_stats 真的通，再回读 /object_info 确认 「底模几个、gguf 主干几个、节点加载了没」。

sdxl：sd_xl_base_1.0_inpainting_0.1.safetensors 丢进 models/checkpoints/ 就能用——「inpaint 专用」和「SDXL」两个条件 同时凑齐，8 GB 卡 30~40 秒一张，不用装任何扩展。同一块选区、同一句 提示词，SD1.5 给的是「糊的正面坐姿猫」，SDXL 给的是一只趴着、带接触阴影、 接缝看不出来的橘猫。

flux：flux1-fill-dev-Q4_K_S.gguf（→ models/diffusion_models/）+ t5xxl_fp8_e4m3fn 和 clip_l（→ models/text_encoders/）+ ae.safetensors （→ models/vae/），还要装 custom_nodes/ComfyUI-GGUF。 8 GB 卡一张 1~3 分钟，许可禁止商用。它不是「换个底模」那么简单： 主干走 UnetLoaderGGUF、文本编码器拆成 T5+CLIP-L 两个、解码用单独的 ae、提示词强度由 FluxGuidance（默认 30）管而不是 cfg（固定 1.0）。所以看到 .gguf 或名字带 flux， inpaint() 会把整张节点图换掉。四个文件缺一个都跑不起来， flux_assets() 会点名缺哪个、该放哪。

三档实测（同选区、同提示词、同一张地板）：SD1.5 的猫毛发是一团、 狗的腿糊在一起；SDXL 形体和投影对了，但同一句「a small cream puppy」 画了两只狗，写 `one single` 才收住；Flux 给一只奶油色小狗、四条腿都在地上， 猫的毛尖和眼神都是清楚的。代价 74~84 秒/张。

自动挑底模优先 SDXL 那一档 inpaint（细节明显强过 SD1.5）， Flux 不进自动——它慢一个数量级，自动挑会让人以为插件卡死了。

六个坑

都在代码里绕开了

1. 蒙版方向是反的。ComfyUI 的 LoadImage 用 alpha 倒推蒙版 （mask = 1 - alpha），所以「要重绘」必须写成透明。直接送灰度图 会得到全 0 蒙版，跑完像素纹丝不动。

2. 8× 对齐。裁剪框宽高不是 8 的倍数就会被截断，回来的图比请求的小， 贴回去整块错位。

3. 模型必须和条件节点配对，配错就乱画。inpaint 专用底模训练时见过 「洞」，要配 InpaintModelConditioning（蒙版和被挖掉的图一起进条件）； 普通底模配 VAEEncode + SetLatentNoiseMask。用普通底模 走 VAEEncodeForInpaint 加 denoise 1.0 时，一块 260×100 的额头 会被重绘出丝状眉毛和几道白痕、边界一条直线——这是 2026-11-24 的实测。 换成 inpaint 底模 + 条件节点，同一块区域眉毛顺着原方向接上。

4. 画幅比例。SD 只在自己训练过的比例附近画得对。选区是眼睛那样一条 1024×400（2.56:1）时，SDXL 会把整块画成平涂海报——一句 sunglasses 出来是一块绿底配重复白色箭头。 plan_canvas_rect() 一律先补到 ≤ 2:1：优先往画面里长真实像素， 画面到边了才复制边缘，补出来的那圈贴回时被蒙版挡住。

5. 短边与上下文。只把长边对到 512 的话，1024×400 会变成 512×200 —— 短边远低于 SD1.5 的 512，出来就是一排排重复图形；上下文只给 32 px 时 模型看不到周围是什么，也会自己编。现在上下文按选区较长边的 0.75 倍给 （至少 64 px），work_size() 两头卡：短边抬到家族下限 （SD1.5 512 / SDXL 768），长边不超上限（768 / 1024）；大图里选一小块时 还会先把上下文收窄（fit_context()），免得整块缩下去把细节 缩没。

6. 一次只画一张。赌一张的失败率就是全部失败率。现在默认一次出 3 张（RepeatLatentBatch，共享模型加载），按四项打分排序： 接缝比周围硬不硬、填充区比周围糊还是碎、跨边缘有没有颜色台阶、选区外 有没有被改动。最好的那张显示，其余藏在图层面板里（点眼睛就能换）。胜出 那张再做两步收尾：接缝色差补偿（只补低频偏移，生成细节不动）和 颗粒匹配（周围是颗粒感照片就补噪点，干净照片不加）。Variations 设成 1 就是原来的一枪定生死。

按名称自动选区

不手描

AI Select by Name… 不描边，只写名字：ear、left eye、the white shirt。它把图层送去 ComfyUI，走 ComfyUI-RMBG 的 SAM2Segment——GroundingDINO 先把文字变成候选框， SAM2 再按框切出蒙版——蒙版回来变成普通 GIMP 选区。这一步不改一个 像素，后面的 AI 填充、调色、局部模糊、抠图都能接着用。

实测 744×1120 的人像、sam2.1_hiera_tiny 档：5.8 秒选中 74×102 的耳朵，边界和手描的一致。档位越大边缘越准（base_plus 在杂乱背景上更稳），代价是慢一些。

要在物体旁边加东西，记得平移选区。SAM2 给的是物体轮廓、不含周围的 留白：框住整只耳朵再写 earring，出来的是压在耳朵上的金环和一个 黑洞；把 Shift selection Y 调 +58、让选区落到耳垂下方之后， 才是一枚挂在耳垂上的金环。改物体本身（换衣服、去掉图案）就直接用原框。

一次性准备：python tools/setup_comfy_sam2.py——装 groundingdino-py / hydra-core / omegaconf、 下 SAM2-tiny + GroundingDINO + bert-base-uncased（约 1.2 GB，走 hf-mirror）、 再写一个 custom_nodes/zz_bert_shim 补丁（transformers 5.x 删掉了 BertModel.invert_attention_mask，补上才能跑）。装完重启 ComfyUI。

AI 环境

装在哪都行

AI Environment… 打开先报状态：连不连得上、什么版本、几个底模，以及 ComfyUI 装在哪、用的是哪个 python。目录不对就点 Choose folder… 手选（含 main.py 的目录，或包着 ComfyUI/ 的外层目录），选择会存进配置文件，下回不用再选。

Start 起服务、Stop 停掉插件自己起的那个进程、 One-click install… 首次装环境（约 10 GB：嵌入式 Python + torch cu128 + ComfyUI + 一份底模）、Model folder 直接打开 models\checkpoints、Refresh 重新探测并带出日志尾几行。

默认开着「ComfyUI 没在运行时自动启动」：跑 AI 之前先探活，连不上就按选好的 目录在后台拉起来（不弹控制台，输出写 comfyui.log），等它就绪 再继续。只用手选过的目录、不去猜——猜错会拿另一个 Python 起别人的 ComfyUI。

配置：Windows 在 %APPDATA%\SuperMrWang\comfyui.json， Linux/macOS 在 ~/.config/SuperMrWang/comfyui.json。安装器随插件走 （包里的 ai-setup/），不需要另外去找。

实测

check_ai_inpaint*.py

tools/check_ai_inpaint.py 298 条断言跑在本地 mock 服务上 （不需要显卡）：蒙版方向、8× 对齐、画布补边、缩放倍率上下限、底模家族判定、 工作流节点与连线、提示词中英转换、候选打分（插入 / 抹除两套判据）、失败退路。

tools/check_ai_inpaint_gimp.py（107 条）在真实 GIMP 3.2 里把过程跑一遍： 选区 → 提示词 → 新图层、蒙版与通道、候选挑选窗的裁切与选择、乱填的底模名 被下拉拒回。

速度（RTX 3070 Ti，SDXL，25 步，1024×512）：8.7 秒。同一尺寸走 CPU 兜底是 94 秒（384×256 实测），能跑但不适合批量。

前提

一个在跑的 ComfyUI + 一份底模。插件只用标准库发 HTTP，不装任何 Python 依赖； HTTP 与 PNG 编解码都在 plugin/_shared/ai_client.py 里， 回归测试用 tools/mock_comfy.py 顶替真服务。

中文界面的人不用记参数名：po/zh_CN.po 里这些标签都翻过， 菜单、参数框、状态提示都是中文。

AI Inpaint

plugin/ai-inpaint AI AI

Frame an area, write one line of prompt, and your own ComfyUI (Stable Diffusion) does the rest: the plug-in crops the selection plus a ring of context, sends it with a mask, waits for the answer and pastes it back as a new layer. No account, no upload — 1024×512 comes back in about 9 seconds on a local GPU.

Menu location
  • SuperMrWang → AI → AI Inpaint… (three boxes)
  • SuperMrWang → AI → AI Inpaint (Advanced)… (every knob)
  • SuperMrWang → AI → AI Select by Name… (SAM2 selection)
  • SuperMrWang → AI → AI Environment… (install / start ComfyUI)

It works on the current selection: frame what should change and the plug-in crops that area plus a ring of context, sends it to ComfyUI, then pastes the answer back as a new layer masked by your feathered selection. With no selection it says so instead of guessing.

Scripting
lb-plugin-ai-inpaint( image, drawables, prompt, preset, negative) lb-plugin-ai-inpaint-advanced( image, drawables, prompt, preset, negative, server, checkpoint, steps, cfg, seed, denoise, grow, grow-mask-by, feather, timeout, keep-mask, scale) lb-plugin-ai-select( image, drawables, object, sam2-model, threshold, grow, shift-x, shift-y, server, timeout) lb-plugin-ai-env(image)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

No operator modules and nothing to compile: the pixels are painted by Stable Diffusion inside your own ComfyUI, and the plug-in only crops, posts over HTTP and pastes back. It needs ai_client.py and prompt_tools.py from plugin/_shared/ (inside the download) plus a running ComfyUI — if there is none, the AI Environment… menu entry installs and starts one, and the installer ships in the ai-setup/ folder of this zip.

What one click does

five steps
  1. Grow the selection by grow (8 px by default, hides the seam) and take its bounding box plus context;
  2. Align the crop to 8 — the VAE downsamples 8×, and a crop that is not a multiple comes back truncated and pastes out of place — then pad the aspect ratio to ≤ 2:1 (see “six traps” below);
  3. Read those pixels from the visible composite (a layer smaller than the canvas gives you the layer below, not black) and post them with a mask PNG;
  4. Poll /history until the job is done;
  5. Load the result as a new layer directly above the original, offset back to where it came from, masked by the feathered selection.
AI Inpaint            new layer · feathered layer mask
  └─ original layer     untouched, toggle it to compare

With keep-mask on, an "AI Mask" channel is kept as well,
so you can re-limit the area later.

Keep the selection tight

the usual trap

Whatever the mask covers is what gets repainted — the model has no idea how big a pair of glasses should be on a face. Frame the whole forehead-to-cheek band and you get glasses covering half the head. Frame the strip where they belong, 8–16 px of slack on each side is plenty.

The edges do not need to be precise: grow expands the mask and feather (4 px by default) blends the pasted result back in.

Three boxes

that is the simple version

Prompt — what should be there. Describe the result, not the action: to remove a bottle write empty wooden table, wood grain, not remove the bottle. Common Chinese words are fine — the plug-in translates them first; SD itself only reads English, so raw Chinese is just noise to it.

What to paint (preset) — a subject drop-down.Cat / dog / person / flower / tree / coffee / food / car. Pick one and the prompt only needs the details (colour, pose, surroundings). Removing something? Pick “Erase (keep the background)”. It adds no words to the prompt — it tells the candidate scorer that this box should end up empty, so the flattest of the three candidates wins instead of the one that invented the most.

Negative prompt — what must not appear.The default already leans photo: illustration, cartoon, flat graphic, poster, vector art, cgi. This is a retouching plug-in, so the model is told not to drift into vector art; change the line if you want a stylised result.

Several candidates, pick one

variations

One run can draw 2–4 candidates (variations, 3 by default). They are scored on seam sharpness, how soft or busy the fill is, the colour step across the edge, changes outside the selection and structure density — then a thumbnail picker opens: side by side, numbered, scored, click to choose, and only the chosen one stays visible.

Thumbnails are cropped to “selection + 30% margin”. A candidate layer is often several times taller than the selection, and scaling the whole layer down made all three look identical. Untick “keep the other candidates” to delete them, or leave them hidden on the layer stack and click an eye to swap.

Batch runs and “repeat last” never open it — a batch job waiting for a mouse click is a hung batch job. Turning pick off does the same.

The parameter dialog

GIMP 3 does not build a dialog for a plug-in — the plug-in has to. This one calls _shared/lb_dialog.py from run(): interactive runs get a dialog, cancel really cancels, and batch runs or “last values” pass straight through instead of silently running with defaults.

Every plug-in in this project learned it the hard way: without a dialog of your own, every parameter is invisible and the defaults always win.

Dependencies: one command, everything

2026-11-24

The plug-in ships as a zip, but everything the AI features need lives on the ComfyUI side: models in five different folders, ComfyUI-GGUF for Flux, ComfyUI-RMBG plus 1.1 GB of weights for select-by-name. Telling users to copy files by hand is the most likely failure in this project, so there is one entry point that checks first and downloads only what is missing:

python tools/setup_comfy.py --check     # what is missing, how big, where
python tools/setup_comfy.py             # default: both inpaints + select + cutout
python tools/setup_comfy.py --tier min  # minimal: SD1.5-inpaint only (4.3 GB)
python tools/setup_comfy.py --tier full # add Flux.1 Fill (12 GB)

It locates ComfyUI itself (portable package, source tree, or the py/ layout setup_ai.py creates; --home → the folder picked in the plug-in → common paths); installs node packs together with their pip dependencies (a pack without its dependency vanishes silently at startup, which is worse than not installing it); writes downloads to .part and renames only when the size matches, retrying across hf-mirror → huggingface.co without losing progress; checks free disk first; restarts only when a node or patch changed, and waits for /system_stats before reading /object_info back to confirm what the server can actually see.

sdxl: drop sd_xl_base_1.0_inpainting_0.1.safetensors into models/checkpoints/ and you are done — it satisfies “inpaint-only” and “SDXL” at once, 30–40 s per image on an 8 GB card, no extensions needed. Same selection and prompt: SD1.5 returns a smeared front-facing cat, SDXL returns a lying cat with a contact shadow and an invisible seam.

flux: flux1-fill-dev-Q4_K_S.gguf (→ models/diffusion_models/) plus t5xxl_fp8_e4m3fn and clip_l (→ models/text_encoders/) and ae.safetensors (→ models/vae/), plus custom_nodes/ComfyUI-GGUF. 1–3 minutes per image on 8 GB; the licence forbids commercial use. It is not just another checkpoint: the trunk loads through UnetLoaderGGUF, text goes through T5 + CLIP-L, decoding uses a separate ae, and prompt strength is FluxGuidance (30) rather than cfg (fixed 1.0). So when the name ends in .gguf or contains flux, inpaint() swaps the whole graph. Miss one of the four files and flux_assets() tells you which one and where it belongs.

Three tiers, measured (same selection, same prompt, same floor): SD1.5 gives a cat whose fur is a single blob and a dog with melted legs; SDXL gets the anatomy and the shadow right, but rendered “a small cream puppy” as two dogs — adding one single reined it in; Flux returns one cream puppy, four legs on the floor, and a cat with individual hairs and readable eyes. Cost: 74–84 s per image.

Automatic prefers the SDXL inpaint tier (visibly better detail than SD1.5); Flux is never automatic — it is an order of magnitude slower and would make the plug-in look hung.

Six traps

all worked around

1. The mask is inverted.ComfyUI's LoadImage derives the mask from alpha (mask = 1 - alpha), so “repaint here” has to be transparent. Send a grey image and you get an all-zero mask — the run finishes and not one pixel moves.

2. Align to 8.A crop whose sides are not multiples of 8 gets truncated, comes back smaller than requested and pastes out of place.

3. The model has to match the conditioning node.An inpaint-only checkpoint was trained with holes in the picture and needs InpaintModelConditioning (mask and the masked image both go into the conditioning); a plain checkpoint takes VAEEncode + SetLatentNoiseMask. Pair a plain model with VAEEncodeForInpaint at denoise 1.0 and a 260×100 patch of forehead comes back with stringy eyebrow hairs, a few white streaks and a straight seam — measured 2026-11-24. With an inpaint model and the conditioning node, the same patch grows the eyebrow along its original direction.

4. Aspect ratio.SD only draws well near the ratios it was trained on. A 1024×400 (2.56:1) strip across the eyes makes SDXL fall back to flat poster art — a prompt of sunglasses came back as a green board with repeated white arrows. plan_canvas_rect() pads to ≤ 2:1 first, growing into real pixels where the image allows and only replicating edges at the border; that ring is masked out when pasting back.

5. Short side and context. Matching only the long side to 512 turns 1024×400 into 512×200 — far below SD 1.5's 512, and it comes back as rows of repeated shapes. A 32 px context is just as bad: the model cannot see what surrounds the hole, so it invents. Context is now 0.75× the selection's longer side (64 px minimum), and work_size() clamps both ends: the short side up to the family floor (SD 1.5 512 / SDXL 768), the long side down to the ceiling (768 / 1024). On a big photo with a small selection, fit_context() narrows the context first instead of shrinking the whole crop into mush.

6. One shot per click. Drawing a single candidate makes its failure rate your failure rate. The default is now three candidates per run (RepeatLatentBatch, sharing the model load), ranked on four signals: whether the seam is harder than its surroundings, whether the fill is softer or busier than the ring around it, the colour step across the edge, and any change outside the selection. The best one is shown; the others wait on the layer stack, hidden — click an eye to swap. The winner then gets two touches: a seam colour correction (low-frequency offsets only, generated detail untouched) and grain matching (adds noise on grainy photos, nothing on clean ones). Set Variations to 1 for the old one-shot behaviour.

Select by name

no tracing

AI Select by Name… never asks you to trace anything: type ear, left eye, the white shirt. The layer goes to ComfyUI and runs ComfyUI-RMBG's SAM2Segment — GroundingDINO turns the words into candidate boxes, SAM2 cuts a mask from them — and the mask comes back as a plain GIMP selection. Not a pixel is touched, so AI Inpaint, colour work, local blur and cut-out all work on it afterwards.

Measured on a 744×1120 portrait with sam2.1_hiera_tiny: 5.8 s for the 74×102 ear, edges matching a hand-drawn selection. Larger tiers give cleaner edges on busy backgrounds and take longer.

To add something next to the object, shift the selection.SAM2 outlines the object itself, not the empty space around it: select the whole ear and ask for an earring and you get a gold ring pressed onto the ear plus a black hole. Set Shift selection Y to +58 so the selection sits below the lobe, and it becomes a hoop hanging from the ear. To change the object itself (swap a shirt, erase a print), use the box as it is.

One-time setup: python tools/setup_comfy_sam2.py — installs groundingdino-py / hydra-core / omegaconf, downloads SAM2-tiny + GroundingDINO + bert-base-uncased (~1.2 GB via hf-mirror), and writes a custom_nodes/zz_bert_shim patch (transformers 5.x dropped BertModel.invert_attention_mask, which GroundingDINO calls). Restart ComfyUI afterwards.

AI Environment

any folder

AI Environment… opens with the state: reachable or not, which version, how many checkpoints — and where ComfyUI lives and which python it runs. If the path is wrong, Choose folder… picks it by hand (the folder holding main.py, or the wrapper folder holding ComfyUI/); the choice is saved, so you only do it once.

Start / Stop manage the process the plug-in started, One-click install… sets everything up the first time (about 10 GB: embedded Python + torch cu128 + ComfyUI + one checkpoint), Model folder opens models\checkpoints, Refresh re-probes and shows the log tail.

“Start ComfyUI automatically when it is not running” is on by default: before an AI pass the plug-in probes /system_stats, and if nothing answers it starts the server in the background from the folder you picked (no console window, output to comfyui.log) and waits for it. Only an explicitly chosen folder is used — never a guess: guessing once meant launching someone else's ComfyUI with the wrong Python.

Config: %APPDATA%\SuperMrWang\comfyui.json on Windows, ~/.config/SuperMrWang/comfyui.json elsewhere. The installer ships with the plug-in, in the ai-setup/ folder of the zip.

Measured

check_ai_inpaint*.py

tools/check_ai_inpaint.py runs 298 assertions against a local mock service (no GPU needed): mask direction, 8× alignment, canvas padding, scale limits, checkpoint family detection, workflow nodes and wiring, Chinese-to-English prompt handling, candidate scoring (insert and erase rules), failure paths.

tools/check_ai_inpaint_gimp.py (107 assertions) runs the procedure inside real GIMP 3.2: selection → prompt → new layer, mask and channel, the candidate picker's cropping and selection, and a bogus checkpoint name being rejected by the dropdown.

Speed (RTX 3070 Ti, SDXL, 25 steps, 1024×512): 8.7 s. The same size on CPU fallback is 94 s (measured at 384×256) — it works, but not for batches.

Requirements

A running ComfyUI and one checkpoint. The plug-in uses only the standard library over HTTP — no Python dependencies; the HTTP and PNG code lives in plugin/_shared/ai_client.py, and the regression suite swaps the real service for tools/mock_comfy.py.

Chinese UI is complete for this plug-in: menus, the parameter dialog and the status messages are all translated in po/zh_CN.po.
