镜头校正

plugin/lens-correction 变形 Distort

PS「滤镜 → 镜头校正」里真正会动的三项：桶形 / 枕形畸变、 暗角、横向色差。分开做要重采样三遍、画质掉三轮；这里一个算子 一次采样全解决，参数挂在图层滤镜栈上，原像素一个字节不动。

菜单位置
  • SuperMrWang → Distort → 镜头校正…
  • 图层右键 → SuperMrWang → Distort → 镜头校正…

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-lens-correction(image, drawables, settings, output)

标准 PDB 过程，参数留空走默认值。

依赖

用本项目自己的算子 lb:lens-correction（GIMP 3 只带 gegl:lens-distortion，只管畸变、没有暗角与色差）。插件包里已附带这个模块，按 readme 放进 GEGL 模块目录即可。

  • lb:lens-correction

三个页签，一个画面

拖哪页看哪页

对话框左边是三个页签，右边是实时预览——每动一下滑杆，预览立刻跟着变， 三页共用同一次重采样，所以畸变、暗角、色差叠在一起的效果就是成品的样子。

畸变：两个系数 k1、k2，外加「自动缩放」和「额外缩放」。
暗角：强度、起始半径、羽化宽度。
色差：红通道与蓝通道各自的径向偏移（像素）。

左下角两个下拉管全局：重采样（默认 Nohalo，无振铃）与 越界（默认拉边）。输出三档：非破坏滤镜（默认）、覆盖当前图层、 复制到新图层。

半径怎么量

四角 = 1

所有半径都按画面半对角线归一化，所以四个角恰好落在 r = 1。 用短边归一化的话，同一组 k1 在 4:3 和 3:2 上看到的角落形变不一样——而角落 正是畸变最明显的地方，那里不一致，参数就没法挪到别的图上用。

暗角按输出半径算，不按畸变后的源半径：它描述的是成像面上的照度衰减， 跟几何校正无关。所以先调畸变再压暗角，暗角的位置不会跟着跑。

畸变：k1 往哪边拖

正 = 收缩

s(r) = 1 + k1·r² + k2·r⁴，源坐标是 c + (p−c)·s(r)。 k1 为正：从更外面取样，画面收缩——这就是去桶形（广角镜头的 直线被拉弯，校正后恢复笔直）。k1 为负：画面膨胀，加桶形 / 鱼眼味道。

k2 是 r⁴ 项，只在角落附近咬得住：k1 修不干净的「角落还差一点」用它补， 常见量级 0.01–0.05。两个滑杆的量程都停在 ±0.5，因为再大 r → s(r) 就不再单调——同一块画面会被折回去两次，边缘出现镜像 重影，那不是「更强的效果」，是碎图。

自动缩放默认开着：zoom = 1/(1 + k1 + k2)，把四角兜回 画面里，不会留下四个透明缺口。关掉就能看见那些缺口——这也是它为什么默认开。

暗角：别用硬边

增益是 1 + 强度/100 · smoothstep(起点, 起点+羽化, r)：负值压暗、 正值提亮，−100 就是角落全黑。起始半径默认 0.55、羽化 0.45。

羽化太小会看到一圈硬边同心环——这是暗角最容易做丑的地方， 也是这里坚持用 smoothstep 而不是线性斜坡的原因。想让暗角更"自然"， 把起点往外推（0.7 以上）、羽化拉到 0.5，效果集中到最后 30% 的画面边缘。

提亮方向也有用：镜头全开时的边缘失光，用正值往回补，比手动画径向渐变准。

色差：绿通道不动

按角落像素给

红、蓝两个通道各自沿半径缩放：r·(1 + ca/半对角线·r²)。 位移按角落处的像素给——ca-red = 2 表示红通道在四角向外 偏 2 px，中心几乎不动。24 MP 的机器上常见量级是 ±1–3 px。

绿通道不参与。横向色差是镜头色散让三个颜色的成像尺寸略有不同， 绿通常落在中间、也是合焦参考；挪它等于把整幅画面往外拉，只会更糊。 红蓝一般反号（一边大一边小），紫边就是这么来的。

预览是缩到 560 长边再挂滤镜的，色差按像素给会跟着缩没——所以预览时按 「原宽 / 预览宽」放大回去，否则你在预览里根本看不见那 1 px 的紫边。

实测

1600×2400

纯暗角 0.05 s、全默认 0.09 s（这两档走快路径，不采样）； 只调畸变 1.10 s、畸变 + 色差 2.69 s、换成双线性 0.92 s。 768×1024 上是 0.05 / 0.07 / 0.22 / 0.56 s。

色差让采样从 1 次变 3 次，这就是它贵的原因——不需要时把它留成 0。 预览在 560 长边上一次约 30 ms，拖滑杆不掉帧。

回归 check_lens_correction_gimp.py 28 项： 恒等逐字节、k1 两个方向的取样半径、自动缩放兜角、两档越界、暗角三点、 色差只动红蓝、极端参数不炸。

脚本怎么调

settings = 一份 JSON

交互对话框写的就是一个 JSON 串，键名与算子属性同名（连字符写法）：

lb-plugin-lens-correction 图层 settings="{\"k1\": 0.08, \"vignette\": -28, \"ca-red\": 1.2, \"ca-blue\": -1.2}" output=replace

output 三档：filter 只写参数（能再改）、 replace 烤进当前层、new 复制一层再烤。漏写的键 取默认值，认不出来的键忽略——所以同一份串可以跨版本用。

没有做的：镜头配置文件（.lcp / lensfun）按 EXIF 自动匹配、几何校正 （梯形 / 旋转）、以及用边缘检测自动估 k1 的「自动」按钮。这三件事都不是 重采样的问题，是「参数从哪来」的问题。

Lens Correction

plugin/lens-correction Distort Retouch

The three Lens Correction controls people actually turn: barrel / pincushion distortion, vignetting and lateral chromatic aberration. Done separately that is three resamples and three rounds of softness; here it is one operator, one sample, live on the filter stack with the original pixels untouched.

Menu location
  • SuperMrWang → Distort → Lens Correction…
  • Layer right-click → SuperMrWang → Distort → Lens Correction…

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-lens-correction(image, drawables, settings, output)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

Uses this project's own lb:lens-correction operator (GIMP 3 only ships gegl:lens-distortion, which has no vignette and no CA). The module is inside the plug-in zip — drop it into the GEGL module folder.

  • lb:lens-correction

Three tabs, one picture

drag and watch

The dialog puts three tabs on the left and a live preview on the right: every slider moves the picture immediately, and because all three share a single resample, what you see is the combined result — not three filters previewed in isolation.

Distortion: two coefficients, k1 and k2, plus auto scale and an extra scale.
Vignette: amount, midpoint, feather.
Chromatic aberration: separate radial shifts for red and blue, in pixels.

Two dropdowns at the bottom are global: resampling (Nohalo by default, no ringing) and out of bounds (clamp by default). Output goes three ways: live filter (default), bake into this layer, duplicate to a new layer.

How the radius is measured

corners = 1

Every radius is normalised to the half diagonal, so the four corners land exactly at r = 1. Normalising to the short edge would make one k1 pair produce different corner shapes on 4:3 and 3:2 — and the corners are where distortion shows most, so that is the one place the numbers must be portable between images.

The vignette is computed from the output radius, not the distorted source radius: it describes illumination falloff on the sensor and has nothing to do with the geometry. Correct the distortion first and the vignette stays where it was.

Which way to drag k1

positive shrinks

s(r) = 1 + k1·r² + k2·r⁴, and the source coordinate is c + (p−c)·s(r). Positive k1 samples from further out and shrinks the picture — that is removing barrel distortion, which straightens the bowed lines of a wide lens. Negative k1 inflates it: barrel / fisheye character.

k2 is the r⁴ term and only bites near the corners: it finishes what k1 leaves behind, typically 0.01–0.05. Both sliders stop at ±0.5 because beyond that r → s(r) stops being monotonic — one slice of the picture gets sampled twice and the border mirrors. That is not a stronger effect, it is a broken image.

Auto scale is on by default: zoom = 1/(1 + k1 + k2) pulls the corners back into the frame so there are no transparent notches. Turn it off to see them — which is exactly why it is on.

Vignette: avoid the hard ring

The gain is 1 + amount/100 · smoothstep(mid, mid+feather, r): negative darkens, positive lightens, −100 is a black corner. Defaults are midpoint 0.55 and feather 0.45.

A feather that is too small leaves a visible concentric ring — the easiest way to make a vignette look cheap, and the reason this uses smoothstep rather than a linear ramp. For something more natural, push the midpoint past 0.7 and the feather to 0.5, so the effect lives in the last 30% of the frame.

Lightening is useful too: open a fast lens wide and the corners fall off; a positive amount puts the brightness back more accurately than painting a radial gradient by hand.

CA: green stays put

pixels at the corners

Red and blue are each scaled along the radius: r·(1 + ca/halfdiag·r²). The shift is given in pixels at the corners — ca-red = 2 moves red 2 px outward at the corners while the centre barely moves. On a 24 MP frame the usual amount is ±1–3 px.

Green is not involved. Lateral CA means the three colours image at slightly different scales; green sits in the middle and is the focus reference, so shifting it would drag the whole picture outward and only make it softer. Red and blue normally take opposite signs — that mismatch is what a purple fringe is.

The preview runs on a 560 px copy, where a pixel-denominated shift would shrink to nothing — so it is scaled back by original width / preview width, or you would never see the fringe you are fixing.

Measured

1600×2400

Vignette only 0.05 s, everything default 0.09 s (both take the copy fast path and never sample); distortion alone 1.10 s, distortion + CA 2.69 s, with bilinear instead 0.92 s. On 768×1024: 0.05 / 0.07 / 0.22 / 0.56 s.

CA triples the sampler cost (1 sample becomes 3) — leave it at zero when you do not need it. The preview costs about 30 ms per update at 560 px, so dragging stays responsive.

Regression check_lens_correction_gimp.py, 28 checks: identity is byte-for-byte, sample radius in both k1 directions, auto scale keeping the corners opaque, two edge policies, three vignette points, CA moving only red and blue, extreme parameters not exploding.

Scripting

settings is one JSON string

The dialog writes exactly one JSON string, keyed by the operator's own property names (hyphenated form):

lb-plugin-lens-correction 图层 settings="{\"k1\": 0.08, \"vignette\": -28, \"ca-red\": 1.2, \"ca-blue\": -1.2}" output=replace

output takes filter (parameters only, re-editable), replace (bake into this layer) or new (duplicate then bake). Missing keys fall back to defaults and unknown keys are ignored, so one string survives across versions.

Not implemented: lens profile lookup (.lcp / lensfun from EXIF), geometric correction (perspective / rotate), and the "Auto" button that estimates k1 from edge detection. None of those are resampling problems — they are about where the numbers come from.
