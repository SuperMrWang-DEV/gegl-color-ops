Split Channels

plugin/split-channels 通道 图层转换

一个图层一次拆成多条通道：R、G、B、Alpha 各存一条，通道面板里排好， 原图层自动隐藏留作对照。原生做法是逐条「新建通道 → 复制 → 粘贴 → 合并」， 四条就是十六步。

菜单位置
  • SuperMrWang → Convert → Split Channels
  • 图层右键 → SuperMrWang → Convert → Split Channels

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-split-channels( image, drawables, include-alpha, hide-source, prefix)

标准 PDB 过程，参数留空走默认值。

依赖

不依赖任何自研算子：读一次图层数据后按分量切片，只调 GIMP 自己的通道 PDB。

一次拆完四路

R · G · B · Alpha

默认按分量拆四条，命名是「图层名 + 后缀」，通道面板里一眼能认出来。同名 通道已存在时自动加序号，不会覆盖你之前存的东西。

图层「photo」
  ├ photo R       红分量
  ├ photo G       绿分量
  ├ photo B       蓝分量
  └ photo Alpha   透明分量

灰度图不硬凑三份

灰度图里 R = G = B，拆三路等于三条全黑一样的通道，没有意义——这种图只拆 一条 Gray；只有带透明时才多一条 Alpha。彩色图默认四路，把 「含 Alpha」关掉就是三路。

源图层默认隐藏

拆完把原图层眼睛关掉、不删除：画布上看到的就是拆分结果，想对照随时点回来。 不需要这个行为就把「隐藏源图层」关掉，原图和通道并存。

偏移的小图层也照样处理：通道恒为画布大小，图层没盖到的地方补黑， 不会出现「通道尺寸跟着图层走、贴上去错位」的老问题。

和 Layer to Channel 的分工

一条 vs 多条

Layer to Channel 把整层压成一条灰度通道（恒按亮度），适合 「这张灰度图当蒙版存档」。Split Channels 保留分量本身、一次 出多条，适合「分开看 R/G/B 各自的分布」「单独修某一路」。两者产物都在通道 面板里，可以并存。

实测

tools/check_split_channels.py 31 条断言跑在真实 GIMP 3.2 里： 四路内容与源图层同名通道逐项相等（索引错位一位就会露馅）、灰度图只出 Gray、无 alpha 图层不出 Alpha、偏移图层外部补零、有选区时通道不被截断、 前缀与重名序号。

速度：600 万像素拆四路约 0.9 秒（一次读完整层再切片，不是每路读一遍）。

Split Channels

plugin/split-channels Channels Convert

One layer becomes several channels in a single step: R, G, B and Alpha each get their own channel, lined up in the Channels dock, with the source layer hidden so you can still compare. The native route is channel-by-channel "new channel → copy → paste → merge" — sixteen steps for four channels.

Menu location
  • SuperMrWang → Convert → Split Channels
  • Layer right-click → SuperMrWang → Convert → Split Channels

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-split-channels( image, drawables, include-alpha, hide-source, prefix)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

No dependency on this project's operators: the layer is read once and sliced per component; only GIMP's own channel PDB is used.

All four at once

R · G · B · Alpha

Each component becomes its own channel named "layer + suffix", so the Channels dock stays readable. A name that is already taken gets a number instead of overwriting what you stored earlier.

layer "photo"
  ├ photo R       red
  ├ photo G       green
  ├ photo B       blue
  └ photo Alpha   transparency

Grayscale images do not fake three

On a greyscale image R = G = B, so three channels would be three identical copies — it produces a single Gray channel instead, plus Alpha when the layer actually has transparency. Colour layers give four by default; turn "Include Alpha" off for three.

The source layer hides itself

It is hidden, never deleted: the canvas shows you the split result and one click brings the original back. Turn "Hide source layer" off if you want both.

Small offset layers work too: channels are always canvas-sized and the area the layer does not cover stays black, so nothing lands at the wrong place.

Versus Layer to Channel

one vs many

Layer to Channel flattens the whole layer into one greyscale channel (always luminance) — for "keep this greyscale image as a mask". Split Channels keeps the components themselves and produces several — for "look at the R/G/B distributions separately" or "retouch one channel only". Both leave their results in the Channels dock and can coexist.

Measured

tools/check_split_channels.py runs 31 assertions inside a real GIMP 3.2: each channel equals the same component of the source layer (an off-by-one index shows up immediately), greyscale yields Gray only, no-alpha layers yield three, offset layers are padded with black, the channel is not clipped by an active selection, and prefix plus duplicate numbering behave.

Speed: four channels from six megapixels take about 0.9 s — the layer is read once and then sliced, not read once per channel.
