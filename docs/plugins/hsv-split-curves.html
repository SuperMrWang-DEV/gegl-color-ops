HSV Split (Curves)

plugin/hsv-split-curves 曲线 Shortcut 快捷方式

GIMP 的曲线只能选 R / G / B / Alpha——想单独曲「色相」或 「饱和度」没有入口。这个插件把图层换成一张数据图（红=S、绿=V、蓝=色相）， 三条曲线各管一个分量，再由一个算子解回颜色：恒等时逐像素还原原图， 改哪条曲线就只动那个分量。

菜单位置

两处
  • 颜色 → SuperMrWang → Shortcut → HSV Split (Curves)
  • 图层右键 → SuperMrWang → Shortcut → HSV Split (Curves)

两处是同一个动作，处理的是当前选中的那一个图层。图层组不行—— 组没有自己的像素，会直接报错并提示先合并。

脚本调用

lb-plugin-hsv-split-curves(image, drawable, group)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活，装插件时它们必须已注册（build.sh 或 dll 包里都有）：

  • lb:hsv-dual
  • lb:hsv-compose
  • gimp:curves

生成的结构

一层
HSV split          组 · 穿透（带 alpha 时组上还有蒙版）
  └─ 1 · HSV S/V/H   模式 正常   ← 一条算子链算完整 HSV 色
  └─ 原图层（不动，可以隐藏）

滤镜栈：decompose（lb:hsv-dual）→ S 曲线（红） → V 曲线（绿） → H 曲线（蓝） → compose （lb:hsv-compose）。三个分量各占一个通道，互不串门。

为什么只有一层

旧版是三张分量层，每层 extract → 曲线 → encode， 再靠 HSV 的三个分量混合模式叠回去。能用，但三层就是三次编码、三次量化， 8 位图上还得靠组内浮点缓冲才不偏色。现在 S、V、H 一起进 lb:hsv-compose：一层、五条滤镜，算完就是最终颜色。

三个分量本来就分不开——V = max、S = (max−min)/V、 色相由三者的比例决定。与其让混合模式逐层去猜，不如让一个算子同时读到 三者，一次算清。

实测精度

32 位浮点图恒等往返 0.0002 码；8 位图 0.49 码（就是量化本身）。 只改 S 曲线时，结果的 V 与色相偏差 < 0.001 码——三个分量确实 互不干扰。

把原图层隐藏掉，这一层自己就能还原（半透明区域靠组蒙版）。

通道约定是硬的：S 在红、V 在绿、色相在蓝。改曲线时选错通道， 等于把另一个分量的数据当曲线输入。色相曲线必须连续（两端相等、中间不跳变）， 整体旋转色相请用 lb:hue-saturation。依赖 lb:hsv-dual / lb:hsv-compose 两个算子，缺了会直接报错。
