HSV Split (Curves)

plugin/hsv-split-curves 曲线 Retouch 修饰

GIMP 的曲线只能选 R / G / B / Alpha——想单独曲「色相」或 「饱和度」没有入口。这个插件把图层换成一张数据图（红=S、绿=V、蓝=色相）， 三条曲线各管一个分量，再由一个算子解回颜色：恒等时逐像素还原原图， 改哪条曲线就只动那个分量。想要「每层能单独关掉」的老做法，菜单里选 · multi 那条就行。

菜单位置
  • SuperMrWang → Retouch → HSV Split (Curves) · single
  • SuperMrWang → Retouch → HSV Split (Curves) · multi
  • 图层右键 → SuperMrWang → Retouch → 同上两条

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-hsv-split-curves(image, drawables, group) lb-plugin-hsv-split-curves-multi(image, drawables, group)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

  • lb:hsv-dual
  • lb:hsv-compose
  • gimp:curves

两种模式

两条菜单

菜单里是两条独立的过程——… · single 与 … · multi， 点哪条就是哪个模式。对话框里只剩「收进图层组」一个开关。

single   HSV split            组 · 穿透（带 alpha 时组上还有蒙版）
           └─ 1 · HSV S/V/H     模式 正常      ← 一条算子链算完整 HSV 色

multi    HSV split            组 · 穿透（带 alpha 时组上还有蒙版）
           ├─ 3 · Value         模式 HSV 明度
           ├─ 2 · Saturation    模式 HSV 饱和度
           └─ 1 · Hue           模式 HSV 色相

single 的滤镜栈：decompose（lb:hsv-dual）→ S 曲线（红） → V 曲线（绿） → H 曲线（蓝） → compose（lb:hsv-compose）。三个分量各占一个通道，互不串门。

single 还是 multi

single 把 S、V、H 一起送进 lb:hsv-compose：一层、 五条滤镜，一次算完，只编码一次，误差最小。

multi 是三张分量层，每层 extract → 曲线 → encode，再靠 HSV 的三个分量混合模式叠回去。三层就是三次 编码、三次量化；换来的是每层都能单独关——拨掉 Hue 层就只剩调过 S/V 的 中间结果，判断在改什么时很直观。

两个模式的恒等曲线都是平滑样条（SMOOTH，三个控制点 (0,0)、(128,128)、(255,255)）。 三个点都踩在 8 位格点上，所以这条平滑曲线与「铺 256 个采样点」在数值上 完全等价——恒等往返差异见下。

实测精度

single：32 位浮点图恒等往返 0.0002 码；8 位图 0.49 码（就是 量化本身）。只改 S 曲线时，结果的 V 与色相偏差 < 0.001 码—— 三个分量确实互不干扰。

multi：浮点图三层合成的恒等往返 0.0015 码，隐藏原图层后照样叠得回去。 比 single 大七倍——多出来的是三次编码来回的余数，但仍然在千分之一码量级， 肉眼无感。8 位图上两个模式都是 0.49 码，量化盖过一切。所以精度上 single 更准，multi 换来的是「每层能单独关」。

通道约定是硬的：S 在红、V 在绿、色相在蓝。改曲线时选错通道， 等于把另一个分量的数据当曲线输入。色相曲线必须连续（两端相等、中间不跳变）， 整体旋转色相请用 lb:hue-saturation。single 依赖 lb:hsv-dual / lb:hsv-compose；multi 只用 GIMP 自带的 gegl:component-extract 与 HSV 分量混合模式。

HSV Split (Curves)

plugin/hsv-split-curves Curves Retouch

GIMP's curves only offer R / G / B / Alpha — there is no way to curve hue or saturation on its own. This plug-in turns the layer into a data image (red = S, green = V, blue = hue), gives each component its own curve, and one operator turns it back: at identity the original is restored pixel for pixel, and moving a curve moves only that component. Pick the · multi menu entry if you want the old "every layer switchable" layout.

Menu location
  • SuperMrWang → Retouch → HSV Split (Curves) · single
  • SuperMrWang → Retouch → HSV Split (Curves) · multi
  • Layer right-click → SuperMrWang → Retouch → same as the two above

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-hsv-split-curves(image, drawables, group) lb-plugin-hsv-split-curves-multi(image, drawables, group)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

  • lb:hsv-dual
  • lb:hsv-compose
  • gimp:curves

Two modes

two menu entries

The menu holds two separate procedures — … · single and … · multi — and the one you click is the mode you get. The dialog has a single switch left: put everything in a layer group.

single  HSV split group · pass-through (plus a mask when there is alpha)
 └─ 1 · HSV S/V/H mode  Normal  ← one operator chain computes the whole HSV colour

multi   HSV split group · pass-through (plus a mask when there is alpha)
 ├─ 3 · Value mode       HSV value
 ├─ 2 · Saturation mode  HSV saturation
 └─ 1 · Hue mode         HSV hue

The single stack is: decompose (lb:hsv-dual) → S curve (red) → V curve (green) → H curve (blue) → compose (lb:hsv-compose). Each component owns one channel and none of them leaks into another.

single or multi

single sends S, V and H into lb:hsv-compose together: one layer, five filters, one encode, the smallest error.

multi is three component layers, each doing extract → curve → encode, stacked back with HSV's three component blend modes. Three layers means three encodes and three quantisations; what you buy is being able to switch any layer off — turn off the Hue layer and you see the intermediate result with only S/V changed, which makes it obvious what you are editing.

Both modes use smooth splines for the identity curve (SMOOTH, three control points at (0,0), (128,128), (255,255)). All three sit on the 8-bit grid, so the spline is numerically identical to "256 sample points" — see the round-trip figures below.

Measured precision

single: identity round trip 0.0002 codes on a 32-bit float image; 0.49 codes on 8-bit, which is the quantisation itself. Moving only the S curve leaves V and hue within < 0.001 codes — the three components really are independent.

multi: the three-layer identity round trip measures 0.0015 codes in float, and it still stacks back with the original layer hidden. That is seven times the single figure — the leftover from three encode passes — but still in the thousandths of a code, invisible to the eye. In 8-bit both modes land on 0.49 codes where quantisation dominates. So single is more accurate; multi trades that for per-layer switches.

Watch out

The channel convention is hard: S in red, V in green, hue in blue. Pick the wrong channel for a curve and you feed one component's data into another. The hue curve must stay continuous (equal at both ends, no jumps in the middle); for a global hue rotation use lb:hue-saturation.

single depends on lb:hsv-dual / lb:hsv-compose; multi uses only GIMP's own gegl:component-extract and the HSV component blend modes.
