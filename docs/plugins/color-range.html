Color Range（色彩范围）

plugin/color-range 蒙版 Mask

GEGL 的算子参数是静态的：lb:color-mask-select 里高光、 阴影、中间调各有一组限值，GIMP 的通用对话框会把四根 0–255 的滑杆 一起摆出来，切换「选择颜色」时一根都不动。这个插件换成自己搭的 对话框：选颜色系只给容差，选高光只给一根「范围」且默认 192， 选阴影是 64，选中间调是上下限 64 / 192。

菜单位置
  • SuperMrWang → Mask → Color Range
  • 图层右键 → SuperMrWang → Mask → Color Range

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-color-range(image, drawables)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

  • lb:color-mask-select

为什么需要一层壳

静态 vs 联动

GEGL 的属性声明是编译期固定的：property_enum 和四个 property_int 之间没有任何联动机制，对话框也没法因为枚举变了 就换掉别的控件。所以算子那边只能四根杆常驻，选「红色」时那四根依旧 占着界面、全程无效。

能真正联动的是程序自己的 GTK 对话框。像素运算仍然交给 lb:color-mask-select——壳只负责「哪个模式该显示哪几根杆、 各自从多少起步」，所以两条入口算出来的像素完全一致。

每个模式各自的起点

  • 红 / 黄 / 绿 / 青 / 蓝 / 洋红：颜色容差 50、最低彩度 0（范围是色相环，没有阈值杆）
  • 高光：范围 192（亮度 ≥ 192 算高光）
  • 阴影：范围 64（亮度 ≤ 64 算阴影）
  • 中间调：下限 64 / 上限 192
  • 自定颜色：取色按钮（默认纯红）+ 容差 + 最低彩度

切模式只换页，各页自己记住自己的值：改过高光的 192 再切到阴影、切回来， 还是改过之后的数。

预览与落地

红色叠加

拖参数时画面上是红色叠加实时预览（60 ms 内连续改动合并成一次重算）。 按「确定」时先把叠加关掉再合并，红色不会被烤进图层；蒙版写进 图层 alpha。按「取消」把预览滤镜整个撤掉，连中途补上的 alpha 通道也回滚。

与非破坏的区别：这里是一次性应用，合并后不能回改。想随时改参数， 用菜单里的 lb:color-mask-select 算子版本挂成滤镜——同一份 参数、同一份像素，只是界面朴素。

依赖 lb:color-mask-select；缺算子会明确报错并给出装包提示， 不会静默什么都不做。图层组没有像素，会拒绝并提示先合并。

Color Range

plugin/color-range Mask Mask

GEGL operator properties are static: lb:color-mask-select holds a set of limits for highlights, shadows and midtones, and GIMP's generic dialog displays all four 0–255 sliders at once, none of them changing when you switch the target. This plug-in replaces it with its own dialog: pick a hue family and you get tolerance only, pick highlights and you get one range slider defaulting to 192, shadows 64, midtones a low of 64 and a high of 192.

Menu location
  • SuperMrWang → Mask → Color Range
  • Layer right-click → SuperMrWang → Mask → Color Range

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-color-range(image, drawables)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

  • lb:color-mask-select

Why a shell is needed

static vs dynamic

GEGL property declarations are fixed at compile time: there is no mechanism linking a property_enum to four property_ints, and a dialog cannot swap other widgets out when the enum changes. The operator therefore has to keep all four sliders permanently, and with "red" selected they still occupy the interface while doing nothing at all.

What can really react is the program's own GTK dialog. The pixel work still goes to lb:color-mask-select — the shell only decides "which mode shows which sliders, and what each starts at", so both entry points compute identical pixels.

Starting point per mode

  • Red / yellow / green / cyan / blue / magenta: colour tolerance 50, minimum chroma 0 (the range is the hue circle, there is no threshold slider)
  • Highlights: range 192 (luminance ≥ 192 counts as highlight)
  • Shadows: range 64 (luminance ≤ 64 counts as shadow)
  • Midtones: low 64 / high 192
  • Custom colour: picker button (pure red by default) + tolerance + minimum chroma

Switching modes only swaps the page, and each page remembers its own values: change the highlight 192, switch to shadows, come back — it is still your number.

Preview and commit

red overlay

While you drag, the canvas shows a live red overlay (changes within 60 ms are merged into one recompute). Pressing OK turns the overlay off before merging, so no red is baked into the layer; the mask is written into the layer's alpha. Cancel removes the preview filter entirely, including any alpha channel added along the way.

The difference from a non-destructive filter: this applies once and cannot be re-tuned after merging. If you want live parameters, attach the menu's lb:color-mask-select operator as a filter — same parameters, same pixels, plainer interface.

Notes

Depends on lb:color-mask-select; if the operator is missing the plug-in fails with an explicit error and a hint about the download rather than silently doing nothing. Layer groups have no pixels, so it refuses and asks you to merge first.
