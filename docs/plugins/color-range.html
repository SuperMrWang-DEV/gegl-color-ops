Color Range（色彩范围）

plugin/color-range 蒙版 Mask

GEGL 的算子参数是静态的：lb:color-mask-select 里高光、 阴影、中间调各有一组限值，GIMP 的通用对话框会把四根 0–255 的滑杆 一起摆出来，切换「选择颜色」时一根都不动。这个插件换成自己搭的 对话框：选颜色系只给容差，选高光只给一根「范围」且默认 192， 选阴影是 64，选中间调是上下限 64 / 192。

菜单位置

多条
  • SuperMrWang → Mask → Color Range
  • 图层右键 → SuperMrWang → Color Range

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行—— 组没有自己的像素，会直接报错并提示先合并。

脚本调用

lb-plugin-color-range(image, drawables)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

  • lb:color-mask-select

为什么需要一层壳

静态 vs 联动

GEGL 的属性声明是编译期固定的：property_enum 和四个 property_int 之间没有任何联动机制，对话框也没法因为枚举变了 就换掉别的控件。所以算子那边只能四根杆常驻，选「红色」时那四根依旧 占着界面、全程无效。

能真正联动的是程序自己的 GTK 对话框。像素运算仍然交给 lb:color-mask-select——壳只负责「哪个模式该显示哪几根杆、 各自从多少起步」，所以两条入口算出来的像素完全一致。

每个模式各自的起点

  • 红 / 黄 / 绿 / 青 / 蓝 / 洋红：颜色容差 50、最低彩度 0（范围是色相环，没有阈值杆）
  • 高光：范围 192（亮度 ≥ 192 算高光）
  • 阴影：范围 64（亮度 ≤ 64 算阴影）
  • 中间调：下限 64 / 上限 192
  • 自定颜色：取色按钮（默认纯红）+ 容差 + 最低彩度

切模式只换页，各页自己记住自己的值：改过高光的 192 再切到阴影、切回来， 还是改过之后的数。

预览与落地

红色叠加

拖参数时画面上是红色叠加实时预览（60 ms 内连续改动合并成一次重算）。 按「确定」时先把叠加关掉再合并，红色不会被烤进图层；蒙版写进 图层 alpha。按「取消」把预览滤镜整个撤掉，连中途补上的 alpha 通道也回滚。

与非破坏的区别：这里是一次性应用，合并后不能回改。想随时改参数， 用菜单里的 lb:color-mask-select 算子版本挂成滤镜——同一份 参数、同一份像素，只是界面朴素。

依赖 lb:color-mask-select；缺算子会明确报错并给出装包提示， 不会静默什么都不做。图层组没有像素，会拒绝并提示先合并。
