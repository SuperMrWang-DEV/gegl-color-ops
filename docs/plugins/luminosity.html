明度蒙版

plugin/luminosity 蒙版 Retouch 修饰

明度蒙版把「哪块该亮、哪块该暗」从一句形容变成可以随时载入的选区： 按亮度切七刀，全在通道面板里，双击就选中。提亮天空、压暗地面、单独修中间调， 都不用再手画蒙版。

菜单位置
  • SuperMrWang → Luminosity Masks → 生成七条明度通道
  • 图层右键 → SuperMrWang → Luminosity Masks → 同上

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-luminosity-mask(image, drawables)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

生成什么

七条通道
明度 · 亮部 1（> 64）      最宽的高光蒙版
明度 · 亮部 2（> 128）
明度 · 亮部 3（> 192）     只剩最亮的那截
明度 · 暗部 1（< 192）      最宽的暗部蒙版
明度 · 暗部 2（< 128）
明度 · 暗部 3（< 64）
明度 · 中间调（64–192）    两端渐隐的梯形

全部落在通道面板里，不是图层——这是它们在 PS 里的原生形态。双击任意 一条就变成选区，曲线、色阶、锐化都只作用在选中的范围里。

用法就三步

1　选中图层 → 点菜单项，七条一次建好
2　双击通道 → 变成选区
3　复制一层，在选区里调曲线

要挂成图层蒙版：选中通道后右键图层（配合 Channel to Mask）。 重跑会先删掉上一批同名通道，不会越点越多。

七条各挑什么

线性色阶拉伸
通道怎么算挑出什么
亮部 1（> 64）亮度 64–255 拉到 0–255 天空、受光面、白墙——所有不在阴影里的地方。最常用的一条
亮部 2（> 128）128–255 明确的高光。压高光、加云层细节
亮部 3（> 192）192–255 云、灯、反光。只想动最亮的那一小块时用
暗部 1（< 192）亮部 3 的反相 从阴影一直到中间调的大片区域
暗部 2（< 128）亮部 2 的反相 明确的暗部。压暗四周做暗角
暗部 3（< 64）亮部 1 的反相 死黑。提暗部细节、去噪点就用这条
中间调（64–192）亮部 1 减亮部 3，再归一化 主体所在的那一层，两端渐隐——加对比不碰高光和阴影

为什么是通道，不是图层

明度蒙版在 PS 里本来就是通道，「载入成选区」是它的用法。做成灰度图层也能看， 但每次都要手动「图层转选区」，多一步就少用一次。

七条通道共用一次明度提取：复制图层 → 去色（明度加权）→ 读一遍像素 → 套七张映射表 → 删掉副本。所以七条是同一份亮度切的，不会因为算了两遍而对不齐。

两个实现细节

中间调是相减，不是相乘。两条亮部相乘，峰值只有 170 左右，蒙版灰蒙蒙的， 当蒙版用时还得再补一条曲线；相减再按峰值归一化，峰值才是纯白、两端纯黑。

按 8 位生成（256 级）。蒙版本身是连续渐变，256 级在绝大多数叠加里看不出来。 真遇上 16 位风光修图露台阶，可以改走 GEGL 色阶，让精度跟着图像走。

Luminosity Masks

plugin/luminosity Mask Retouch

Luminosity masks turn "this part should be brighter" from a description into a selection you can load at any time. Seven channels cut by brightness, all in the channels dialog: double-click one and it becomes a selection. Brighten the sky, darken the ground, work on the midtones alone -- no more hand-painted masks.

Menu location
  • SuperMrWang → Luminosity Masks → 生成七条明度通道
  • Layer right-click → SuperMrWang → Luminosity Masks → 同上

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-luminosity-mask(image, drawables)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

What gets built

seven channels
Luminosity · Lights 1 (> 64)     widest highlight mask
Luminosity · Lights 2 (> 128)
Luminosity · Lights 3 (> 192)     only the brightest
Luminosity · Darks 1 (< 192)      widest shadow mask
Luminosity · Darks 2 (< 128)
Luminosity · Darks 3 (< 64)
Luminosity · Midtones (64-192)   trapezoid, fading at both ends

They land in the channels dialog, not the layer stack -- that is their native form in Photoshop too. Double-click one to load it as a selection; curves, levels and sharpening then act only inside it.

Three steps to use it

1　Select a layer, run the menu item -- all seven are built
2　Double-click a channel to load it as a selection
3　Duplicate the layer, adjust the curve inside the selection

To hang one as a layer mask: select the channel, then right-click the layer (pairs with Channel to Mask). Re-running deletes the previous batch first, so the channels never pile up.

What each one selects

linear level stretch
ChannelHow it is computedWhat it picks
Lights 1 (> 64)luminance 64-255 stretched to 0-255 Sky, lit surfaces, white walls -- everything outside the shadows. The workhorse
Lights 2 (> 128)128-255 Clear highlights. Pull down highlights, recover cloud detail
Lights 3 (> 192)192-255 Clouds, lamps, specular hits. For touching only the brightest patch
Darks 1 (< 192)inverse of Lights 3 Everything from the shadows up into the midtones
Darks 2 (< 128)inverse of Lights 2 Clear shadow areas. Darken the edges into a vignette
Darks 3 (< 64)inverse of Lights 1 Crushed blacks. Lift shadow detail, clean up noise there
Midtones (64-192)Lights 1 minus Lights 3, normalised The tonal band the subject lives in, fading at both ends -- add contrast without touching highlights or shadows

Why channels, not layers

A luminosity mask is a channel in Photoshop; "load as selection" is how it is used. Gray layers work too, but every use costs an extra "layer to selection" step -- one extra step means it gets used less.

All seven share one luminance pass: duplicate the layer, desaturate (weighted), read the pixels once, apply seven look-up tables, delete the copy. So they are cut from the same brightness and cannot drift apart.

Two implementation details

Midtones subtract, they do not multiply. Multiplying two highlight masks peaks around 170 -- a muddy grey that needs another curve before it is usable as a mask. Subtracting and renormalising puts the peak at pure white with pure black at both ends.

Built at 8 bits (256 levels). A mask is a continuous gradient and 256 levels are invisible in almost any composite. If 16-bit landscape work ever shows stepping, the same masks can be routed through GEGL levels so the precision follows the image.
