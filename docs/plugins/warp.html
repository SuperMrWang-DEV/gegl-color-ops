木偶变形

plugin/warp 变形 Distort

姿势差一点、胳膊短一截、杯子被拍歪了——这些都不该开液化一格一格推。 在图层上点几个钉子，拖住钉子把内容拽过去，钉子之间平滑地跟着走， 离钉子远的地方一个字节都不动。

菜单位置
  • SuperMrWang → Distort → 木偶变形（网格变形）…

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-puppet-warp(image, drawables, pins, mode, radius, output)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

怎么用

点、拖、右键

选图层 → 菜单 → 图片上点一下就是一根钉子（按住可以直接拖）； 拖钉子画面跟着动；右键点钉子删掉它，或者选中后按 Delete。 钉子拖过的范围由「影响半径」决定，圈外是严格的恒等——连一个字节都不重采样。

三档解算：刚性（MLS 相似）只允许旋转 + 等比缩放，方角还是方的， 纯摆位最好看；自由（MLS 仿射）再放开剪切和拉伸，适合把东西拉长； ARAP 在网格上解「尽可能刚性」，大角度弯折时局部不会被压扁， 最接近 PS 的手感。

ARAP 那一档要 numpy（见「GIMP 自带的 Python 与 numpy」），没装就不出现在 下拉里；它也不用影响半径（靠弱锚定收口），选它时滑杆自动变灰。

输出三档，第一档是 非破坏滤镜（对话框默认）：钉子和参数以 lb:puppet-warp 的形式挂在图层滤镜栈上，像素一个字节都不动， 之后随时能在图层属性里改参数、临时关掉或删掉；再跑一次对话框会从滤镜里 把钉子读回来接着拖。另外两档是 覆盖当前图层、复制到新图层 （把结果烤进像素）。

非交互也能跑

钉子是过程参数 pins，格式 sx,sy,dx,dy; sx,sy,dx,dy（原位 → 拖到的地方，图层像素坐标）， 分号和换行都认，写两个数就表示没拖。对话框点应用时也是把钉子写成这个 字符串再跑一遍，所以脚本能完整复现一次手动变形：

lb-plugin-puppet-warp 图层 pins="100,200,140,200; 300,400,300,430" mode=rigid radius=30

它是怎么算的

MLS + ARAP 双路

前两档是 MLS（移动最小二乘）：每个像素按到各钉子的距离加权，解一个 最小二乘仿射，让「钉子原位」尽量对到「钉子现在的位置」。钉子上严格插值， 场是光滑的。第三档是 ARAP：在 48×37 的网格上解 Σ｜(xᵢ-xⱼ) - Rᵢ(vᵢ-vⱼ)｜²，局部步骤求每个顶点的最优旋转、全局步骤解 Laplacian 系统，交替到收敛。

五件事必须做对，否则画面会悄悄坏掉：

① MLS 是全局的，要自己收口。用 1/d² 权重时远处解出来的仍是一个像样的 仿射，整张图会跟着轻微旋转（实测四角漂 0.7 px）。所以每个像素再乘一个 到最近钉子的 smoothstep 窗口，圈外严格恒等。

② 只在栅格上解，不是每个像素。768×1024 逐像素解 8 个钉子要十几秒； 改成在长边 140 个节点的栅格上解、重采样时对偏移量做双线性，误差 < 0.02 px。

③ 整行跳过的判据是「严格为 0」，不是「小于 0.5 px」。节点间距 7 px， 用 0.5 px 当阈值，节点之间那些 0.504 px 的位移会整行漏掉——纯 Python 里 看不出来，和逐像素判断的 numpy 路径一比就差 2 万多个像素。

④ ARAP 的钉子必须是硬约束。把约束以「大权重」加进 Laplacian 看着更简单， 但钉子合力不为零、L 的零空间又是常数向量，系统会把整张网格抬成均匀平移 ——实测整幅画面平移到钉子位移，一个顶点都不形变。

⑤ ARAP 只看边长，所以要加弱锚定。「整张网格刚体转过去」是零能量解， 只有一个钉子时整个画面会跟着旋转（实测中位位移 44 px）。加 0.06 的弱弹簧 把远处按住；远处不动时弹簧不受力，不干扰形变。

实测

768×1024 图层、两个钉子、影响半径 25%：全分辨率变形 0.15 秒（含读写 缓冲区，装了 numpy）。预览以前缩在 520 长边、58 毫秒一张（numpy 重采样）， 现在直接调 C，尺寸也放开到屏幕能给的：1600×1200 的图给 1064×798， 一帧 6～10 毫秒，拖钉子完全跟手。

1600×2400 的图局部拖一处 0.7 秒，影响半径拉满的全图重采样 1.2 秒 （纯 Python 兜底分别是 2.4 / 6.2 秒）。ARAP 的网格分解只做一次（24 ms）， 拖钉子时每帧约 20 ms。

和 PS 差在哪

有：钉子上拖、刚性/自由/ARAP 三档、影响半径、网格叠加、右键删钉子、 实时预览、非交互的钉子参数。没有：PS 的「深度」（钉子前后层级）、 以及按 Alt 旋转整根钉子的那套手柄——要大角度旋转请直接转图层。

图层组、文字层、矢量层会被明确拦下来（它们没有可变的像素）， 报错里直接说要先栅格化，而不是丢一串 GIMP 内部错误。

Puppet Warp

plugin/warp Distort Retouch

The pose is slightly off, the arm a bit short, the cup knocked crooked — none of that deserves pixel-by-pixel liquify. Drop a few pins on the layer, drag the pins and the picture follows: smooth in between, and byte-for-byte untouched far away.

Menu location
  • SuperMrWang → Distort → Puppet Warp（网格变形）…

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-puppet-warp(image, drawables, pins, mode, radius, output)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

How it works

click, drag, right-click

Pick a layer → menu → click once on the picture to place a pin (holding the button drags it right away); drag a pin and the pixels follow; right-click a pin to delete it, or select it and press Delete. How far a pin reaches is set by Falloff; outside that circle the layer is left alone completely — not even resampled.

Three solvers. Rigid (MLS similarity) allows only rotation and uniform scale, so square corners stay square — best for moving something around. Free (MLS affine) adds shear and stretch: good for lengthening, bad for faces. ARAP solves “as rigid as possible” on a mesh, so a big bend does not squash the patch — the closest to Photoshop's behaviour.

ARAP needs numpy (see “GIMP's own Python and numpy”); without it the entry is not in the dropdown. It also ignores Falloff — the slider greys out when you pick it.

Three outputs. The first is a non-destructive filter (the dialog's default): the pins and settings live on the layer's filter stack as lb:puppet-warp, so not a single pixel changes — you can retune or switch it off at any time, and running the dialog again reads the pins back from the filter. The other two are replace this layer and copy to a new layer, which bake the warp into pixels.

Works without a mouse, too

The pins are a procedure argument, pins, written as sx,sy,dx,dy; sx,sy,dx,dy (where a pin was placed → where it was dragged, in layer pixels). Semicolons and newlines both separate; two numbers mean “placed but not dragged”. Pressing Apply writes exactly that string back into the config and runs the same code, so a script can reproduce a manual warp step for step:

lb-plugin-puppet-warp layer pins="100,200,140,200; 300,400,300,430" mode=rigid radius=30

How it is computed

MLS + ARAP

The first two modes are MLS (moving least squares): each pixel gets weights from its distance to every pin, then a least-squares affine is solved that maps “where the pin was” onto “where the pin is now”. Interpolation at the pins is exact and the field is smooth. The third is ARAP: on a 48×37 mesh it minimises Σ｜(xᵢ-xⱼ) - Rᵢ(vᵢ-vⱼ)｜², alternating a local step (best rotation per vertex) with a global Laplacian solve until it converges.

Five things have to be right or the picture quietly goes wrong:

① MLS is global, so it needs a cutoff. With 1/d² weights the far field is still a perfectly good affine — the whole image drifts slightly (measured: corners moved 0.7 px). Every pixel is therefore multiplied by a smoothstep window measured from the nearest pin; outside it the map is the identity.

② Solve on a grid, not per pixel. Solving 8 pins per pixel at 768×1024 takes ten-odd seconds. Solving on a grid of 140 nodes along the long edge and bilinearly interpolating the offsets costs 0.02 px of accuracy.

③ A row is skipped only when its displacement is exactly zero — not “under 0.5 px”. Nodes are 7 px apart, so a 0.5 px threshold silently drops the 0.504 px displacements between nodes: invisible in pure Python, but it makes 20 000+ pixels differ from the per-pixel numpy path.

④ ARAP pins must be hard constraints. Adding them to the Laplacian with a big weight looks simpler, but their total force is non-zero and the nullspace of L is the constant vector, so the solver lifts the whole mesh into a uniform translation — measured: the entire picture translated to the pin offset, zero deformation.

⑤ ARAP only measures edge lengths, so it needs a weak anchor. “Rotate the whole mesh rigidly” is a zero-energy solution; with a single pin the picture just spins (measured: median displacement 44 px). A 0.06 spring pulls every vertex back home — it costs nothing when the vertex is already there, so it does not fight the deformation.

Measured

768×1024 layer, two pins, falloff 25 %: full-resolution warp in 0.15 s including buffer read and write (with numpy). The preview used to be squeezed into a 520 px long edge at 58 ms a redraw (numpy resampling); it now calls the C operator directly and takes the room the screen allows: a 1600×1200 picture previews at 1064×798 in 6–10 ms, so dragging keeps up completely.

On a 1600×2400 photo a local drag costs 0.7 s; resampling everything (falloff 100 %) takes 1.2 s. Pure-Python fallback: 2.4 s / 6.2 s. The ARAP mesh is factored once (24 ms); dragging then costs about 20 ms per frame.

Where it differs from Photoshop

Has: draggable pins, rigid / free / ARAP modes, falloff, mesh overlay, right-click delete, live preview, a non-interactive pin argument. Does not have: Photoshop's depth (pins in front of / behind each other) and the Alt-drag rotation handle — for big rotations, rotate the layer instead.

Layer groups, text and vector layers are refused with a plain sentence (they have no pixels of their own) instead of a GIMP-internal error.
