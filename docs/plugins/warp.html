木偶变形

plugin/warp 变形 Distort

姿势差一点、胳膊短一截、杯子被拍歪了——这些都不该开液化一格一格推。 在图层上点几个钉子，拖住钉子把内容拽过去，钉子之间平滑地跟着走， 离钉子远的地方一个字节都不动。

菜单位置
  • SuperMrWang → Distort → 木偶变形（网格变形）…

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-puppet-warp(image, drawables, pins, mode, radius, output)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

怎么用

点、拖、右键

选图层 → 菜单 → 图片上点一下就是一根钉子（按住可以直接拖）； 拖钉子画面跟着动；右键点钉子删掉它，或者选中后按 Delete。 钉子拖过的范围由「影响半径」决定，圈外是严格的恒等——连一个字节都不重采样。

「刚性（保形）」只允许旋转 + 等比缩放，方角还是方的，和 PS 的木偶变形最像； 「自由（仿射）」放开剪切和拉伸，适合把东西拉长，不适合脸。

输出两种：覆盖当前图层，或者复制到新图层（原图层留着对比）。

非交互也能跑

钉子是过程参数 pins，格式 sx,sy,dx,dy; sx,sy,dx,dy（原位 → 拖到的地方，图层像素坐标）， 分号和换行都认，写两个数就表示没拖。对话框点应用时也是把钉子写成这个 字符串再跑一遍，所以脚本能完整复现一次手动变形：

lb-plugin-puppet-warp 图层 pins="100,200,140,200; 300,400,300,430" mode=rigid radius=30

它是怎么算的

MLS，不是三角网格

PS 的木偶变形是 ARAP（在网格上解一个稀疏线性系统）。GIMP 3 的 Python 里 没有 numpy，稀疏求解在纯 Python 里跑不动，所以这里换成 MLS （移动最小二乘）：每个像素按到各钉子的距离加权，解一个最小二乘仿射， 让「钉子原位」尽量对到「钉子现在的位置」。钉子上严格插值，场是光滑的。

三件事必须做对，否则画面会悄悄坏掉：

① MLS 是全局的，要自己收口。用 1/d² 权重时远处解出来的仍是一个像样的 仿射，整张图会跟着轻微旋转（实测四角漂 0.7 px）。所以每个像素再乘一个 到最近钉子的 smoothstep 窗口，圈外严格恒等。

② 只在栅格上解，不是每个像素。768×1024 逐像素解 8 个钉子要十几秒； 改成在长边 140 个节点的栅格上解、重采样时对偏移量做双线性，误差 < 0.02 px。

③ 没动过的行整行抄。纯 Python 重采样 1600×2400 全图要 6 s； 逐行先按节点扫「这一行有没有超过 0.5 px 的位移」，没有就整行切片复制， 只动画面一角时是 0.2 s 级。

实测

768×1024 图层、两个钉子、影响半径 25%：全分辨率变形 0.35 秒（含读写 缓冲区）。预览是 520 长边，拖钉子时按 70 ms 节流重画，通常 0.1 秒 一张，手感跟得上。

1600×2400 的图局部拖一处约 2.4 秒；影响半径拉到 100% 就是全图重采样， 约 6 秒，界面上不会假死但会等一会儿。

和 PS 差在哪

有：钉子上拖、刚性/自由两档、影响半径、网格叠加、右键删钉子、 实时预览、非交互的钉子参数。没有：PS 的「深度」（钉子前后层级）、 以及按 Alt 旋转整根钉子的那套手柄——要大角度旋转请直接转图层。

图层组、文字层、矢量层会被明确拦下来（它们没有可变的像素）， 报错里直接说要先栅格化，而不是丢一串 GIMP 内部错误。

Puppet Warp

plugin/warp 变形 Retouch

The pose is slightly off, the arm a bit short, the cup knocked crooked — none of that deserves pixel-by-pixel liquify. Drop a few pins on the layer, drag the pins and the picture follows: smooth in between, and byte-for-byte untouched far away.

Menu location
  • SuperMrWang → Distort → Puppet Warp（网格变形）…

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-puppet-warp(image, drawables, pins, mode, radius, output)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

How it works

click, drag, right-click

Pick a layer → menu → click once on the picture to place a pin (holding the button drags it right away); drag a pin and the pixels follow; right-click a pin to delete it, or select it and press Delete. How far a pin reaches is set by Falloff; outside that circle the layer is left alone completely — not even resampled.

“Rigid (keeps shapes)” only allows rotation and uniform scale, so square corners stay square — this is the one that behaves like Photoshop's puppet warp. “Free (allows stretching)” opens up shear and stretch: good for lengthening something, bad for faces.

Two outputs: replace this layer, or copy to a new layer so the original stays around for comparison.

Works without a mouse, too

The pins are a procedure argument, pins, written as sx,sy,dx,dy; sx,sy,dx,dy (where a pin was placed → where it was dragged, in layer pixels). Semicolons and newlines both separate; two numbers mean “placed but not dragged”. Pressing Apply writes exactly that string back into the config and runs the same code, so a script can reproduce a manual warp step for step:

lb-plugin-puppet-warp layer pins="100,200,140,200; 300,400,300,430" mode=rigid radius=30

How it is computed

MLS, not a triangle mesh

Photoshop's puppet warp is ARAP: a sparse linear system on a mesh. GIMP 3's Python has no numpy, and a sparse solve in pure Python is hopeless, so this uses MLS (moving least squares) instead: each pixel gets weights from its distance to every pin, then a least-squares affine is solved that maps “where the pin was” onto “where the pin is now”. Interpolation at the pins is exact and the field is smooth.

Three things have to be right or the picture quietly goes wrong:

① MLS is global, so it needs a cutoff. With 1/d² weights the far field is still a perfectly good affine — the whole image drifts slightly (measured: corners moved 0.7 px). Every pixel is therefore multiplied by a smoothstep window measured from the nearest pin; outside it the map is the identity.

② Solve on a grid, not per pixel. Solving 8 pins per pixel at 768×1024 takes ten-odd seconds. Solving on a grid of 140 nodes along the long edge and bilinearly interpolating the offsets costs 0.02 px of accuracy.

③ Copy untouched rows verbatim. Resampling 1600×2400 in pure Python takes 6 s. Each row is first scanned at node level for “any displacement over 0.5 px”; if there is none the whole row is a slice copy. Dragging one corner becomes 0.2 s.

Measured

768×1024 layer, two pins, falloff 25 %: full-resolution warp in 0.35 s including buffer read and write. The preview runs at a 520 px long edge and is throttled to 70 ms while dragging — usually 0.1 s per redraw, which keeps up with the hand.

On a 1600×2400 photo a local drag costs about 2.4 s; pushing the falloff to 100 % means resampling everything, roughly 6 s. The window stays responsive, it just takes a moment.

Where it differs from Photoshop

Has: draggable pins, rigid/free modes, falloff, mesh overlay, right-click delete, live preview, a non-interactive pin argument. Does not have: Photoshop's depth (pins in front of / behind each other) and the Alt-drag rotation handle — for big rotations, rotate the layer instead.

Layer groups, text and vector layers are refused with a plain sentence (they have no pixels of their own) instead of a GIMP-internal error.
