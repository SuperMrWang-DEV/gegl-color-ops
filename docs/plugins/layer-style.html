图层样式

plugin/layer-style 图层 Layer

PS 的「图层 → 图层样式」这一整套：投影、内阴影、外发光、内发光、 斜面和浮雕、光泽、颜色/渐变/图案叠加、描边。勾一个效果、拖几根滑杆，画面立刻 跟着动；确定之后不烤进像素，而是给出一组**还能单独选中、隐藏、调不透明度的图层**。

菜单位置
  • SuperMrWang → Layer → 图层样式…

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-layer-style(image, drawables, style)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

十个效果，一个面板

10 个

投影 / 内阴影：颜色、不透明度、角度（可跟随全局光）、距离、扩展/阻塞、 大小、12 条预设等高线、杂色。外发光 / 内发光：单色或渐变、柔和/精确两种 技法、扩展、大小、范围；内发光还能选「边缘 / 居中」两个源。

斜面和浮雕：外斜面 / 内斜面 / 浮雕 / 枕状浮雕 / 描边浮雕五种样式， 平滑 / 雕刻清晰 / 雕刻柔和三种方法，深度、方向、大小、软化、高度，高光与阴影 各自有颜色和混合模式。光泽：角度、距离、大小、反相。

颜色 / 渐变 / 图案叠加：26 种混合模式，渐变有线性 / 径向 / 角度 / 对称 / 菱形五种、可反相、可对齐图层。描边：外 / 内 / 居中三档，宽度按精确距离 算（不靠模糊），填充可选颜色、渐变或图案。

结果是一组真图层

非破坏

应用后会多一个叫 原图层名 (layer style) 的组，原图层被收进组里 居中：投影和外发光在它下面，内阴影、内发光、描边、三种叠加、斜面 在它上面。这个顺序就是 PS 的那套，所以半透明的原图层会「透出」阴影、 内阴影只会压在内缘 —— 不需要额外裁蒙版。

改参数再跑一次，组里的旧效果层会被整体换掉（原图层原封不动），不会越叠越多。 每个效果层都是普通 RGBA 图层，可以单独关掉、调不透明度、加自己的蒙版。

复制样式：一份代码串

复制粘贴

PS 是「右键 → 拷贝图层样式」，粘到另一个图层上是「右键 → 粘贴图层样式」。 GIMP 没有「样式挂在图层上」这个宿主概念，所以这里换成一串代码：对话框底部展开 Style code，里面就是当前样式的 JSON（换行缩进，全是 ASCII）；点 Copy code 带走，到另一个图层的同一个对话框里点 Paste and load， 或者把代码贴进框里再点 Load this code。参数面板、勾选框、预览会一起 跟着变，确定之后就是同一份样式。

代码里就是全部参数，没有藏起来的状态：数字越界会夹到边界、0–255 写法的颜色 自动除以 255、认不出来的效果忽略并提示 —— 所以从旧版本或别的机器上拿来的 代码也读得进去。这串东西正好就是 PDB 的 style 参数，脚本能原样 回放，不需要再维护第二套格式。

样式跟着图层走

存进 XCF

应用之后，这份 JSON 会被写成图层和组的寄生数据（parasite），跟着 XCF 一起保存、跟着撤销一起回退。于是再点同一个图层的「图层样式」，看到的是 上次那一套参数，不是默认值 —— 少了这一步，复制出去的就永远是默认样式， 功能等于没有。

把一份样式铺到很多图层上：在源图层复制，再到每个目标图层粘一次。尺寸按文档 像素算，粘到尺寸不同的图层上数值原样保留（PS 也是这样）。

和 PS 差在哪

有：十个效果、26 种混合模式、全局光角度、12 条等高线、扩展/阻塞、 挖空（无 / 浅 / 深）、本图层的混合颜色带（含两端拆分）、实时预览。

没有：纹理（斜面的图案浮雕）、3D 材质、自定义等高线编辑器、 下一图层的混合颜色带、图案叠加的角度旋转（PS 也没有）、 「在图层上直接拖投影手柄」那套交互。

另外这个版本里「样式」不是挂在图层上的对象，改参数要重跑一遍（PS 是点开 样式面板随时改）。不过参数本身会记在图层上，重跑时看到的就是上次那一套， 调好一处再复制给其它图层，实际用起来差别不大。要「参数随时能改、原像素 一点不动」，用下一节那条实时滤镜。

为什么交给 GIMP 的是「普通」模式

GIMP 3 默认的混合模式在线性光里算：实测 50% 的 204 叠在 51 上是 153，而 PS 在 sRGB 值上算，结果是 128。直接把效果层挂上 MULTIPLY / SCREEN，边和中间调会整体偏亮，柔边还会发白。

所以插件把混合先算进颜色里，图层一律挂 NORMAL_LEGACY （纯 sRGB 的 over）。和 GEGL 对拍：实心区最大色差 0.6/255、平均 0.12/255，等于同一张图。代价是效果层的颜色里带着「下方是什么」的痕迹， 拖动它会跟着错 —— 图层样式本来也不是让你挪的。

实测

768×1024、六种效果一起开：1.7 s（含 14 次全图合成），预览 560 长边一帧 60–100 ms，拖滑杆跟得上手。描边和斜面用的都是精确 带符号距离（不是模糊逼近），所以同样的参数在软边和硬边上厚度一致。

非交互也能跑

整份样式是一个 JSON 字符串参数 style，对话框点应用时写的就是 它，脚本可以原样回放：lb-plugin-layer-style 图层 style="{\"effects\": {\"drop-shadow\": {\"enabled\": true, …}}}"。渐变和图案取 GIMP 当前的渐变 / 图案。

同一套样式的另一条路：实时滤镜

非破坏

这一页讲的是破坏性的做法：算完就变成图层，原像素被换掉了，参数只能 记着、不能随时调。仓库里另有一个 GEGL 算子 lb:layer-style （菜单不同：SuperMrWang → Layer → Layer Style (live)…）， 同一个引擎挂成图层滤镜——拖滑杆实时重算、眼睛图标可关、参数随 XCF 存盘、原像素一个字节都不动。

两条路各自有用：要「随时改」或者「存进 XCF 回头再调」，用滤镜那条；要 「拿到十个能单独加蒙版、改不透明度、随手涂改的效果图层」，用这一条。滤镜 版拿不到 GIMP 的图案库（GEGL 进程看不到 GIMP 资源），图案只能用六种程序化 图形；渐变也只能给两个颜色。

为什么不是同一份代码

GIMP 3 的非破坏编辑只认 GEGL 算子：滤镜栈里存的是算子名 + 属性值， 所以必须是 C 编译出来的模块。Python 插件只能读写像素，再多的图层组也只是 一份烤好的结果。

两份实现共用同一套公式（plugin/_shared/layer_style.py 是 C 版的 对照实现），对拍过：实心区平均差 0.45/255、p99 5.0。

Layer Style

plugin/layer-style Layer Layer

Photoshop's Layer Styles, the whole set: drop shadow, inner shadow, outer and inner glow, bevel and emboss, satin, colour / gradient / pattern overlay and stroke. Tick an effect, drag a slider, the picture follows. Nothing gets baked into pixels — you get a group of layers you can still select, hide and fade one by one.

Menu location
  • SuperMrWang → Layer → Layer Style…

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-layer-style(image, drawables, style)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

Ten effects, one panel

10

Drop / inner shadow: colour, opacity, angle (optionally following the global light), distance, spread / choke, size, one of 12 preset contours, noise. Outer / inner glow: solid colour or gradient, softer or precise technique, spread, size, range; the inner glow can radiate from the edge or from the centre.

Bevel and emboss: outer bevel / inner bevel / emboss / pillow emboss / stroke emboss, smooth / chisel hard / chisel soft, depth, direction, size, soften, altitude, with separate highlight and shadow colours and blend modes. Satin: angle, distance, size, invert.

Colour / gradient / pattern overlay: 26 blend modes; gradients can be linear, radial, angled, reflected or diamond, reversed, aligned to the layer. Stroke: outside / inside / centre, width measured as an exact distance (not a blur), filled with a colour, a gradient or a pattern.

The result is real layers

non-destructive

Applying creates a group called layer name (layer style) and moves the original layer into the middle of it: drop shadow and outer glow go underneath it, inner shadow, inner glow, stroke, the three overlays and the bevel go on top. That is Photoshop's stacking order, so a semi-transparent layer lets its shadow show through and an inner shadow only presses on the inside edge — no extra masking needed.

Run it again after changing a slider and the old effect layers inside the group are replaced; the original layer is never touched and nothing piles up. Every effect layer is an ordinary RGBA layer: switch it off, fade it, give it its own mask.

Copying a style: one string of code

copy / paste

Photoshop does it with right-click → Copy Layer Style, then Paste Layer Style on the target. GIMP has no host concept of a style attached to a layer, so here it is a string: expand Style code at the bottom of the dialog and you get the current style as JSON (indented, pure ASCII). Copy code takes it away; Paste and load in the other layer's dialog reads the clipboard, or paste into the box yourself and press Load this code. Sliders, checkboxes and the preview all follow, and Apply then gives that same style.

The string holds every parameter and no hidden state: out-of-range numbers are clamped to the limit, colours written 0–255 are divided by 255, unknown effect names are ignored with a note — so codes from an older version or another machine still load. It is exactly the PDB's style argument, so scripts replay it with no second format to keep in sync.

The style travels with the layer

stored in the XCF

After applying, that JSON is attached to the layer and the group as a parasite: it is saved in the XCF and rolls back with undo. So opening Layer Style on that layer again shows the values you last used, not the defaults — without that step the copy feature would only ever copy the defaults, which is the same as not having it.

To cover many layers with one style: copy on the source layer, then paste once per target. Sizes are document pixels, so pasting onto a differently sized layer keeps the numbers as they are — same as Photoshop.

Where it differs from Photoshop

There: all ten effects, 26 blend modes, global light, 12 contours, spread / choke, knockout (none / shallow / deep), "blend if: this layer" with both softness handles, live preview.

Not there: texture (pattern bevels), 3D materials, a custom contour editor, "blend if: underlying layer", rotating the pattern (Photoshop cannot either), and dragging shadow handles straight on the canvas.

In this version the style is not an object hanging off the layer, so changing a parameter means running the plug-in again (Photoshop reopens the panel at any time). The values themselves are remembered on the layer, so a re-run starts from what you last applied — and one good style can be pasted onto the rest. For "parameters editable at any time, pixels untouched", see the live filter below.

Why GIMP is handed plain "normal" layers

GIMP 3's default blend modes work in linear light: measured, 50% of 204 over 51 gives 153, while Photoshop blends sRGB values and gives 128. Hang MULTIPLY or SCREEN straight onto an effect layer and edges and midtones come out too bright, with soft edges glowing.

So the plug-in blends first, in the colour itself, and every layer is NORMAL_LEGACY (a plain sRGB over). Cross-checked against GEGL: maximum channel difference in solid areas 0.6/255, mean 0.12/255 — the same picture. The cost is that an effect layer's colour carries a trace of what was under it, so dragging the layer would smear; layer styles are not meant to be dragged anyway.

Measured

768×1024 with six effects on: 1.7 s, including 14 full-frame composites. The 560-pixel preview runs a frame in 60–100 ms, so sliders keep up. Stroke and bevel use an exact signed distance field rather than a blur, so the same number gives the same thickness on a soft edge and a hard one.

Scriptable

The whole style is one JSON string argument, style, and the dialog writes exactly what it applied, so a script can replay it. Gradients and patterns come from GIMP's current gradient and pattern.

The other way to get the same styles: a live filter

non-destructive

This page describes the destructive route: the effects are computed once and become layers, the original pixels are replaced, and the parameters are only remembered, never re-applied. The repository also ships a GEGL op, lb:layer-style (different menu: SuperMrWang → Layer → Layer Style (live)…), which attaches the same engine as a layer filter: sliders recompute live, the eye icon switches it off, the parameters are saved in the XCF, and the pixels are never written to.

Both have their use. Want to keep tweaking, or reopen the file next month and adjust? Use the filter. Want ten separate effect layers you can mask, fade and paint on? Use this one. The filter version cannot reach GIMP's pattern library (a GEGL process cannot see GIMP resources), so patterns are six procedural kinds and gradients are two colours.

Why it is not one code base

GIMP 3's non-destructive editing only understands GEGL operations: the filter stack stores an operation name plus property values, so it has to be a C module. A Python plug-in can only read and write pixels; any number of groups is still a baked result.

Both implementations share the same formulas (plugin/_shared/layer_style.py is the reference the C version was checked against): mean difference in solid areas 0.45/255, p99 5.0.
