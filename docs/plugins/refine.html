选择并遮住

plugin/refine 蒙版 Mask

选区做完了，边还是糊的：AI 抠图回来的 alpha 半透明、魔棒选出来的边 像狗啃、羽化过的边上挂着背景色。这个对话框就是拿来收尾的——左边一块预览、 右边六根滑杆，拖一下立刻重算，满意了点应用。

菜单位置
  • SuperMrWang → Mask → 选择并遮住（精修边缘）…

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-refine-mask(image, drawables, radius, smart, smooth, feather, contrast, shift, decontaminate, output, work-size)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

六根滑杆

和 PS 同名同向
滑杆做什么什么时候拉
边缘检测半径 沿法线在 ±N 像素里找画面中真实的边缘，把蒙版剖面推过去。 「智能半径」勾上时，只有找到明显更强的边缘（1.35×）才动 AI 抠的边糊出去一两像素、旁边正好有强边（头发对背景、衣领对皮肤）
平滑 盒式模糊一遍。锯齿、毛刺、零星飞点被摊平 魔棒 / 快速选择出来的边像狗啃
羽化 三次盒式逼近高斯，软化过渡 要贴到另一张图上，硬边会看出「剪纸」
对比度 把软边往 0 和 255 推（S 曲线，斜率最高 5×） 羽化过头、边缘一圈雾；或者 AI 的 alpha 太软
移动边缘 整体加/减 alpha：正值外扩、负值内缩，软硬不变 整体差半像素（白边、吃掉一圈轮廓）
去色边 半透明像素的颜色沿 alpha 梯度往里取「实心前景色」替换 抠到浅底上有白边，抠到绿幕上有绿边

顺序是 吸附 → 平滑 → 羽化 → 对比度 → 移动边缘。羽化放在对比度 之前，是为了让对比度还能把软边重新压硬；反过来做，羽化永远压在上面， 那根滑杆就白给了。

输出四种

图层蒙版：挂在当前图层上，非破坏，随时能改。
透明新图层：复制一层、把蒙版烤进 alpha，去色边只在这条输出上生效 （另外三种不碰像素）。
选区：只换选区，什么都不动。
通道 + 选区：存成「Refined Mask」通道，选区也留着。

通道那条就是画笔的入口：PS 里那支「选择并遮住」的画笔，在这里 换成——在通道上用黑白画笔涂（白加、黑减），再双击通道载入成选区。 美术上的事交给 GIMP 自己的画笔，比插件里再搓一支靠谱。

实测

768×1024 / RMBG 结果

拿 SDXL 生成、RMBG-2.0 抠好的一张卷发人像当输入（alpha 就是蒙版）： 1.03 秒跑完六项（半径 2 / 平滑 1 / 羽化 1 / 对比度 35 / 去色边 60）， 半透明像素从 40 万降到 1.3 万，边缘的浅色雾被收干净，23416 个边缘像素 换了颜色。预览那一侧是 520 长边，拖滑杆到重画通常 150 毫秒。

工作尺寸默认 1600 长边。GIMP 3 的 Python 里没有 numpy，模糊只能 手写前缀和；1600×1067 跑一遍约 1~2 秒，再大就要等了。0 表示按原分辨率算， 2400 万像素大概 10 秒起步。

和 PS 差在哪

有：六根滑杆、实时预览、四种看片方式（棋盘格 / 白 / 黑 / 红蒙版）、 四种输出。没有：画布上的那支减画笔、以及 PS 那种「按图重建 matte」 的边缘检测。

边缘检测这里是沿法线平移剖面：每个半透明像素在 ±半径内找最强边缘， 明显更强就把蒙版挪过去（双线性重采样）。结果一样是把糊出去的边收回来， 但它不会像 PS 那样重新解一遍前景色和不透明度。

三个不下心就翻车的细节

通道读出来是线性的。选区存成通道后，用 "Y u8" 读到的 是线性亮度，而选区值和图层 alpha 是 sRGB 编码的（实测：通道写 128， 选区读回 188）。不转这一下，精修完中间调整体下压，50% 等值线跟着漂。

预览和应用必须是同一套代码。两边都调同一个 refine_mask， 只有分辨率不同。各写一套实现，早晚会漂成「预览好看、确定后不一样」。

吸附要把位移沿法线传播到 ±半径。只改半透明带的话，剖面搬过去没有 地方接住，边界会塌成一道硬跳变。

Select and Mask

plugin/refine Mask Mask

The selection is there, the edge is not: alpha from an AI cut-out is half-transparent, a magic-wand edge looks gnawed, a feathered edge carries the old background colour. This dialog is the finishing pass — preview on the left, six sliders on the right, every change re-rendered immediately.

Menu location
  • SuperMrWang → Mask → Select and Mask（精修边缘）…

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-refine-mask(image, drawables, radius, smart, smooth, feather, contrast, shift, decontaminate, output, work-size)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

The six sliders

same names, same direction
SliderWhat it doesWhen to pull it
Edge radius Searches ±N px along the normal for a real edge and moves the mask profile onto it. With “smart” on, it only moves for an edge at least 1.35× stronger The AI edge is one or two pixels out and there is a strong edge nearby (hair against background, collar against skin)
Smooth One box blur pass: jaggies, specks and stray dots get flattened A magic-wand / quick-select edge looks gnawed
Feather Three box passes approximating a Gaussian Pasting onto another picture, where a hard edge reads as cut paper
Contrast Pushes the soft part towards 0 and 255 (S-curve, up to 5× slope) Over-feathered, a band of fog around the subject; or alpha that is simply too soft
Shift edge Adds or subtracts alpha: positive expands, negative contracts, the softness stays The whole mask is half a pixel out (a white fringe, or eating into the outline)
Decontaminate Walks inwards along the alpha gradient and replaces half-transparent colours with the solid foreground colour behind them A white fringe on a light background, a green fringe from a green screen

The order is snap → smooth → feather → contrast → shift. Feather sits before contrast on purpose: contrast has to be able to harden a softened edge, otherwise feather always wins and that slider does nothing.

Four outputs

Layer mask: attached to the current layer, non-destructive.
New layer: the layer is copied and the mask is baked into its alpha; decontaminate only applies here, because the other three do not touch pixels.
Selection: replaces the selection, nothing else changes.
Channel + selection: stored as a “Refined Mask” channel.

That channel is the brush entry point: Photoshop's brush inside Select and Mask is replaced by painting black and white on the channel (white adds, black removes) and loading it back as a selection. GIMP's own brushes are better than a brush we would re-invent inside a plug-in.

Measured

768×1024 / RMBG result

Input: an SDXL portrait cut out with RMBG-2.0 (its alpha is the mask). All six steps in 1.03 s (radius 2 / smooth 1 / feather 1 / contrast 35 / decontaminate 60): half-transparent pixels dropped from 400 k to 13 k, the pale haze on the edge was cleaned up, and 23 416 edge pixels changed colour. On the preview side (520 px long edge) a slider drag re-renders in under 150 ms.

The working size defaults to 1600 px on the long edge. GIMP 3's Python has no numpy, so blurs are written by hand with prefix sums: 1600×1067 takes one to two seconds, more takes longer. 0 means full resolution — 24 MP starts at about ten seconds.

Where it differs from Photoshop

Has: the six sliders, a live preview, four ways to look at the result (checker / white / black / red overlay), four outputs. Has not: the subtract brush on the canvas, and Photoshop's “rebuild the matte” edge detection.

Edge detection here slides the profile along the normal: every half-transparent pixel looks for the strongest edge within ±radius and, if it is clearly stronger, the mask is resampled onto it. Same visible result — the smeared edge comes back — but it does not re-solve foreground colour and opacity the way Photoshop does.

Three details that bite

A channel reads back linear. After saving a selection to a channel, "Y u8" gives linear luminance while selection values and layer alpha are sRGB-encoded (measured: write 128 into the channel, the selection reads 188). Skip that conversion and the whole midtone shifts down after refining, taking the 50 % contour with it.

Preview and apply have to be the same code. Both call the same refine_mask, only at different resolutions. Two implementations always drift into “looks great in the preview, different after Apply”.

The snap has to propagate its offset along the normal to ±radius. Moving only the half-transparent band leaves nothing to receive the shifted profile, and the edge collapses into a hard step.
