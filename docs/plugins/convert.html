Convert（十二向互转 + 路径转位图）

plugin/convert 转换 图层转换

通道、选区、蒙版、路径四者两两互转，十二个方向各占一个菜单项，点下去 直接执行、不弹参数框；另外一条 Path to Bitmap 把路径或矢量图层落成像素。原生菜单里这些路分散在四处，而且「蒙版 → 通道」 「通道 → 路径」这类根本没有直连，只能绕选区两步走。路径这一站是有损闸门： 它只有几何、没有 alpha，位图进路径时按 50% 等值线取轮廓。

只是原生方式的便捷实现　这里没有新算法： 像素结果全部出自 GIMP 自带的 PDB 过程，插件只负责把散在三处菜单、要跨三四步的动作 收成一次点击，并保证与手点原生菜单得到的结果逐位相同。

菜单位置
  • SuperMrWang → Convert → 十三项，按目标命名
  • 图层右键 → SuperMrWang → Convert
  • 通道右键 / 路径右键 → SuperMrWang → Convert

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-conv-* 十三个过程，全部零参数

标准 PDB 过程，参数留空走默认值。

依赖

不依赖任何自研算子：十二个方向都只调 GIMP 自己的通道、选区、蒙版、路径 PDB（位图那条读的是图层自己的渲染）。

为什么值得单独做

十三条路，散在四处

原生要办同一件事，得记住三套路径：选择菜单里存通道、通道右键转选区、 图层面板右键 → 添加图层蒙版再在弹窗里挑类型。同一类操作放在三个地方， 方向还是反的。

更关键的是蒙版 → 通道根本没有：GIMP 没有这个过程，只能先「蒙版到选区」 再「选区存通道」，两步、两处菜单。这个插件把它做成一步。

路径也一样：路径 → 选区在路径右键里、选区 → 路径在选择菜单里， 而通道 / 蒙版 ↔ 路径两个方向原生压根没有入口，只能自己拼两步。 现在这些全在同一个子菜单里，按目标命名。

十三个方向

全零参数
  • Channel to Selection · 通道 → 选区
  • Selection to Channel · 选区 → 通道
  • Channel to Mask · 通道 → 图层蒙版
  • Mask to Channel · 图层蒙版 → 通道
  • Selection to Mask · 选区 → 图层蒙版
  • Mask to Selection · 图层蒙版 → 选区
  • Path to Selection · 路径 → 选区
  • Selection to Path · 选区 → 路径
  • Path to Channel · 路径 → 通道
  • Channel to Path · 通道 → 路径
  • Path to Mask · 路径 → 图层蒙版
  • Mask to Path · 图层蒙版 → 路径
  • Path to Bitmap · 路径 / 矢量图层 → 像素图层（矢量图层用它自己的填充与描边原地替换；裸路径按前景色填充）

没有省略号的菜单项就是点一下直接跑：源全从上下文取，不需要在对话框里 再选一遍。

最后一条和前面十二条不一样：前面都是 GIMP 内部几种对象之间倒腾，Path to Bitmap 是唯一一条把几何真正落成像素的——路径在 GIMP 里只存几何、没有填充色和 线宽，所以替它选了「用前景色填内部」这一种落笔方式（与原生「编辑 → 用前景色填充 路径」同义）。新图层只做路径外接框那么大、偏移对回原位，栅格化一个 24×24 的图标 不会顺手生成一张 4000×3000 的空图层。要线稿（描边）就用原生「编辑 → 描边路径」。

源永远是「当前」

  • 通道 = 通道面板里右键点中的那条 → 面板里选中的那条 → 图里唯一的那条，依次兜底
  • 选区 = 当前像素选区；没有选区就当全选
  • 蒙版 = 选中图层的图层蒙版
  • 路径 = 路径面板里右键点中的那条 → 面板里选中的那条 → 图里唯一的那条，同样三路兜底
  • 目标：通道 / 路径各新建一条、蒙版挂到选中图层（多选则每个都挂）

已有蒙版时先丢掉旧的再新建，结果与原生新建逐位一致——改完源再跑 一次就是刷新。

结果与原生逐位一致

硬指标

十二个方向都不碰像素缓冲，一律转调 GIMP 自己的过程：通道 / 路径转选区用 gimp-image-select-item，选区存通道用 gimp-selection-save， 选区建蒙版用 create_mask(SELECTION)，选区描路径用 plug-in-sel2path（就是「选择 → 路径」背后那个过程）。 凡是原生没有直连的，就按原生的两步走：通道 ↔ 蒙版、通道 / 蒙版 ↔ 路径， 都经选区这一站。

所以中间灰带着原生那点漂移：默认 8 位图上，通道 128 进选区读回 188， 选区 128 存通道读回 55；而选区与蒙版之间原生会换算，那一对不漂。 32 位线性精度的图像上通道本身就存线性值，那六个方向都不漂。 路径方向跟着这条链走：通道 → 路径是先变成 188 的选区再描轮廓，轮廓落在 50% 等值线上，和原生手点两步的结果一样。

为什么单步看着不对

不是插件算错。通道和蒙版存的是 Y'（sRGB 编码），选区存的是 线性 alpha。原生在通道与选区交界处把 Y' 当线性覆盖率直搬， 128 就变成了 188，反方向压成 55。

往返会互相抵消。188 存回通道又变回 128，所以连着跑两步看不出问题， 单步才明显。这是原生的行为，插件不做补偿。

蒙版是 8bit。极暗处有 ±1 的量化误差，原生也一样；偏移图层按画布 坐标对齐，原生建蒙版时同样如此。

和 Channel to Mask 的关系

Channel to Mask...（Mask 组，带省略号）是同一个动作的可配置版： 能指定通道名、能反相、能一次挂多个图层。

Convert → Channel to Mask（无省略号）是一键版：取通道面板里点中的 那条、不反相。日常右键直接跑一键版，需要细调时走带参数的那个。

十二个方向都不依赖自研算子，只调 GIMP 自己的通道、选区、蒙版、路径 PDB。 缺源时会明确说缺什么（没选通道 / 没蒙版 / 没路径 / 图层组没有像素），不会静默什么都不做。 路径这一站有损：羽化、渐变、抗锯齿的边缘在「位图 → 路径」时会被压成硬边界， 这是路径只有几何、没有 alpha 决定的，原生 To Path 同样如此。反过来「路径 → 位图」 不丢任何东西，栅格化出来就是干净的硬边。矢量图层（GIMP 3.2）是另一条路： 它自己有填充色、描边色和线宽，所以按它自己的样子渲染成位图，替换掉原来那一层， 不会再额外盖一张前景色的图上去。

Convert

plugin/convert Convert Convert

Channels, selections, layer masks and paths, converted in every direction: twelve menu items plus Path to Bitmap, each one click and done — no parameter dialog. Natively these paths are spread across four places, and mask → channel does not exist at all; it takes a detour through the selection in two steps. A path is a lossy stop: it carries geometry and no alpha, so anything going into a path is traced along the 50% contour.

Only a convenience wrapper over native behaviour — no new algorithms here: every pixel comes out of GIMP's own PDB procedures. The plug-in just folds a detour that lives in three different menus and takes three or four steps into a single click, and keeps the result bit-for-bit identical to doing it by hand.

Menu location
  • SuperMrWang → Convert → 十三项，按目标命名
  • Layer right-click → SuperMrWang → Convert
  • Channel right-click / Path right-click → SuperMrWang → Convert

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-conv-* 十三个过程，全部零参数

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

Why it needs its own entry

four places

Doing the same thing natively means remembering three routes: Select menu to save a channel, the channel context menu to make a selection, and Layers → Mask → Add Layer Mask with a type picked in the dialog. Same family of operations, three locations, and the directions reverse halfway through.

Worse, mask → channel simply is not there: GIMP has no such procedure, so it is "mask to selection" and then "selection to channel" — two steps, two menus. This plug-in makes it one.

Paths are the same story: path → selection lives in the Paths context menu and selection → path in the Select menu, while channel / mask ↔ path has no native entry at all and has to be assembled by hand. All of it now sits in one submenu, named by destination.

Thirteen directions

zero arguments
  • Channel to Selection
  • Selection to Channel
  • Channel to Mask
  • Mask to Channel
  • Selection to Mask
  • Mask to Selection
  • Path to Selection
  • Selection to Path
  • Path to Channel
  • Channel to Path
  • Path to Mask
  • Mask to Path
  • Path to Bitmap — rasterise to a pixel layer

A menu item without an ellipsis runs immediately: the source is read from the context, so there is nothing to pick in a dialog.

The last one is different from the other twelve. All of those shuffle objects inside GIMP; Path to Bitmap is the only one that turns geometry into pixels. A path carries no fill colour and no line width, so rasterising it here means filling its interior with the foreground colour — the same thing the native "Edit > Fill with foreground colour" does on a path. The new layer is cropped to the path's bounding box and offset back into place, so rasterising a 24×24 icon does not also hand you a 4000×3000 empty layer. For outlines rather than solid shapes, use the native "Edit > Stroke Path".

A vector layer (GIMP 3.2) is the other case: it carries its own fill colour, stroke colour and width, so it is rasterised as it looks and replaces that layer — one layer in, one layer out, no foreground-colour copy stacked on top.

The source is always "current"

  • Channel = the one right-clicked in the Channels dock, else the dock selection, else the only channel in the image
  • Selection = the active pixel selection; none means select-all
  • Mask = the selected layer's layer mask
  • Path = the one right-clicked in the Paths dock, else the dock selection, else the only path in the image
  • Sinks: a new channel or path, or masks on every selected layer

An existing mask is dropped and rebuilt, bit-for-bit identical to a fresh native one — change the source and re-run to refresh.

Bit-for-bit with native

the hard requirement

None of the twelve directions touches a pixel buffer. Each one calls GIMP's own procedure: gimp-image-select-item for a channel or path to a selection, gimp-selection-save for a selection to a channel, create_mask(SELECTION) for a selection to a mask, and plug-in-sel2path — the procedure behind Select > To Path — for a selection to a path. Where native has no direct entry (channel ↔ mask, channel / mask ↔ path) it runs the native two steps through the selection.

That means mid greys carry the native drift: on a default 8-bit image a channel value of 128 reads back as 188 in the selection, and a selection value of 128 reads back as 55 in a channel. Selection ↔ mask converts properly in GIMP, so that pair does not drift. On 32-bit linear precision the six bitmap directions do not drift at all. The path directions follow the same chain: channel → path first becomes the 188 selection, then the contour is taken at 50%, exactly like doing the two native steps by hand.

Why single steps look wrong

It is not the plug-in's arithmetic. Channels and masks store Y' (sRGB encoded); the selection stores linear alpha. Native copies the Y' value straight in as linear coverage, so 128 becomes 188, and the reverse direction squashes it to 55.

Round trips cancel out. 188 stored back into a channel becomes 128 again, so two steps in a row look fine; only a single step shows it. That is native behaviour and the plug-in does not compensate.

Masks are 8-bit. Expect ±1 quantisation in the deep shadows, exactly as native; offset layers align by canvas, also as native.

Relation to Channel to Mask

Channel to Mask... (in the Mask group, with an ellipsis) is the configurable version of the same action: channel by name, invert, several layers at once.

Convert → Channel to Mask (no ellipsis) is the one-click version: it takes the channel you clicked in the dock and does not invert. Use the quick one day to day, the parameterised one when you need to adjust.

None of the twelve directions depends on this project's operators — they only call GIMP's own channel, selection, mask and path PDB. A missing source produces an explicit message (no channel found / no mask / no path / layer group has no pixels) instead of silently doing nothing. A path is a lossy stop: feathered, gradient and anti-aliased edges collapse to a hard boundary on the way into a path, because a path carries geometry and no alpha — the native To Path does the same. Going the other way loses nothing: rasterising a path gives clean hard edges.
