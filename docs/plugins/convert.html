Convert（通道 / 选区 / 蒙版 六向转换）

plugin/convert 转换 图层转换

通道、选区、蒙版三者两两互转，六个方向各占一个菜单项，点下去直接执行、 不弹参数框。原生菜单里这六条路分散在三处，而且「蒙版 → 通道」根本没有直连， 只能绕选区两步走。

只是原生方式的便捷实现　这里没有新算法： 像素结果全部出自 GIMP 自带的 PDB 过程，插件只负责把散在三处菜单、要跨三四步的动作 收成一次点击，并保证与手点原生菜单得到的结果逐位相同。

菜单位置

多条
  • SuperMrWang → Convert → Channel to Selection
  • SuperMrWang → Convert → Selection to Channel
  • SuperMrWang → Convert → Channel to Mask
  • SuperMrWang → Convert → Mask to Channel
  • SuperMrWang → Convert → Selection to Mask
  • SuperMrWang → Convert → Mask to Selection
  • 图层右键 → SuperMrWang → Convert（同样六项）
  • 通道右键 → SuperMrWang → Convert（以通道为源的两项）

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用

lb-plugin-conv-* 六个过程，全部零参数

标准 PDB 过程，参数留空走默认值。

依赖

不依赖任何自研算子：六个方向都只调 GIMP 自己的通道、选区、蒙版 PDB。

为什么值得单独做

六条路散在三处

原生要办同一件事，得记住三套路径：选择菜单里存通道、通道右键转选区、 图层面板右键 → 添加图层蒙版再在弹窗里挑类型。同一类操作放在三个地方， 方向还是反的。

更关键的是蒙版 → 通道根本没有：GIMP 没有这个过程，只能先「蒙版到选区」 再「选区存通道」，两步、两处菜单。这个插件把它做成一步。

六个方向

全零参数
  • Channel to Selection · 通道 → 选区
  • Selection to Channel · 选区 → 通道
  • Channel to Mask · 通道 → 图层蒙版
  • Mask to Channel · 图层蒙版 → 通道
  • Selection to Mask · 选区 → 图层蒙版
  • Mask to Selection · 图层蒙版 → 选区

没有省略号的菜单项就是点一下直接跑：源全从上下文取，不需要在对话框里 再选一遍。

源永远是「当前」

  • 通道 = 通道面板里右键点中的那条 → 面板里选中的那条 → 图里唯一的那条，依次兜底
  • 选区 = 当前像素选区；没有选区就当全选
  • 蒙版 = 选中图层的图层蒙版
  • 目标：通道新建一条、蒙版挂到选中图层（多选则每个都挂）

已有蒙版时先丢掉旧的再新建，结果与原生新建逐位一致——改完源再跑 一次就是刷新。

结果与原生逐位一致

硬指标

六个方向都不碰像素缓冲，一律转调 GIMP 自己的过程：通道转选区用 gimp-image-select-item，选区存通道用 gimp-selection-save， 选区建蒙版用 create_mask(SELECTION)。「通道 ↔ 蒙版」原生没有 直连，就按原生的两步走。

所以中间灰带着原生那点漂移：默认 8 位图上，通道 128 进选区读回 188， 选区 128 存通道读回 55；而选区与蒙版之间原生会换算，那一对不漂。 32 位线性精度的图像上通道本身就存线性值，六个方向都不漂。

为什么单步看着不对

不是插件算错。通道和蒙版存的是 Y'（sRGB 编码），选区存的是 线性 alpha。原生在通道与选区交界处把 Y' 当线性覆盖率直搬， 128 就变成了 188，反方向压成 55。

往返会互相抵消。188 存回通道又变回 128，所以连着跑两步看不出问题， 单步才明显。这是原生的行为，插件不做补偿。

蒙版是 8bit。极暗处有 ±1 的量化误差，原生也一样；偏移图层按画布 坐标对齐，原生建蒙版时同样如此。

和 Channel to Mask 的关系

Channel to Mask...（Mask 组，带省略号）是同一个动作的可配置版： 能指定通道名、能反相、能一次挂多个图层。

Convert → Channel to Mask（无省略号）是一键版：取通道面板里点中的 那条、不反相。日常右键直接跑一键版，需要细调时走带参数的那个。

六个方向都不依赖自研算子，只调 GIMP 自己的通道、选区、蒙版 PDB。 缺源时会明确说缺什么（没选通道 / 没蒙版 / 图层组没有像素），不会静默什么都不做。

Convert

plugin/convert 转换 Convert

Channels, selections and layer masks, converted in every direction: six menu items, each one click and done — no parameter dialog. Natively these six paths are spread across three places, and mask → channel does not exist at all; it takes a detour through the selection in two steps.

Only a convenience wrapper over native behaviour — no new algorithms here: every pixel comes out of GIMP's own PDB procedures. The plug-in just folds a detour that lives in three different menus and takes three or four steps into a single click, and keeps the result bit-for-bit identical to doing it by hand.

Menu location

Several
  • SuperMrWang → Convert → Channel to Selection
  • SuperMrWang → Convert → Selection to Channel
  • SuperMrWang → Convert → Channel to Mask
  • SuperMrWang → Convert → Mask to Channel
  • SuperMrWang → Convert → Selection to Mask
  • SuperMrWang → Convert → Mask to Selection
  • Layer right-click → SuperMrWang → Convert（同样六项）
  • 通道右键 → SuperMrWang → Convert（以通道为源的两项）

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting

lb-plugin-conv-* 六个过程，全部零参数

A standard PDB procedure; leave an argument empty to take its default.

Why it needs its own entry

three places

Doing the same thing natively means remembering three routes: Select menu to save a channel, the channel context menu to make a selection, and Layers → Mask → Add Layer Mask with a type picked in the dialog. Same family of operations, three locations, and the directions reverse halfway through.

Worse, mask → channel simply is not there: GIMP has no such procedure, so it is "mask to selection" and then "selection to channel" — two steps, two menus. This plug-in makes it one.

Six directions

zero arguments
  • Channel to Selection
  • Selection to Channel
  • Channel to Mask
  • Mask to Channel
  • Selection to Mask
  • Mask to Selection

A menu item without an ellipsis runs immediately: the source is read from the context, so there is nothing to pick in a dialog.

The source is always "current"

  • Channel = the one right-clicked in the Channels dock, else the dock selection, else the only channel in the image
  • Selection = the active pixel selection; none means select-all
  • Mask = the selected layer's layer mask
  • Sinks: a new channel, or masks on every selected layer

An existing mask is dropped and rebuilt, bit-for-bit identical to a fresh native one — change the source and re-run to refresh.

Bit-for-bit with native

the hard requirement

None of the six directions touches a pixel buffer. Each one calls GIMP's own procedure: gimp-image-select-item for a channel to a selection, gimp-selection-save for a selection to a channel, create_mask(SELECTION) for a selection to a mask. Channel ↔ mask has no native entry, so it runs the native two steps.

That means mid greys carry the native drift: on a default 8-bit image a channel value of 128 reads back as 188 in the selection, and a selection value of 128 reads back as 55 in a channel. Selection ↔ mask converts properly in GIMP, so that pair does not drift. On 32-bit linear precision nothing drifts at all.

Why single steps look wrong

It is not the plug-in's arithmetic. Channels and masks store Y' (sRGB encoded); the selection stores linear alpha. Native copies the Y' value straight in as linear coverage, so 128 becomes 188, and the reverse direction squashes it to 55.

Round trips cancel out. 188 stored back into a channel becomes 128 again, so two steps in a row look fine; only a single step shows it. That is native behaviour and the plug-in does not compensate.

Masks are 8-bit. Expect ±1 quantisation in the deep shadows, exactly as native; offset layers align by canvas, also as native.

Relation to Channel to Mask

Channel to Mask... (in the Mask group, with an ellipsis) is the configurable version of the same action: channel by name, invert, several layers at once.

Convert → Channel to Mask (no ellipsis) is the one-click version: it takes the channel you clicked in the dock and does not invert. Use the quick one day to day, the parameterised one when you need to adjust.

None of the six directions depends on this project's operators — they only call GIMP's own channel, selection and mask PDB. A missing source produces an explicit message (no channel found / no mask / layer group has no pixels) instead of silently doing nothing.
