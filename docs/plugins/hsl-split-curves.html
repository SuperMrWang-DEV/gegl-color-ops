HSL Split (Curves)

plugin/hsl-split-curves 曲线 Retouch 修饰

GIMP 给 HSV 和 LCh 都配了分量混合模式，唯独 HSL 没有，也没有 HSL 的色相入口。这个插件不拿 HSV 近似 HSL，而是把三者精确换算后打包进 一张数据图，三条曲线各管一个分量。

菜单位置
  • SuperMrWang → Retouch → HSL Split (Curves) · single
  • SuperMrWang → Retouch → HSL Split (Curves) · multi
  • 图层右键 → SuperMrWang → Retouch → 同上两条

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-hsl-split-curves(image, drawables, group) lb-plugin-hsl-split-curves-multi(image, drawables, group)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

  • lb:hsl-dual
  • lb:hsl-compose
  • gimp:curves

两种模式

两条菜单

菜单里是两条独立的过程——… · single 与 … · multi， 点哪条就是哪个模式。对话框里只剩「收进图层组」一个开关。

single   HSL split            组 · 穿透（带 alpha 时组上还有蒙版）
           └─ 1 · HSL S/L/H     模式 正常      ← 一条算子链算完整 HSL 色

multi    HSL split            组 · 穿透（带 alpha 时组上还有蒙版）
           ├─ 2 · Hue           模式 HSV 色相   ← 只替换 H
           └─ 1 · S / L         模式 正常        ← 算出 S、L 与色相

single 的滤镜栈：decompose（lb:hsl-dual）→ S 曲线（红） → L 曲线（绿） → H 曲线（蓝） → compose（lb:hsl-compose）。

single 还是 multi

S 与 L 是耦合的：C = (1−|2L−1|)·S、V = L + C/2、 S_hsv = C/V。要精确算回 HSV 的 S/V，编码器必须同时读到两者 ——这正是它们要挤进同一张图的原因，两种模式都一样。

multi 在上面再加一层 Hue：借 HSV 的色相模式（HSL 与 HSV 的色相角 完全相等），S、L 原样保留。把 Hue 层的眼睛一关，就能看到「原色相 + 调过 S/L」的中间结果。

single 把色相也收进 compose，一层就够：少一层图、少一次编码量化， 代价是少了那个可以单独关掉的开关。

不拿 L 当 V

把 HSL 的 L 直接当 HSV 的 V 用会差很多：S=0.25 偏 25 码、S=1 偏 64 码（差的正好是 C/2）。本插件在 compose 内部按上式换算， 没有这个近似。

实测：浮点恒等往返 0.0001 码（multi 两层 0.0014 码）、 8 位 0.49 码——single 更准，multi 换的是分层开关； 只改 S 曲线时 L 与色相的偏差 < 0.001 码。转换由 babl 的 HSLA float 完成，与 component-extract 的 hsl-s / hsl-l 同一口径。依赖 lb:hsl-dual / lb:hsl-compose。

HSL Split (Curves)

plugin/hsl-split-curves Curves Retouch

GIMP ships component blend modes for HSV and LCh but not for HSL, and there is no HSL hue entry point either. This plug-in does not approximate HSL with HSV: it converts exactly, packs the three components into one data image and gives each its own curve.

Menu location
  • SuperMrWang → Retouch → HSL Split (Curves) · single
  • SuperMrWang → Retouch → HSL Split (Curves) · multi
  • Layer right-click → SuperMrWang → Retouch → same as the two above

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-hsl-split-curves(image, drawables, group) lb-plugin-hsl-split-curves-multi(image, drawables, group)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

  • lb:hsl-dual
  • lb:hsl-compose
  • gimp:curves

Two modes

two menu entries

The menu holds two separate procedures — … · single and … · multi — and the one you click is the mode you get. The dialog has a single switch left: put everything in a layer group.

single  HSL split group · pass-through (plus a mask when there is alpha)
 └─ 1 · HSL S/L/H mode  Normal  ← one operator chain computes the whole HSL colour

multi   HSL split group · pass-through (plus a mask when there is alpha)
 ├─ 2 · Hue mode      HSV hue  ← replaces H only
 └─ 1 · S / L mode    Normal   ← computes S, L and hue

The single stack is: decompose (lb:hsl-dual) → S curve (red) → L curve (green) → H curve (blue) → compose (lb:hsl-compose).

single or multi

S and L are coupled: C = (1−|2L−1|)·S, V = L + C/2, S_hsv = C/V. Converting back to HSV's S/V exactly means the encoder must read both at once — which is why they share one image in both modes.

multi puts one more Hue layer on top, borrowing HSV's hue mode (HSL and HSV hue angles are identical) while S and L pass through. Switching the Hue layer's eye off shows you "original hue plus the S/L you just edited".

single folds hue into compose and needs one layer only: one layer less, one quantisation less, at the cost of that per-layer switch.

L is not V

Using HSL's L as HSV's V is off by a lot: 25 codes at S=0.25, 64 codes at S=1 (exactly C/2). This plug-in computes the real conversion inside compose instead of approximating it.

Measured

Float identity round trip 0.0001 codes (multi with two layers: 0.0014 codes), 0.49 codes in 8-bit — single is more accurate, multi trades that for the switches. Editing only the S curve leaves L and hue within < 0.001 codes.

The conversion is babl's HSLA float, the same one component-extract's hsl-s / hsl-l uses. Depends on lb:hsl-dual / lb:hsl-compose.
