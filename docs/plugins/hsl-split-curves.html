HSL Split (Curves)

plugin/hsl-split-curves 曲线 Shortcut 快捷方式

GIMP 给 HSV 和 LCh 都配了分量混合模式，唯独 HSL 没有，也没有 HSL 的色相入口。这个插件不拿 HSV 近似 HSL，而是把三者精确换算后打包进 一张数据图，三条曲线各管一个分量。

菜单位置

两处
  • 颜色 → SuperMrWang → Shortcut → HSL Split (Curves)
  • 图层右键 → SuperMrWang → Shortcut → HSL Split (Curves)

两处是同一个动作，处理的是当前选中的那一个图层。图层组不行—— 组没有自己的像素，会直接报错并提示先合并。

脚本调用

lb-plugin-hsl-split-curves(image, drawable, mode, group)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活，装插件时它们必须已注册（build.sh 或 dll 包里都有）：

  • lb:hsl-dual
  • lb:hsl-compose
  • gimp:curves

两种模式

mode 参数
single   HSL split            组 · 穿透（带 alpha 时组上还有蒙版）
           └─ 1 · HSL S/L/H     模式 正常      ← 一条算子链算完整 HSL 色

multi    HSL split            组 · 穿透（带 alpha 时组上还有蒙版）
           ├─ 2 · Hue           模式 HSV 色相   ← 只替换 H
           └─ 1 · S / L         模式 正常        ← 算出 S、L 与色相

single 的滤镜栈：decompose（lb:hsl-dual）→ S 曲线（红） → L 曲线（绿） → H 曲线（蓝） → compose（lb:hsl-compose）。

single 还是 multi

S 与 L 是耦合的：C = (1−|2L−1|)·S、V = L + C/2、 S_hsv = C/V。要精确算回 HSV 的 S/V，编码器必须同时读到两者 ——这正是它们要挤进同一张图的原因，两种模式都一样。

multi 在上面再加一层 Hue：借 HSV 的色相模式（HSL 与 HSV 的色相角 完全相等），S、L 原样保留。把 Hue 层的眼睛一关，就能看到「原色相 + 调过 S/L」的中间结果。

single 把色相也收进 compose，一层就够：少一层图、少一次编码量化， 代价是少了那个可以单独关掉的开关。

不拿 L 当 V

把 HSL 的 L 直接当 HSV 的 V 用会差很多：S=0.25 偏 25 码、S=1 偏 64 码（差的正好是 C/2）。本插件在 compose 内部按上式换算， 没有这个近似。

实测：浮点恒等往返 0.0001 码（multi 两层 0.0014 码）、 8 位 0.49 码——single 更准，multi 换的是分层开关； 只改 S 曲线时 L 与色相的偏差 < 0.001 码。转换由 babl 的 HSLA float 完成，与 component-extract 的 hsl-s / hsl-l 同一口径。依赖 lb:hsl-dual / lb:hsl-compose。
