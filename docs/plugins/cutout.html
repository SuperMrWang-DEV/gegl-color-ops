抠图 / 移除背景

plugin/cutout 蒙版 Mask

把主体从背景里抠出来：图层加一张羽化过的蒙版，主体之外透明，顺手还能 垫一层纯色（白底证件照、电商主图）或一张新背景图。两条路——AI 那条连发丝都能 分开，本地那条对付纯色和渐变背景是毫秒级的。

菜单位置
  • SuperMrWang → Mask → 抠图 / 移除背景（本地）
  • SuperMrWang → Mask → 抠图 / 移除背景（AI）

这几条是同一个动作，处理的是当前选中的那一个图层。图层组不行——组没有自己的像素，会直接报错并提示先合并。

脚本调用
lb-plugin-cutout-local( image, drawable, threshold, seeds, shrink, feather, background, color, bg-file, keep-mask, use-selection) lb-plugin-cutout-ai( image, drawable, model, resolution, sensitivity, refine, shrink, feather, background, color, bg-file, keep-mask)

标准 PDB 过程，参数留空走默认值。

依赖

靠下面这些算子干活。它们已经打进这个插件的下载包（modules-windows-x64 / modules-linux-x64），不用另外去下：

两条路各自管什么

按素材挑
菜单项怎么找主体什么时候用
抠图（AI） 缩略图发给本机 ComfyUI 的 RMBG 节点 （BiRefNet / RMBG-2.0），拿回来的 alpha 当蒙版 头发、毛绒、透明玻璃、绿幕、复杂背景。单张 4~6 秒
抠图（本地） 从四条边的多个种子点泛洪选背景，再反选。已有选区时 直接把选区当主体，只做收边 纯色、渐变、影棚白底；或者想先粗框一下再自动收边。毫秒级

两条路的收尾是同一段代码：蒙版 → 收缩 shrink 像素 → 羽化 feather → 图层蒙版 + Cutout Mask 通道 → 按需垫背景。

输出形态

透明：只加蒙版，导出 PNG 就是透明底。纯色：在照片下面新建一层 纯色（默认白），证件照、主图直接可用。图片：选一张背景图，按 cover 等比缩放铺满、居中裁切，放在照片下面。

三种都是非破坏的：原图层像素没动，蒙版随时能改，背景层删掉就回到透明。

实测

RTX 3070 Ti

SDXL 生成的一张 768×1024 卷发人像，RMBG-2.0 抠图：4.6 秒（含模型加载）， 主体占比 59.6%，发丝成缕保留，白衬衫边缘干净；shrink=1 收掉 RMBG 边界外扩的半像素，白底上看不到白边。

本地版在一张 400×300 的「白底 + 红方块」上：泛洪覆盖四边 100%， 主体内部蒙版 255、四角 0，全程没有 Python 逐像素循环—— gimp-image-select-contiguous-color 是 C 实现，24MP 也是毫秒级。

四个模型，门槛不一样

2026-11 逐个实测

ComfyUI-RMBG 的节点把四个模型摆在同一个下拉里，但它们的准备成本差得远。 插件会把差别写在选项后面，选错时也会说清缺什么，而不是甩一句 No module named …。

模型第一次用要做什么实测
RMBG-2.0 无。装 ComfyUI-RMBG 时就连带下好了（812 MB） 768×1024 人像 4.6 秒，发丝最干净 —— 默认选它
BEN2首次下约 1.1 GB 权重 批量推理快，边缘略软；人像、商品都可以
BEN首次下约 1.1 GB 权重（实测下载 8 分钟） 能用，但没有明显强过 BEN2，下载最久
INSPYRENET 要装 Python 包 transparent-background（连带 onnxruntime），而且它默认走 CPU 没装必炸；装了也比 RMBG-2.0 慢，不推荐

下载那几分钟里 ComfyUI 窗口只多出几行 Downloading…，进度条不动， 插件这边只能等。所以超时提示写的是「正在下约 1.1 GB 权重，再等等」， 而不是「图太大或步数太多」。等不了就换 RMBG-2.0。

想自己核对：python tools/check_cutout_models.py 会把四个模型逐个 真跑一遍，打印每个的耗时与失败原因。

蒙版怎么从 AI 的 alpha 变成选区

AI 回来的 alpha 尺寸是缩略图的（长边 ≤ 2048）。在 Python 里把它插值到 4000×6000 要十几秒；这里建一个同尺寸的临时图层，RGB=白、A=alpha， 插进图像后让 GIMP 自己 gimp-layer-scale 到画布大小， 再 select-item 取它的 alpha——缩放是 C 做的，Python 只搬一次 mw×mh×4 字节。

两个静默失败

泛洪一个点都没选中时 GIMP 不报错：选区是空的，反选之后就成了整张图， 看起来像「把主体抠成了全白」。所以先看边框采样点的命中率，低于 35% 直接 报错让人调阈值或换 AI 版。

背景层插错位置会盖住照片：insert_layer 的 position 从 顶部数，插到照片的 pos 是插在它上面。要插 pos + 1。

Cut Out / Remove Background

plugin/cutout Mask Mask

Lift the subject off its background: one feathered mask on the layer, everything else transparent — optionally with a flat colour (ID photos, product shots) or a new background picture underneath. Two routes: the AI one separates single hairs, the local one eats plain and gradient backgrounds in milliseconds.

Menu location
  • SuperMrWang → Mask → Cut Out (Local)
  • SuperMrWang → Mask → Cut Out (AI)

These are all the same action, applied to the one layer you have selected. Layer groups do not work — a group has no pixels of its own, so the plug-in stops with an explicit error and asks you to merge first.

Scripting
lb-plugin-cutout-local( image, drawable, threshold, seeds, shrink, feather, background, color, bg-file, keep-mask, use-selection) lb-plugin-cutout-ai( image, drawable, model, resolution, sensitivity, refine, shrink, feather, background, color, bg-file, keep-mask)

A standard PDB procedure; leave an argument empty to take its default.

Dependencies

The operators below do the work. They are already inside this plug-in's download (modules-windows-x64 / modules-linux-x64) — nothing else to fetch:

Which route does what

pick by photo
Menu itemHow it finds the subjectWhen to use it
Cut Out (AI) A downscaled copy goes to the local ComfyUI RMBG node (BiRefNet / RMBG-2.0); the returned alpha becomes the mask Hair, fur, glass, green screen, busy backgrounds. 4–6 s per image
Cut Out (Local) Flood-fills the background from several seeds per border, then inverts. With an existing selection, the selection is the subject and only its edge is refined Plain, gradient or studio backgrounds; or rough-select first and let it clean the edge. Milliseconds

Both routes end in the same code: mask → shrink by shrink px → feather by feather → layer mask plus a Cutout Mask channel → optional background underneath.

Output

Transparent: just the mask — export a PNG and the background is gone. Solid colour: a flat layer (white by default) is created under the photo. Image: pick a picture; it is scale-to-cover and centre-cropped under the photo.

All three are non-destructive: original pixels stay, the mask stays editable, and deleting the background layer brings transparency back.

Measured

RTX 3070 Ti

A 768×1024 SDXL portrait with curly hair, cut out with RMBG-2.0: 4.6 s including model load, 59.6 % of the pixels kept, individual strands preserved, the white shirt edge clean. shrink=1 removes the half-pixel the model adds outward, so no white fringe shows on a light background.

The local route on a 400×300 “white background + red block” test image: border coverage 100 %, mask 255 inside the subject and 0 at all four corners, with no per-pixel Python loop — gimp-image-select-contiguous-color is C, so even 24 MP is a matter of milliseconds.

Four models, four different thresholds

tested one by one, Nov 2026

The ComfyUI-RMBG node lists four models in one dropdown, but getting them to run is not the same job. The plug-in appends the difference to each entry and, when one fails, says what is missing instead of echoing No module named ….

ModelFirst run needsMeasured
RMBG-2.0 Nothing — downloaded along with ComfyUI-RMBG (812 MB) 4.6 s on a 768×1024 portrait, cleanest hair. The default
BEN2A one-time ~1.1 GB weight download Faster in batches, slightly softer edges; fine for people and products
BENA one-time ~1.1 GB weight download (8 min here) Works, but nothing over BEN2 except the longer wait
INSPYRENET The transparent-background Python package (plus onnxruntime), and it runs on CPU by default Fails without the package; slower than RMBG-2.0 even with it. Not recommended

While the weights download, the ComfyUI console only prints a few Downloading… lines and the progress bar does not move — the plug-in can only wait. So the timeout message reads “downloading about 1.1 GB, give it a few more minutes” rather than “image too large or too many steps”. If you would rather not wait, switch back to RMBG-2.0.

To check for yourself: python tools/check_cutout_models.py runs every model once for real and prints its time and failure reason.

Turning an AI alpha into a selection

The alpha comes back at thumbnail size (long edge ≤ 2048). Interpolating that to 4000×6000 in Python takes tens of seconds, so instead a temporary layer of the same size is created with RGB=white and A=alpha, inserted, scaled to the canvas by gimp-layer-scale, and finally select-itemd. The scaling is C; Python moves mw×mh×4 bytes once.

Two silent failures

A flood fill that selects nothing reports no error: the selection is empty, inverting gives the whole image, and the result looks like “the subject became pure white”. So the border coverage is checked first; below 35 % it stops and says to raise the threshold or use the AI route.

A background layer at the wrong index hides the photo: insert_layer positions count from the top, so inserting at the photo's own position puts it above. It has to be pos + 1.
