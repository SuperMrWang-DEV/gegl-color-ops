安装与排错

没有安装程序，也没有注册表：把模块文件放进 GEGL 的插件目录，重启 GIMP 就完事。

环境要求

  • GIMP 3.x（3.0 / 3.2 实测），自带 GEGL 0.4。
  • Windows x64 用现成的 .dll，Linux x86_64 用 .so； 两端都有预编译包，37 个模块齐全。
  • 不需要 Python 运行时——算子是 C 编译的 GEGL 模块。

安装

把压缩包解开，把里面的模块文件（.dll / .so）全部放进 用户插件目录（目录不存在就新建）：

系统目录
Windows%LOCALAPPDATA%\gegl-0.4\plug-ins
Linux~/.local/share/gegl-0.4/plug-ins
macOS~/Library/Application Support/gegl-0.4/plug-ins

然后完全退出 GIMP 再打开（不是关窗口）。模块只在启动时扫描一次。

确认加载成功，可以在命令行问 GEGL：

gegl --info lb:hsl-levels

能打印出参数表就说明注册上了。GIMP 自带的 gegl 在安装目录的 bin/ 里，Windows 上通常是 C:\Program Files\GIMP 3\bin\gegl.exe。

怎么用

菜单在 图像 → 颜色 → SuperMrWang：色阶家族（Levels / LAB / HSL / HSB / LCH / CMYK / HSI Levels）收在 Levels 子菜单里，分量曲线那几个 一键插件收在 Shortcut 子菜单里，其余分 Tone / Color / Blend / Mask 四组。也可以在 /（搜索动作）里直接输算子名。

绝大多数算子是 Point 或 Filter 类型，GIMP 会把它们当非破坏性 fx 挂在图层上——参数随时能改，原像素不动。双输入算子（应用图像 / 计算）目前只能合并应用。

自己编（可选）

需要 GIMP 3 自带的 GEGL 开发头文件与 gcc（Windows 上 MSYS2 的 mingw64 工具链即可）：

git clone https://github.com/SuperMrWang-DEV/gegl-color-ops.git
cd gegl-color-ops
./build.sh              # 产物在 build/
./install.sh --verify   # 顺带拷进插件目录并逐个验证注册

Linux / macOS 也可以用 meson：

export PKG_CONFIG_PATH="/path/to/gimp/lib/pkgconfig"
meson setup build-meson && ninja -C build-meson

排错

菜单里看不到

  • 路径对不对：必须是 gegl-0.4/plug-ins，不是 GIMP 的 plug-ins。
  • 有没有重启：GIMP 启动后才扫描，热拷进去不生效。
  • 位数/依赖：用 GIMP 自带的那份 GEGL 运行时，别混用系统里另一套 GEGL。
  • 用 gegl --info lb:xxx 单独验：命令行能看到、GIMP 看不到，通常是 GIMP 版本太旧。

同一个算子出现两次 / 报重复注册

插件目录里同时存在旧文件名的模块（早期是 12 个独立仓库，文件名不一样）。 删掉旧名字的 .dll 即可，详见仓库 README.md 的「与旧布局的对应关系」。

打开旧图提示未知参数

算子升级时偶尔会删掉合并过的参数，旧 XCF 里存的值会丢。加载只警告、不报错， 但要重新调一次。升级前建议先另存一份。

常见问题

和 经典图像编辑器 的调整图层结果一致吗？

多数算子的目标是「肉眼与 8 位输出一致」。实测残差写在每篇算法说明里， 通常是中位 0–4 码；有明确对不上的段落时也会说明（例如 经典图像编辑器 在个别对角线上的硬裁切）。

为什么叫 lb: 前缀？

GEGL 的 id 必须唯一。前缀避免和 GIMP 自带算子撞名——撞了会静默加载失败， 所以这个工程里所有 id 和 GType 名都带前缀。

会进 GIMP 官方仓库吗？

不会。这是独立的第三方算子集，按 GPL-3.0 发布，自己装进用户插件目录即可。
