# lb:clarity-dehaze — 清晰度 / 去朦胧

PS Camera Raw「基本」面板上最常拖的两个滑块。GIMP 3 没有等价物：
`gegl:unsharp-mask` 是高频锐化，跟清晰度不是一回事；去朦胧更是完全没有。

    SuperMrWang → Color → Clarity & Dehaze

插件 `plugin/clarity-dehaze/` 是它的对话框；算子本身不依赖插件，挂在图层滤镜上
就是非破坏的。

## 清晰度 / clarity

不是锐化。锐化动高频（像素级边缘），清晰度动**中频**（几十像素尺度的明暗过渡）。
所以它能把平的照片打开，却不放大噪点。

    Y     = 0.2126 R + 0.7152 G + 0.0722 B      编码值上的 Rec.709
    low   = 三次盒式模糊 ≈ 高斯，半径 clarity-radius
    d     = Y − low
    d'    = h · tanh(d / h)                     h 由 clarity-protect 决定
    w     = 1 − |2Y − 1|²                       中间调权重
    gain  = 1 + 强度 · w · d' / max(low, 0.08)
    RGB  *= gain

三个选择都有理由：

- **相对增益**（除以 `low`）而不是绝对差值。暗部的 `low` 只有 0.03，绝对差值
  加回去就是噪点；除一下，暗部的增益自然变小，同时亮部也不会一推就溢出。
- **tanh 压幅**。`|d|` 远大于 `h` 的地方（硬边缘两侧的过冲）被压到 ±h，
  于是硬边不会长出亮边 / 黑边；幅度在 `h` 以内的中频细节几乎原样通过。
  这就是「清晰度」和「USM」的分界线。`h = 0.03 + (1−protect)²`，protect 从
  0 到 1，`h` 从 1.03 收窄到 0.03。
- **中间调权重** `1 − |2Y−1|²`。纯黑和纯白没有可分配的空间，硬推只有噪点
  和死白。

半径 40 px 是「中频」的边界：再小滑向锐化，再大滑向全局对比（那就是拉曲线）。
1920 宽的照片上 40 px ≈ 画面宽度的 2%。

强度为负 = 去清晰度：柔化中频但保留细节，比高斯模糊体面，适合皮肤。

## 去朦胧 / dehaze

大气散射模型：`I = J·t + A·(1−t)`，`t` 随距离衰减。He, Sun & Tang (2009)
的暗通道先验给了一个便宜的逆解：

    dark  = min over window( min(R,G,B) )       窗口 dehaze-radius
    A     = 暗通道最亮 0.1% 像素的原图均值       直方图找阈值，不排序
    t     = 1 − ω · dark / max(lum(A), ε)       夹在 [0.12, 1]
    J     = (I − A) / t + A
    O     = I + s · (J − I)                     s = 强度/100

- **ω**（`dehaze-keep`，默认 0.95）留一点雾。全解 `ω=1` 看着假，留一点空气
  反而像照片。
- **窗口**（`dehaze-radius`，默认 15 px）要比雾里最亮的物体大，否则透射率
  跟着物体轮廓走而不是跟着远近走，去完雾像贴了一层灰补丁。
- **`t` 下限 0.12**。再低，`1/t` 会把噪声乘十几倍，暗部变彩色斑块。
- **饱和补偿**（`dehaze-saturation`）默认 0，通常给 10–20：去雾按 `1/t` 提亮，
  颜色被拉向大气光的灰白，补一点饱和拉回来。只围绕亮度放大色度，色相不动。

强度为负 = 加雾，做空气透视用。

### 什么时候不管用

暗通道先验假设「无雾画面里总有一个通道很暗」。天空占满画面、或者大面积白色
主体（雪、白墙）时假设不成立，`A` 会落在主体上，结果是天空发灰、白墙出现
暗角状色块。彩色雾（沙尘暴的黄、水雾的青）也不适用——先验假设雾是灰的。
这两种情况把强度压到 30 以下，或者只用清晰度。

## 执行顺序与整幅读取

先去雾、再清晰度。清晰度用的是亮度 `Y`，而去雾改过 RGB，所以算子内部在去雾
之后重算一遍 `Y`——沿用它之前的值会让低频层和新像素对不上，暗部出一圈晕。

`get_required_for_output` 返回**整幅**：大气光 `A` 需要全图统计，只给 roi 的话
预览和导出会用两个不同的 `A`，观感会跳。

两个强度都是 0 时走真正的恒等快路径（`gegl_buffer_copy`），不做浮点往返。

## 性能（1600×2400）

| 参数 | 耗时 |
| --- | --- |
| 两个都是 0（快路径，含图层复制） | 0.20 s |
| 只开清晰度（半径 40） | 2.03 s |
| 只开去朦胧（窗口 15） | 1.21 s |
| 两个都开 | 3.59 s |

清晰度是三遍盒式模糊（六个方向 pass），去朦胧是单调队列求窗口最小值 + 直方图
估大气光，都是 O(N)，窗口变大不变慢。

## 回归

`tools/check_clarity_dehaze_gimp.py`，24 项：

- 恒等逐字节、挂滤镜后原图层不动；
- 纯色图不被清晰度改（`d = 0`）；
- 正弦条纹 `clarity=+80` 对比上升、`−80` 下降；
- 硬边相对过冲 < 0.35，保护 1.0 时压到 0.025；
- 中间调增益 1.86× 大于暗部 1.56×；
- 合成雾图 `I = J·t + A(1−t)` 反解：MAE 40.4 → 14.0（含一块三通道都等于 A 的
  天空，否则 `A` 会被估低——暗通道取的是 `min(R,G,B)`，彩色块永远不亮）；
- 纯雾图（`I ≡ A`）不爆；
- 负强度加雾：对比降、整体变亮；
- 饱和补偿只扩色度；
- 极端参数无 NaN、不整幅黑白；
- 性能。

算子侧验证只靠这一份（没有纯 Python 的数学对拍）：测试图都是**可解析**的
（正弦、硬边、合成雾），期望值直接按公式算，不需要第二份实现。

## 没做的

- 局部去雾（按深度图或亮度分区只处理天空）——加参数的事；
- 多尺度清晰度（当前半径只有一个）——同理；
- PS 那种「自动」按钮——估参数的事，不是算子的事。
