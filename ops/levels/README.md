# lb:levels · Levels

PS「色阶」对话框的复刻：**复合 + R/G/B 四组**，每组都是
「输入黑场 / 输入灰点 / 输入白场 + 输出黑场 / 输出白场」五个数，
刻度 0–255，和 PS 的数字框一一对应。

对应面板：`Colors → SuperMrWang → Tone → Levels`。

## 模型

单通道：

```
t   = clamp((v - inLow) / (inHigh - inLow), 0, 1)
t'  = t ^ (1 / gamma)
out = outLow + t' * (outHigh - outLow)
```

- `inLow` 及以下压成 `outLow`，`inHigh` 及以上压成 `outHigh`，
  中间按 gamma 曲线重新分布；
- **gamma > 1 提亮，gamma < 1 压暗**（与 PS 数字框同向。注意这与
  「标准 gamma」的直觉相反，因为 PS 的滑块值直接进的是 `1/gamma` 的倒数位置；
  指数写成 `t^gamma` 会让方向整个反过来）；
- 输入区间会把整段拉伸：设了 `inLow = 64` 之后，`v = 240` 会变成 `235`，
  不是原样保留；
- `inHigh == inLow` 时区间塌成一点，按台阶处理（≥ 该值为白），不除零。

执行顺序：**先复合组（三通道同一条曲线），再各通道组**。各通道组默认恒等，
所以「只动复合」与 PS 的 RGB 通道模式逐位一致；「只动红」等价于 PS 的
Red 通道模式。四组可以叠加使用，这比 PS 一次只能选一个通道更强。

## 域

在 **8bit sRGB 伽马域**逐通道直接算，不回线性光。色阶的黑白场是
「0–255 编码值」的语义，喂线性光会让数字框对不上 PS。算子自己在 `prepare`
里把两个 pad 钉成感知格式（`R~G~B~A float`），不需要前置 `linear-rgb`。

## 验证

```bash
python tools/check_levels_ps.py
```

11 项，两层：

**A 数学层** —— Python 侧逐行复刻 C 模型，256 列灰阶探针（第 x 列灰度恰好是 x，
采样不插值）逐像素比对，全 0.00 码：

| 用例 | 检查点 |
|---|---|
| 全默认 | 0 / 20 / 128 / 240 / 255 恒等 |
| 输入黑场 64 | 归零、中段、高段被拉伸到 235 |
| 输入白场 192 | 全白、暗端被拉伸到 27 |
| 输出收缩 50–200 | 两端落到 50 / 200，中段线性 |
| gamma 2.0 / 0.5 | 提亮 / 压暗，端点不动 |
| 组合 | 50 / 0.7 / 200 → 30 / 220 |
| 单通道 | 只动红，绿蓝不动 |

**B 基准层** —— 回放两个公开的 PS 实测点，专门卡住 gamma 的**方向和指数形式**：

| 输入 | gamma | PS 实测 | 本算子 | 偏差 |
|---|---|---|---|---|
| 154 | 0.46 | 84 | 85 | 1.19 码 |
| 200 | 1.646 | 220 | 220 | 0.01 码 |

这两点很要紧：只做「C 和 Python 自洽」的验证是查不出指数写反的，两边会一起错。
基准取自 Adobe 社区里用户量出来的像素值与公认公式 `out = in^(1/gamma)`。

## 本机为什么没做逐码标定

PS 2025（26.10.0）在这台机器上：`executeAction` 的 `Lvls` 事件、以及
`Mk` 创建调整图层，都直接抛「不能完成命令，因为程序错误」；DOM 的
`LayerKind.LEVELS` 也给「只能改为文本或正常」。诊断日志见
`../lvls-cal/_diag2.txt`。`colorRange` 反而能跑，所以不是 ExtendScript 整体
不可用，是这两个命令在这套安装里被挡了。

因此基准改用公开实测值，而不是本机标定。**如果你在另一台机器上能跑 PS 脚本，
可以把 `lvls-cal/` 里的 `ps_levels.jsx` 修好重跑，就能升级成逐码标定。**

## 与 GIMP 自带「色阶」的区别

GIMP 的 `Colors → Levels` 是 app 层私有实现，GEGL 里的 `gegl:levels` 只有
`in-low / in-high / out-low / out-high` **四个**属性——没有 gamma，没有每通道，
也没有 0–255 的数字刻度（`gegl --info gegl:levels` 可查）。所以这个算子补的是
GEGL 算子层面的真空白：脚本、批处理、`gegl` 命令行里都能用 PS 的色阶参数。
