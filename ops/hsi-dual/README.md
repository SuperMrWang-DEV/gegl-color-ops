# lb:hsi-dual · HSI 三联提取

把一张图打包成**一张数据图**：`R = 饱和度`、`G = 强度`、`B = 色相/360`，全部 0…1。
alpha 恒为 1。

```
原图 ──lb:hsi-dual──> (R=S, G=I, B=H/360)
                          │
              ┌───────────┼───────────┐
          S 曲线(红)   I 曲线(绿)   H 曲线(蓝)
              └───────────┼───────────┘
                          ▼
                    lb:hsi-compose  ──> 真实颜色
```

## 为什么三个分量挤在一张图里

HSI 的定义与 GIMP 现成的分量混合模式**一个都对不上**：

```
I = (R+G+B)/3          HSV 的 V = max        ✗
S = 1 − min/I          HSL 的 S ≠            ✗
H = 余弦定义的角度      HSV 的参数角          ✗ 最多差 1.117°
```

色相那一条尤其容易被忽略：HSI 的色相角是

```
cos H = [(R−G) + (R−B)] / (2·√((R−G)² + (R−B)(G−B)))
```

它量的是色度矢量在等亮度平面里的**真实夹角**；HSV 的色相是六边形投影上的参数角。
两者只在 0°/30°/60°… 重合，15°、45°、75°… 处各偏 ±1.08°。

所以就算把色相层接到「HSV 色相」模式上，也有两个问题：角度不是同一个（差 1°，饱和色
上折算几个码值），而且那个模式保留的是 HSV 的 S/V，**HSI 的 S、I 会被带走**——实测换
一条色相曲线，I 偏 0.085（约 22 码）。于是三个分量只能联合算，一层搞定。

## 输入输出

| | 格式 | 含义 |
|---|---|---|
| input | `R'G'B'A float` | 滤镜栈的编码域缓冲 |
| output | `R'G'B'A float` | **数值是数据不是颜色**：0.85 / 0.45 / 0.583 = S 85%、I 45%、色相 210° |

转换用的是本仓库 `common/color-levels.h` 里那一套，与 `lb:hsi-levels` 同一份代码：
`I = (R+G+B)/3`、`S = 1 − min/I`、色相按余弦式。

alpha 恒写 1：分量层必须不透明，透明度交给组蒙版。

## 实测

`tools/check_hsi_split.py` 里 `dual → compose` 恒等往返：32 位浮点图 **0.0001 码**，
8 位图 **0.499 码**（只剩量化）。改任一条曲线后，结果落在「只有那个分量变了」的
HSI 点上：S、I 误差 < 0.0001，色相角误差 **0.0013°**。

## 注意

- 输出是数据图，**不要直接看它当照片**。
- 它和 `lb:hsi-compose` 是配对使用的。只装一个没有意义。
- HSI 的色域是六边形棱锥，不是立方体：S、I 推到极端时逆变换会出 sRGB 色域，
  出界部分由 compose 裁掉。
