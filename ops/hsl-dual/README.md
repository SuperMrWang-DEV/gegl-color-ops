# lb:hsl-dual · HSL 双通道提取

把一张图打包成**一张数据图**：`R = HSL 饱和度`、`G = HSL 明度`、`B = 色相/360`，
全部 0…1。alpha 恒为 1。

```
原图 ──lb:hsl-dual──> (R=S, G=L, B=H/360)
                          │
                    ┌─────┴─────┐
                 S 曲线(红)   L 曲线(绿)
                    └─────┬─────┘
                          ▼
                    lb:hsl-compose  ──> 真实颜色
```

## 为什么要把 S 和 L 塞进同一张图

HSL 的饱和度与明度是耦合的：

```
C = (1 − |2L − 1|)·S        V = L + C/2        S_hsv = C/V
```

想把 HSL 的 (S, L) 精确换回 HSV 的 (S, V)，编码器必须**同时**读到这两个值。分成
两张灰度图的话，每张只有自己的分量，两条互相独立的 1D 曲线表达不了这个二元映射
——只在「只动其中一个、另一个恒定」时才碰巧正确。

塞进一张图后，两条曲线各挂一个通道（红、绿），再由 `lb:hsl-compose` 一起读，就
精确了。这就是 `HSL Split (Curves)` 用它当第一道滤镜的原因。

## 输入输出

| | 格式 | 含义 |
|---|---|---|
| input | `R'G'B'A float` | 滤镜栈的编码域缓冲，与 `component-extract` 同域 |
| output | `R'G'B'A float` | **数值是数据不是颜色**：0.6 / 0.5 / 0.583 = S 60%、L 50%、色相 210° |

转换由 babl 的 `HSLA float` 完成，与 GIMP 自己的 HSL（`component-extract` 的
`hsl-s` / `hsl-l`）同一口径；本算子只做通道重排。babl 的输出本来就是 0…1 归一化
（`h/360`、`s`、`l`），不需要再缩放。

alpha 恒写 1：分量层必须不透明，透明度交给组蒙版（半透明的混合层会按 alpha 做
lerp 而不是纯替换）。

## 实测

`tools/check_hsl_split.py` 里 `dual → compose` 恒等往返：32 位浮点图 **0.0002 码**，
8 位图 ≤ 1 码（只剩量化）。无色像素（S = 0）的色相在 babl 侧无定义，算子把非有限
值折成 0，不会把 NaN 漏进缓冲。

## 注意

- 输出是数据图，**不要直接看它当照片**：它看起来是某种奇怪的彩色，这是正常的。
- 它和 `lb:hsl-compose` 是配对使用的。只装一个没有意义。
