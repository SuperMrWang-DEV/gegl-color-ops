# lb:hsv-compose · HSV 合成

把数据图还原成真实颜色：`R = 饱和度`、`G = 明度`、`B = 色相/360`（都是 0…1），
按 HSV 定义算出 RGB。

```
(R=S, G=V, B=H/360) ──lb:hsv-compose──> 真实颜色
```

## 输入约定是硬的

本算子**无法分辨**输入是一张数据图还是一张普通照片——它一律按「R 是饱和度、
G 是明度、B 是色相」解释。挂错地方会把照片当成数据算出一张乱七八糟的图。

正常用法是紧跟在 `lb:hsv-dual` 之后（中间夹三条曲线）：

```
lb:hsv-dual → S 曲线(红) → V 曲线(绿) → H 曲线(蓝) → lb:hsv-compose
```

## 为什么不用「HSV 分量混合模式」

GIMP 的 `HSV Hue / HSV Saturation / HSV Value` 三个模式合起来也能改 HSV，但每层
只看得见一个分量：色相层换了角度，它保留的仍是下层的 S、V——对 HSV 来说这恰好
就是「只改色相」，所以旧版能用。代价是三层、每层要先把分量抽成灰度、曲完再编码
成「携带该分量」的颜色，8 位图上还得靠组内浮点缓冲才不偏色。

一次合成没有这个包袱：三个分量在同一条管线里，算完就是最终颜色。

## 实测

- `dual → compose` 恒等往返：32 位浮点 **0.0002 码**，8 位 **0.49 码**。
- 在完整插件里（`tools/check_hsv_split.py` 33 项）：改 S 曲线后结果的 V 与色相
  偏差 **&lt; 0.001 码**。

## 注意

- 输出 alpha 恒 1，理由同 `lb:hsv-dual`。
- 输入超出 0…1 的值会被夹紧；NaN 折成 0。
- 色相为环形量：0 与 1 是同一个角度，数据图里不要指望「1.0 表示比 0.0 大」。
