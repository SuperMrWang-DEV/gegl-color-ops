# lb:hsv-dual · HSV 双通道提取

把一张图打包成**一张数据图**：`R = HSV 饱和度`、`G = HSV 明度`、`B = 色相/360`，
全部 0…1。alpha 恒为 1。

```
原图 ──lb:hsv-dual──> (R=S, G=V, B=H/360)
                          │
                 ┌────────┼────────┐
              S(红)     V(绿)    H(蓝)
                 └────────┼────────┘
                          ▼
                    lb:hsv-compose  ──> 真实颜色
```

## 为什么要挤进同一张图

HSV 的三个分量互相耦合：

```
V = max(R,G,B)              S = (max − min) / V
H = 由三者比例决定（60° 一档的线性插值）
```

想让「只改 S、V 与 H 不动」成立，合成器必须同时读到三者。拆成三张灰度图的话，
只能靠 GIMP 的 HSV 分量混合模式逐层替换——那是 `HSV Split (Curves)` 的旧做法：
三层、每层 `extract → 曲线 → encode`，三次编码、三次量化。

一张图 + 三条曲线 + 一次合成，同样精确，但少两层、少一半滤镜。

## 输入输出

| | 格式 | 含义 |
|---|---|---|
| input | `R'G'B'A float` | 滤镜栈的编码域缓冲，与 `component-extract` 同域 |
| output | `R'G'B'A float` | **数值是数据不是颜色**：0.6 / 0.8 / 0.583 = S 60%、V 80%、色相 210° |

转换由 babl 的 `HSVA float` 完成，与 GIMP 的 HSV 分量模式同一口径；babl 的输出
本来就是 0…1 归一化（`h/360`、`s`、`v`），本算子只做通道重排。

alpha 恒写 1：分量层必须不透明，透明度交给组蒙版。

## 实测

`tools/check_hsv_split.py` 里 `dual → compose` 恒等往返：32 位浮点 **0.0002 码**，
8 位 **0.49 码**（就是量化本身）。灰像素（S = 0）的色相在 babl 侧无定义，算子把
非有限值折成 0，不会把 NaN 漏进缓冲。

## 注意

- 输出是数据图，**不要直接看它当照片**。
- 它和 `lb:hsv-compose` 配对使用，只装一个没有意义。
