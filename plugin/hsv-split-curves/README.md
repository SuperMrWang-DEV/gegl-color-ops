# HSV 分量层 + 曲线（GIMP 3 Python 插件）

> 把当前图层拆成 **H / S / V** 三张分量层，每层挂一条**可编辑曲线**，再用「颜色」
> 组的 **HSV 色相 / HSV 饱和度 / HSV 明度** 三条混合模式叠回去。
> 恒等曲线时逐位还原原图 —— 所以「调曲线」就等于「在 HSV 空间里调那一个分量」，
> 顺带补上了 GIMP 一直没有的 HSL/HSV 分量曲线。

菜单：`颜色 → SuperMrWang → HSV Split (Curves)`，也挂在 `图层右键 → SuperMrWang` 下。

## 生成的结构

```
HSV split                 组，混合模式 = 穿透
  ├─ 1 · Hue              模式 HSV 色相      extract → curve → encode×3
  ├─ 2 · Saturation       模式 HSV 饱和度    extract → curve → encode×3
  ├─ 3 · Value            模式 HSV 明度      extract → curve
  └─ 原图层（不动）
```

每层的滤镜栈（图层面板里从下往上就是执行顺序）：

| 序号 | 滤镜 | 作用 |
|---|---|---|
| `1 · extract` | `gegl:component-extract` | 抽出该分量，输出灰度（`hue` / `hsv-s` / `hsv-v`） |
| `2 · curve` | `gimp:curves`（通道 = 值） | **给用户调的那条**，默认恒等 |
| `3 · encode` ×3 | `gimp:curves`（通道 = R / G / B） | 把灰度重新编码成「携带该分量」的彩色，混合模式才读得出来 |

Value 层不需要编码：**灰色本身就是 V**，所以只有两条滤镜。

## 为什么需要 encode 这三步

灰度像素的色相、饱和度是**无定义**的。把 H 灰度层直接设成「HSV 色相」模式不会有
任何效果——混合模式从灰里读不出色相。必须先把灰度映射到色环上的真实颜色。

这三条编码都是「灰度 → 单通道」的一维映射，用三条 `gimp:curves` 就能精确表达，
**不需要任何 `lb:` 算子**（原来干这事的 `lb:gray-to-component` 已于 2026-11-15
废弃；实测它在真实滤镜栈里把输入当线性光读，往返是错的，约 83–255 码偏差）。

| 层 | 编码公式（sRGB 编码值域） |
|---|---|
| Hue | `hsl(g·360°, 1, 0.5)` 逐通道——饱和度/明度拉满的色相轮；色相模式只读色相，另两个分量无所谓 |
| Saturation | `(1, 1−g, 1−g)`——红相、V=1 的 HSV 饱和度；同样只读饱和度，取直线最省 |
| Value | 恒等（灰层本身就是 V） |

## 实测精度

`tools/check_hsv_split.py`（跑在 GIMP 3.2.8 的 Python 里，18 项）：

| 场景 | 结果 |
|---|---|
| 32 位浮点图，恒等曲线往返 | 最大通道误差 0.00196（**0.50 码**） |
| 8 位图，恒等曲线往返 | 最大通道误差 0.00196（**0.50 码**） |
| 8 位图，改曲线 vs 直接改 HSV 的数学期望 | ≤ 1.84 码 |
| 真实 512×512 图，恒等往返（PNG 逐像素比对） | 最大 **1 码**，仅 0.335% 的通道值有差异 |
| 透明区域 alpha | 逐位保留（分量混合模式沿用下层 alpha，不需要蒙版） |

误差来源是 `gimp:curves` 内部的 **256 项查表**（色相环上一个采样点 = 1.4°），
不是公式；单位曲线本身实测 0 误差。想更准就把图像设成 16/32 位浮点——但曲线
的 256 项 LUT 依然是下限。

## 用起来的几条经验

- **改 `2 · curve` 就行**，`3 · encode` 别动（动了颜色就读错了）。
- **色相曲线必须连续**：两端相等、中间不跳变。用 `(t+Δ) mod 1` 做**整体色相旋转**
  会在跳变点插值出一条约 1.4° 宽的伪彩带（实测有）。要旋转色相请用
  `lb:hue-saturation`；这条曲线适合「压缩/拉伸某段色相」这类连续映射，比如
  `t + 0.04·sin(2πt)`。
- 三层的顺序别换：**V 在最下、H 在最上**。S 是相对 V 的量，先定 V 再定 S 语义才一致。
- 图层自带的非破坏滤镜不会被复制（`new_from_drawable` 只取像素）；要保留就先合并。
- 图层组不能直接拆（没有自己的像素），先右键 → 合并图层组。
- 想「烘焙」成普通像素：对三层执行 `图层 → 合并图层组`，或删掉组只留原图。

## 安装

仓库根的 `./install-plugin.sh` 会把 `plugin/` 下每个子目录拷进 GIMP 的
`plug-ins/`；也可以手动把本目录整个复制过去：

```
Windows: %APPDATA%\GIMP\3.x\plug-ins\hsv-split-curves\
Linux:   ~/.config/GIMP/3.x/plug-ins/hsv-split-curves/
```

重启 GIMP 后出现在 `颜色 → SuperMrWang`。

批处理调用（PDB）：

```scheme
(lb-plugin-hsv-split-curves RUN-NONINTERACTIVE image drawable TRUE)
```

第三个参数 `TRUE` = 收进「HSV split」穿透组，`FALSE` 就直接叠在原图层上方。

## 与已有算子的关系

这套不是替代 `lb:hsl-levels` / `lb:lch-levels`，而是补两条它们覆盖不到的路：

1. **交互**：曲线是 GIMP 原生控件，可加控制点、可存 XCF、可随时改；等级算子要
   弹对话框、参数是数值。
2. **分层**：三个分量各自成层，可以分别开关、调不透明度、加蒙版、套别的滤镜。

代价是三层分量层、多条缓冲往返。批处理、预设、极致精度还是用 `lb:` 算子。

## 已知限制

- LCh 版（L/C/h）**没做**：GIMP 的 `gegl:component-extract` 的 `lch-c` 量程是
  C/200（D50 适配 Lab），编码端与 `LCh Chroma` 混合模式的口径对不上，实测恒等
  往返还有 83 码残差，需要单独标定后再加。
- 8 位以外的精度受曲线 LUT 限制，见上表。
