# LCh 分量层 + 曲线（GIMP 3 Python 插件）

> 把当前图层拆成 **L / C / h** 三张分量层，每层挂一条**可编辑曲线**，再用「颜色」
> 组的 **LCh 明度 / LCh 彩度 / LCh 色相** 三条混合模式叠回去。恒等曲线时还原原图
> ——「调曲线」就等于「在 CIE LCh 空间里调那一个分量」。
>
> 选 LCh 而不是 HSV，是因为它是 GIMP 分量混合模式里**唯一完整、且没有 legacy
> 包袱**的一组（H / C / L / Color 四项齐全，另有一个 Luminance）。HSV 组里那个
> `HSL Color` 还混了模型，见 `plugin/hsv-split-curves/`。

菜单：`颜色 → SuperMrWang → LCh Split (Curves)`，也挂在 `图层右键 → SuperMrWang` 下。

## 生成的结构

```
LCh split                 组，混合模式 = 穿透（带 alpha 时组上还有一张蒙版）
  ├─ 3 · Lightness        模式 LCh 明度      extract → curve → encode
  ├─ 2 · Chroma           模式 LCh 彩度      extract → curve → encode
  ├─ 1 · Hue              模式 LCh 色相      extract → curve → encode   ← 垫底
  └─ 原图层（不动，可以隐藏）
```

**层序不能反，这是「藏掉原图层还能还原」的关键。** 分量混合模式只替换一个分量，
另外两个从下行读。最底层下面什么都没有，所以它必须自带真实色相——这里用的是等
L*、等 C* 的色相圆。早期版本把 Lightness 放在最底：那是灰（C=0），上面两层换 C、
换 H 时读到的都是 0，怎么换都还是灰，原图一隐藏整幅就还原不出来。

合成顺序自下而上：**色相定 H → 彩度换 C（L、H 取自下层）→ 明度换 L**，
三者互不干扰。四条 LCh 混合模式的语义都做过黑盒验证（底图 L49.6 / C29.6 / H56.9）：

| 模式 | 实际行为 |
|---|---|
| LCh 色相 | LCh(**L_base**, **C_base**, **H_src**) |
| LCh 彩度 | LCh(**L_base**, **C_src**, **H_base**) |
| LCh 明度 | LCh(**L_src**, **C_base**, **H_base**) |
| LCh 颜色 | LCh(**L_base**, **C_src**, **H_src**) |

每层的滤镜栈（图层面板里从上往下读，实际执行顺序与之相反）：

| 序号 | 滤镜 | 作用 |
|---|---|---|
| `1 · extract` | `gegl:component-extract` | 抽出该分量，输出灰度（`lab-l` / `lch-c` / `lch-h`） |
| `2 · curve` | `gimp:curves`（通道 = 值） | **给用户调的那条**，默认恒等 |
| `3 · encode` | `lb:gray-to-component` | 把灰度重新编码成「携带该分量」的彩色，混合模式才读得出来 |

编码那一步是一个 GEGL 算子（本仓库的 `ops/gray-to-component`），不是三条曲线：
旧版「scale + 三条 `gimp:curves`」加起来五六个滤镜，现在每层固定三条。没装这个
算子时插件自动退回曲线编码，结果一样，只是回到 256 点查表的精度。

## 三个分量的真实量程（实测标定）

`gegl:component-extract` 报出来的数不是「原始单位」，标定结果（GIMP 3.2.8 / babl D50）：

| 分量 | 字符串 | 量程 |
|---|---|---|
| 明度 | `lab-l` | `L*/100`，0…1 |
| 彩度 | `lch-c` | `C*/200`，sRGB 内只到 0…**0.656** |
| 色相 | `lch-h` | `h/360`，0…1 |

彩度层的曲线直接作用在这个 `C*/200` 上：曲线的 0.656 处就是 sRGB 最大彩度
（纯蓝 C*=131.21，36³ 网格搜出来的最大值），右端 1/3 用不到但留着不吃亏。
编码时算子按 `chroma-scale = 200` 把灰度乘回真实 C*。

## 编码路径怎么选

灰度像素的色相、彩度是**无定义**的：把 H 灰度层直接设成「LCh 色相」模式不会有
任何效果。必须先把它映射成真实颜色。路径怎么选很关键：

| 层 | 路径 |
|---|---|
| Lightness | 灰阶：`Lab(100g, 0, 0)`，直接就是 L* |
| Chroma | `Lab(70, C·cos30°, C·sin30°)`，`C = 200g`（模式只读 C，方向无关） |
| Hue | **等 L、等 C 的色相圆**：`LCh(70, 39.8, 360g)` |

色相那条吃过一次亏：最早用「全饱和色轮 `hsl(h,1,.5)`」，恒等往返差 4.7 码。
原因是**色相混合模式对色相误差极其敏感**——ΔH=0.5° 在 C*=90 时就折合 9.6 个码值；
而全饱和路径在 a\*b\* 平面上曲率大，256 点线性插值本身就有 0.22° 误差。换成等 L
等 C 的圆后角度在极坐标下严格线性；现在由算子直接写 `a=C·cos h, b=C·sin h`，
连查表都没有了。

`L*=70` 也不是随手取的：sRGB 里能整圈容纳最大彩度的明度就是 70（41.9），取 39.8
留出余量，保证整圈都在色域内。

## 实测精度

`tools/check_lch_split.py`（跑在 GIMP 3.2.8 的 Python 里，35 项）：

| 场景 | 结果 |
|---|---|
| 32 位浮点图，恒等曲线往返 | ≤ **0.02 码** |
| 8 位图，恒等曲线往返 | ≤ **0.5 码** |
| 8 位图，改曲线 vs 直接改 LCh 的数学期望 | ≤ **2.7 码** |
| 真实 512×512 图，恒等往返（逐像素比对） | 旧版最大 0.03 码，算子版更低 |
| 透明区域 alpha | 逐位保留（组蒙版，见下） |
| **原图层隐藏后**，三层自己还原 | RGB **0.00006 码**，alpha 逐位对 |

剩下的误差几乎全是 8 位量化，不是公式。要更准就用 16 位 / 浮点图。

## 用起来的几条经验

- **改 `curve` 那条就行**，`encode` 别动（动了读数就错了）。
- **色相曲线必须连续**：两端相等、中间不跳变。要**整体旋转色相**请用
  `lb:hue-saturation`；这条曲线适合「压缩/拉伸某段色相」，比如 `t + 0.04·sin(2πt)`。
  注意 `(t+Δ) mod 1` 这类写法在 `t=1.0` 处会因为浮点误差（`sin(2π) = -2.4e-16`）
  算出 `0.0`，曲线最后一段从 0.99 直接砸到 0，画面上就是一条伪彩带。**别用取模**。
- **8 位图像必须收进组里**：三层直接合成到 8 位投影缓冲时会被逐层量化，色相偏到
  11 码级；组内合成走浮点缓冲，只有 0.5 码。所以 8 位图上 `group=False` 会被
  自动改成分组并给出提示。
- 近中性区域的色相是噪声（C≈0 时无定义），但结果不受影响：彩度层把 C 归零后，
  色相层读到的 C 也是 0。
- 结果可能超出 sRGB 色域（浮点图里保留负值/超 1），8 位落盘就裁切——这是分量
  混合模式本身的性质。
- 图层组不能直接拆（没有自己的像素），先右键 → 合并组。
- 图层自带的非破坏滤镜不会被复制（`new_from_drawable` 只取像素）。

## 安装

仓库根的 `./install-plugin.sh` 会把 `plugin/` 下每个子目录拷进 GIMP 的
`plug-ins/`；也可以手动把本目录整个复制过去：

```
Windows: %APPDATA%\GIMP\3.x\plug-ins\lch-split-curves\
Linux:   ~/.config/GIMP/3.x/plug-ins/lch-split-curves/
```

重启 GIMP 后出现在 `颜色 → SuperMrWang`。

批处理调用（PDB）：

```scheme
(lb-plugin-lch-split-curves RUN-NONINTERACTIVE image drawable TRUE)
```

第三个参数 `TRUE` = 收进「LCh split」穿透组，`FALSE` 就直接叠在原图层上方
（8 位图会被自动改成分组）。

## 与 HSV 版、与 `lb:` 算子的关系

- **HSV 版 vs LCh 版**：HSV 的 V/S 是「相对量」，调 S 会随 V 变化而改变观感；LCh 的
  L/C 是感知均匀的绝对量，做亮度/彩度分级更稳。两者都保留——论完整度 LCh 更高，
  论习惯 HSV 更熟。
- **插件 vs `lb:lch-levels` 等算子**：这套补的是「交互 + 分层」——曲线是 GIMP 原生
  控件（可加控制点、存 XCF、随时改），三个分量各自成层（可单独开关、调不透明度、
  加蒙版、套别的滤镜）。批处理、预设、极致精度还是用 `lb:` 算子。

## 已知限制

- LCh 的 `C` 在 sRGB 内上限是 131.21，更大的彩度无法表达（也不可显示）。
- 8 位图受色相量化（1.41°/步）限制，逐位还原做不到，见上表。
- 彩度曲线的横轴是 `C*/200`：0.656 处就到 sRGB 最大彩度，右边 1/3 用不到。
- 没装 `lb:gray-to-component` 时自动退回旧版曲线编码（scale + 三条曲线），
  精度掉回 0.5–4 码，但结果结构不变。
- 透明区域靠**组蒙版**保住（三层本身必须不透明，否则混合模式会按 alpha 做 lerp，
  半透明区实测偏 28 码）。因此带 alpha 的图层即使选「不分组」也会自动收进组里。
