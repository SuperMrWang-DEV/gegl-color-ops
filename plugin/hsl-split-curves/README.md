# HSL Split (Curves) · 在 HSL 空间里调曲线

GIMP 3 给 HSV 和 LCh 都配了分量混合模式，唯独 **HSL 没有**。本插件用两个小算子
把 HSL 接到 HSV 上，做到与「直接改 HSL」完全等价：恒等曲线逐像素还原原图，调
S 曲线就只动 HSL 的饱和度，明度和色相一动不动。

```
颜色 → SuperMrWang → Shortcut → HSL Split (Curves)
图层右键 → SuperMrWang → Shortcut → HSL Split (Curves)
```

## 生成的结构

```
HSL split                       组，混合模式 = 穿透（带 alpha 时组上还有一张蒙版）
  ├─ 2 · Hue        模式 HSV 色相    extract → 曲线 → encode
  ├─ 1 · S / L      模式 正常        dual → S 曲线 → L 曲线 → compose
  └─ 原图层（不动，可以隐藏）
```

色相从一开始就在 S/L 层的 B 通道里带着，所以**把 Hue 层关掉、只留 S/L 层**，看到
的就是「原色相 + 调过的 S/L」——一个很好用的中间状态。

## 为什么只有两层

HSL 的 S 与 L 是耦合的：

```
C = (1 − |2L − 1|)·S        V = L + C/2        S_hsv = C/V
```

要精确得到 HSL 的 (S, L)，编码器必须**同时**读到 S 和 L 两个值。而每层的曲线只
看得到自己那一个分量，两条互相独立的 1D 曲线表达不了这个二元映射。

所以 S 与 L 被放进同一张数据图（R = S、G = L），两条曲线各挂一个通道，再由
`lb:hsl-compose` 联合还原。这一层算出来的本来就是完整颜色，第三层就没有必要了：
上面的 Hue 层用「HSV 色相」模式只替换色相，S 与 L 原样保留。

硬凑三层会付什么代价（纯数学，S/L 网格全扫）：

| 做法 | 偏差 |
|---|---|
| 把 HSL 的 L 直接当 HSV 的 V 用 | S=0.25 → **-25 码**，S=1 → **-64 码**（差的就是 C/2） |
| 再加一条按「典型 S」校准的曲线 | 实际 S 一变就偏到 **77 码** |
| S、L 一起调，两条 1D 曲线 | 最坏 **102 码** |

这不是精度问题，是可分离性的问题。

## 每层的滤镜栈

| 层 | 滤镜 | 做什么 |
|---|---|---|
| S/L | `1 · decompose` | `lb:hsl-dual`：原图 → R = S、G = L、B = H/360 |
| S/L | `2 · S curve` | `gimp:curves`，**通道 = 红**：调 HSL 饱和度 |
| S/L | `3 · L curve` | `gimp:curves`，**通道 = 绿**：调 HSL 明度 |
| S/L | `4 · compose` | `lb:hsl-compose`：(R,G,B) → 真实 HSL 色 |
| Hue | `1 · hue` | `gegl:component-extract`，component = `hue` |
| Hue | `2 · H curve` | `gimp:curves`，通道 = 值：调色相 |
| Hue | `3 · encode` | `lb:gray-to-component`，mode = `hue`：灰 → 全饱和色环 |

**改曲线时注意通道**：S 曲线在红通道、L 曲线在绿通道。选「值」会把三条数据一起
改掉。曲线的 `trc` 已经钉成 `NON_LINEAR`（在编码值上生效，与分量语义一致）。

## 实测

`tools/check_hsl_split.py`（跑在 GIMP 3.2.8 的 Python 里，28 项）：

| 场景 | 结果 |
|---|---|
| 32 位浮点图，恒等曲线往返 | **0.00001 码** |
| 8 位图，恒等曲线往返 | **0.002 码**（0.5 码以内） |
| 改 S 曲线 → 结果 HSL 饱和度 = f(原 S) | 误差 **0.0001 码**，明度/色相不动 |
| 改 L 曲线 → 结果 HSL 明度 = f(原 L) | 误差 **0.0001 码**，饱和度不动 |
| **原图层隐藏后**两层自己还原 | RGB **0.00001 码**，alpha 零误差 |

适配算子内部用 babl 的 `HSLA float` 做转换，与 GIMP 自己的 HSL（`component-extract`
的 `hsl-s` / `hsl-l`）**同一口径**，所以往返没有查表误差。

## 透明区域

分量层必须不透明——半透明层的混合会按 alpha 做 lerp（实测偏 28 码）。透明度交给
**整组的 alpha 蒙版**（取原图层 alpha）：颜色由两层算，透明度由原图给。因为蒙版
只能挂组上，带 alpha 的图层即使选了「不分组」也会自动收进组里。

## 依赖

精确适配依赖本仓库的两个 GEGL 算子：

- `lb:hsl-dual` — 把 S/L/H 打包进一张数据图
- `lb:hsl-compose` — 把数据图还原成颜色

缺了它们**没有等价回退**（二维映射没法用一维曲线凑），插件会直接报错并说明要装
什么，不会静默给一个偏几十码的结果。装法：仓库根目录 `./install.sh`。

顺带：色相编码那步用 `lb:gray-to-component`，缺它时退回三条曲线，色相精度从
精确降到 1 码级。

## 已知限制

- 色相曲线必须是连续的（两端相等、中间不跳变）。整体旋转色相请用
  `lb:hue-saturation`——曲线的 256 项查表会在跳变处插值出一条伪彩带。
- 8 位图上数据图只有 256 级，S/L 各占 1 级 → 往返仍有 0.5 码以内的量化误差。
  要精确就用 16 位或 32 位浮点图。
- 图层自带的非破坏滤镜不会被复制（`new_from_drawable` 只取像素）。
- 只支持 RGB* 图像。

## 和另外两个插件的区别

| | 分量混合模式 | 每层一条曲线 | 精确 |
|---|---|---|---|
| HSV Split | HSV 色相 / 饱和度 / 明度 | 3 层 | 是（HSV 三分量本来就独立） |
| LCh Split | LCh 色相 / 彩度 / 明度 | 3 层 | 是（LCh 三分量独立） |
| **HSL Split** | 借 HSV 色相 + 正常模式 | **2 层**（S/L 合并） | 是（联合算子消除耦合） |

LCh 版看 `plugin/lch-split-curves/`，HSV 版看 `plugin/hsv-split-curves/`。
